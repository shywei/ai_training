CHAPTER 02

Function Calling 协议 — OpenAI API 格式

请求：tools 参数定义可用工具（替代已废弃的 functions）
{
  "model": "Qwen2.5-7B",
  "messages": [...],
  "parallel_tool_calls": true,
  "tools": [{
    "type": "function",
    "function": {
      "name": "queryProductInfo",
      "description": "查询商品价格和库存",
      "strict": true,
      "parameters": {
        "type": "object",
        "properties": {"productId": {"type": "string", "description": "商品ID"}},
        "required": ["productId"], "additionalProperties": false
      }
    }
  }]
}
• tools + tool_calls 是现行标准，支持 parallel_tool_calls 并发调用与 strict: true 约束解码保证参数合规
• 权力边界清晰：LLM 仅依据 Schema 生成调用意图，绝不直接执行物理代码；由 Host 运行时校验后代为执行
响应：tool_calls 决策指令（无代码执行权）
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [{
        "id": "call_abc123",
        "type": "function",
        "function": {
          "name": "queryProductInfo",
          "arguments": "{\"productId\":\"NB001\"}"
        }
      }]
    }
  }]
}
🚨 权力边界与调试识伪
content: null 携带 tool_calls 是正常的协议决策流而非报错。大模型绝无物理执行权，实际执行权、入参白名单校验、沙箱运行与异常捕获完全归属于 Agent Runtime。执行后需由 Runtime 回传 role: tool 回执才能继续生成。
结构化输出三方案 — 互补不是竞争，按场景分层选
① Native Structured Output
response_format + json_schema 约束解码，输出必合 schema。适合：抽取、分类、报表等纯数据产物。
② Function Calling
tool schema 约束调用决策，物理动作交给 Agent Runtime。适合：触发 Tool / MCP，一个管决策一个管执行。
③ JSON mode + Parser
保证合法 JSON，不合 schema 靠 Parser 校验 + 重试修复兜底。适合：旧版模型或自由动态结构。
选型铁律：结构化产出选①｜触发外部动作选②（开启 strict: true 零幻觉）｜弱模型兜底选③。
