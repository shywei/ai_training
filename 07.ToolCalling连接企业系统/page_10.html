CHAPTER 03

MCP 核心概念 — 角色模型与 Server/Client 能力矩阵分类

🔧 Tools（Server Feature）
暴露给模型调用的可执行函数
查询、计算、企业系统写入
LLM 决策，Runtime 调度执行
MCP 协议定义：
// Server 暴露 Tool
Tool {
  name: "queryPrice"
  description: "查价格"
  inputSchema: {
    type: "object",
    properties: {id:{type:"string"}}
  }
}
// Client 调用
callTool("queryPrice", {id:"NB001"})
Demo 已覆盖：queryProductInfo
📄 Resources（Server Feature）
提供上下文与只读数据源
文件、配置、用户画像
Client 主动读取与订阅
MCP 协议定义：
// Server 暴露 Resource
ResourceTemplate {
  uriTemplate: "user://{userId}"
  name: "用户画像"
  mimeType: "application/json"
}
// Client 读取
readResource("user://U001")
// → 返回结构化画像 JSON
Demo 已覆盖：user://{userId}
💬 Prompts（Server Feature）
预定义的交互与提示词模板
服务端标准化封装与复用
声明式能力暴露
MCP 协议定义：
// Server 暴露 Prompt
Prompt {
  name: "analyze-review"
  arguments: [{
    name: "review", required: true
  }]
}
// Client 获取 Prompt
getPrompt("analyze-review", {...})
生产扩展：标准化 Prompt 模板
🔄 Client Features（客户端特性）
Server 请求客户端协助能力：
• Elicitation：请求用户补充信息
• Sampling：请求代调模型推理
• Roots：暴露工作区根目录信息
⚠️ 2026-07-28 规范弃用提示：
Roots、Sampling 与 Logging 已正式进入弃用阶段。
模型推理与工作区管理应在 Host/Agent 层统一自治，不再通过协议反向侵入 Server。
弃用：Roots / Sampling / Logging
💡 MCP 核心能力矩阵与 2026-07-28 规范演进： Client、Server、Host 职责清晰划分；三大 Server Features（Tools / Resources / Prompts）是长期稳定的能力基石；Client Features 中 Elicitation 负责向用户补充信息，而 Roots、Sampling 与 Logging 已被 2026-07-28 规范列入弃用；Tasks 则从核心解耦为独立 Extension。
