MCP 架构与协议演进 — 协议时间线与 Demo/2026 双轨制对照

协议演进四阶段时间线
① 2024-11-05 · 初始协议
本地 stdio 与远程 HTTP+SSE 双端点（Demo 所采用教学基线）
② 2025-03-26 · 引入 Streamable HTTP
引入单端点 Streamable HTTP，旧 HTTP+SSE 传输步入弃用路线
③ 2025-11-25 · 会话式 Streamable HTTP
Streamable HTTP 采用 Mcp-Session-Id 与 initialize 显式两阶段握手
④ 2026-07-28 · 无状态核心演进（最新）
• 取消 initialize 握手与协议级 Session ID，请求自包含认证
• server/discover RPC 方法动态协商元数据与能力清单
• Mcp-Method / Mcp-Name 请求头路由与 ttlMs/cacheScope 缓存
• Tasks 解耦为独立扩展；OAuth 强化与 CIMD 客户端元数据文档
• MRTR 交互：服务端返回 input_required，客户端通过 inputResponses 提供答案后重试原请求
双轨制对比：Demo 实践基线 vs 2026 无状态演进
对比维度 Demo 实践基线（2024-11 HTTP+SSE） MCP 2026 最新无状态前瞻标准
传输模型 HTTP+SSE 双端点（/sse 长连接 + /mcp/message POST） 无状态 HTTP POST（Mcp-Method/Mcp-Name 头路由，按需切流）
握手与会话 强制 initialize 两阶段握手，依赖 Mcp-Session-Id 取消初始化握手与协议级 Session ID，ttlMs/cacheScope 列表缓存
服务与能力发现 连接建立后分立调用 tools/list、resources/list 现代化 server/discover RPC 方法，一次性协商全量能力与扩展
长任务与多轮补充 Tasks 混在核心协议中，参数缺失需 Agent 自行循环处理 Tasks 移入独立 Extension；MRTR 原生支持 input_required/inputResponses
生产治理架构 单机开发友好，但粘性连接阻碍 API 网关与负载均衡 完美适配 K8s 微服务网关、无状态扩容与 Serverless 冷启动
⚠️ Java 生态落地实现边界： ① 协议层：2026-07-28 发布无状态核心； ② Java SDK 层：SDK 2.2.0 中 Modern Server 仍为 Preview，暂无 Modern Client，Tasks 待实现； ③ Spring AI 层：2.0.2 支持 Stateless Streamable 传输，但不等同于完整实现 2026-07 规范全部核心； ④ Demo 层：采用稳定 2024-11 HTTP+SSE 教学基线。
理论视野完全同步 MCP 2026 无状态演进，确保架构设计不落后于企业微服务生产前沿！
