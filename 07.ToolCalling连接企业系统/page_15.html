Function Calling 完整链路 + MCP Client 代码

McpProductClient.java — Tool 发现与动态桥接
@PostConstruct
public void init() {
  // 1. 连接 MCP Server（Demo 基线：有状态长连接）
  mcpClient = McpClient.sync(transport)
    .requestTimeout(Duration.ofSeconds(10))
    .build();
  mcpClient.initialize(); // [基线握手，2026 无状态模式已免除]

  // 2. 发现 Tool（2026 演进为 server/discover 动态端点）
  ListToolsResult tools = mcpClient.listTools();

  // 3. 包装为 FunctionCallback（向 LLM 注册 OpenAI tools）
  for (Tool tool : tools.tools()) {
    String toolSchema = mapper.writeValueAsString(tool.inputSchema());
    FunctionCallback cb = new McpToolCallback(
      "mcp_" + tool.name(), "[MCP] " + tool.description(),
      toolSchema, mcpClient, tool.name());
    callbacks.add(cb);
  }
}
Demo 基线与 2026 对照：代码基于 Spring AI 1.0.0-M4 跑通有状态握手；2026 无状态规范中无需 initialize()，直接按需 POST 并在 server/discover 获取元数据。
执行时序与权力边界
① 用户："ThinkPad X1 多少钱"
② LlmRouter 意图路由 → 判定为 TOOL 模式
③ 注册 Tool Schema → LLM API 请求体携带标准 tools 数组
④ LLM 决策输出 tool_calls: mcp_queryProductInfo("NB001")
⑤ Runtime 校验与执行：McpToolCallback → MCP Client → MySQL
⑥ 结果组装（role=tool）回传 LLM → 生成最终自然语言回复
LLM 不感知 MCP：大模型仅看见 OpenAI 兼容的 tools 契约；所有 MCP 握手、超时控制、入参白名单校验均由 Agent Runtime 独占闭环。
