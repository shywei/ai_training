CHAPTER 08

课后练习 — 每题对应一个核心知识点，动手才有结论

练习 1 · 手写 function definitionFunction Calling 协议
不看课件，给 queryStock 手写一份 function definition JSON（name / description / parameters，含 productId 的 JSON Schema）。 写完对照 mcp-product-server 的 McpServerConfig.java 里 productIdSchema 与 Tool 注册，逐字段说清对应关系。
练习 2 · 加一个 Tool，验证自动发现MCP Tool 发现
在 product-server 加 queryCategory（按商品 ID 查类别，改 McpServerConfig + ProductRepository）， 重启后在 agent-runtime 控制台确认它被自动发现并包装——验证"加 Tool 不用改 Client"，并说明 Schema 写错时 LLM 会怎么传错参数。
练习 3 · 路由扩一类LLM 路由
给 LlmRouter 的三分类加一类（如 LOGISTICS 查物流），改分类 Prompt 与 Route 枚举， 用 POST /api/agent/recommend 验证，看 logs/llm-route.log；回答：为什么 temperature 必须是 0？
练习 4 · 给写操作设计幂等键幂等
对照 mcp-knowledge-server 的 save_memory（MemoryService.save() 裸 INSERT）或假设在 mcp-product-server 新增一个 place_order 下单 Tool，设计完整幂等方案：幂等键的构成、去重表 DDL（或唯一索引）、重复请求返回什么，并写出"超时后重试"的完整时序。
练习 5 · 给 queryProductInfo 上限流限流
用 Guava RateLimiter（或 Redis+Lua）给 queryProductInfo 配 10 次/分钟，写一段循环调用的测试， 观察第 11 次返回什么。三选一（排队 / 降级 / 429+Retry-After）里你选哪个，写清理由与取舍。
练习 6 · 超时重连实验与补偿设计超时 · 补偿
把 McpProductClient 的 requestTimeout 改成 1 秒并停掉 product-server，观察调用报错与 ensureConnected() 10 秒冷却重连日志； 再为"下单 → 扣库存 → 发通知"三步设计补偿链：哪些有反向操作、哪些转人工、对账比什么。
练习 7 · 从现有日志拼出一条审计记录审计
执行一次商品价格查询后，从控制台 [MCP] 调用 Tool 日志与 logs/llm-chat.log 拼出一条审计记录 （谁 / 何时 / 调了什么 / 参数 / 结果 / 耗时），对照审计表字段清单，指出 v1.4 现有日志还缺什么、为什么不能用文本日志代替审计表。
练习 8 · 综合大作业（课后一周内交）五件套综合
选一个你企业里真实的 API（订单、审批、工单都行），按企业治理五件套写一份治理设计： 限流配额（粒度+算法+超限策略）、幂等键（构成+判重点）、超时档位、补偿（正向/补偿 Tool 对+对账）、审计字段。 要求每项写"不做的后果"——这门课的重点不是怎么调 Tool，是怎么管 Tool。
