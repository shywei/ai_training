LLM 路由 — 三种方案对比

方案一：关键词过滤
匹配"多少钱"→ TOOL
匹配"推荐"→ KNOWLEDGE
默认 → CHAT
✗ 局限
"帮我看看那个笔记本"不含"推荐"
第六课用过，已淘汰
方案二：Embedding 相似度
预定义意图描述
用户消息 Embedding 后
和意图描述做相似度匹配
△ 中等
需要维护意图描述，新增意图要更新
仅 PPT 讲解
方案三：LLM 分类 ✓
用快模型做两件事：
① 意图分类：KNOWLEDGE / TOOL / CHAT
② 模型选择：KNOWLEDGE/TOOL → 推理模型，CHAT → 对话模型
✓ 优势
一次 LLM 调用同时返回路由+模型，不需维护规则
Demo 采用
选型建议与路由三价值：意图少（<10）用 LLM 分类，规则明确用关键词，实际常混合使用。 路由器核心解决三件事：① 安全隔离（按角色屏蔽高危 Tool） ② 成本控制（按需挂载省 50%+ token） ③ context 按需构建（Demo 中仅 KNOWLEDGE 注入 RAG）
🚀 2026 大规模工具治理 — Tool RAG（Dynamic Tool Discovery 动态工具检索）： 当企业 MCP Gateway 汇聚 50~200+ 个 Tool 时，全量注册 Tool Schema 每轮白白消耗 20,000+ tokens，且工具过多会导致大模型注意力分散、选错工具准确率显著下降。 生产解法：先走 Domain Routing（领域路由） 或 Tool Embedding Search（Tool RAG，拿用户 Query 向量检索 Tool 描述库），每轮动态挂载最相关的 Top-K（如 3~5 个） 工具给 LLM。
