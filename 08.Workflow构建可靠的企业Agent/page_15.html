CHAPTER 06

Human-in-the-loop — AI 的安全边界

为什么需要人工确认
LLM 可能误判意图——用户说"帮我看看"，LLM 理解成"下单"。
LLM 可能过度自信——用户还没确认，就直接调了下单接口。
LLM 可能被注入——恶意用户通过提示词诱导 Agent 执行危险操作。

AI 不应该对所有操作都有执行权。
哪些操作需要确认
下单 退款 删除 修改价格 支付
Demo 已覆盖：ConfirmationService.java 完整确认/取消流程。
仅 PPT 讲解：确认超时、CSRF 防护、多级审批。
工作流程
① Agent 准备调用高风险 Tool（如 place_order）
② ConfirmationService 拦截 → 工作流暂停
③ 返回确认请求给前端
④a 用户确认 → 工作流恢复 → 执行工具
④b 用户取消 → 状态变为 CANCELLED
API 端点
POST /api/agent/workflow/confirm
  ?traceId=trace-xxx
  &confirmed=true  // 或 false
  &sessionId=default
