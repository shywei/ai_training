CHAPTER 08 · 生产差距

Demo vs 生产 — 可靠运行时关键机制对照

1. Durable Execution 与故障重建（Rehydration）
问题：Demo 状态散在内存 Map，容器重启或 Pod 漂移后状态全丢。
生产落地：每个节点执行完毕实时落盘 workflow_checkpoint 表（PostgreSQL/Redis）；故障重启后读取快照执行 Process Rehydration 重水化重建，从中断点继续推进，绝不从头重新规划，绝不重复调用副作用工具。
2. 概率规划与确定性 FSM 拓扑校验
问题：Demo 仅靠 Prompt 约束步骤 JSON，缺乏程序级依赖校验。
生产落地：确立“概率规划 + 确定性 FSM 约束”架构，对模型输出的 DAG 执行循环依赖检测（无环性）与前置依赖条件校验，通过后方可注入状态机流转。
3. 错误恢复四层协同矩阵（Error Recovery Synergy）
问题：仅有单点重试与熔断，遇到商品缺货等语义报错无法动态自愈。
生产落地：建立 ① 重试（瞬态）+ ② 熔断降级（雪崩）+ ③ 错误重规划（Replanning 动态换路）+ ④ 人工介入接管（Escalation 终极安全） 四层协同机制。
4. 规划触发 — 混合路由机制
问题：Demo 纯依赖静态关键词表，遗漏长尾复杂任务表达，误触发单步任务。
生产落地：确定性规则快路径（85% 典型场景零成本命中）+ 轻量快模型语义分类兜底。
5. 审批超时与分布式并发锁
问题：待确认操作无 TTL，用户关窗导致工作流永久悬挂；无并发控制导致双下单。
生产落地：Redis SETEX 5 分钟自动取消并记录 Trace；原子单飞消费防重确认，数据库乐观锁（version）杜绝超卖。
6. 分布式链路追踪（OpenTelemetry Tracing）
问题：TraceService 仅保存在单机内存，多实例集群链路分散丢失。
生产落地：接入 OpenTelemetry 标准，Root Span 绑定 W3C traceparent，步骤转 Span/Event 上报 Jaeger。
7. 真正多事件流式响应（Agentic SSE）
问题：Demo 同步跑完所有步骤才回传，前端面对长达 5~10 秒空白等待。
生产落地：标准化 Agentic SSE 事件流（step_start、tool_call、confirm_required、answer_delta），实时推流。
架构演进结论
第八课手搓完成了状态机、ReAct 循环与容错的核心骨架；生产落地通过 Durable Execution 与 四层协同矩阵 筑牢可靠性底线，为第九课迁移至专业框架奠定坚实基石。
