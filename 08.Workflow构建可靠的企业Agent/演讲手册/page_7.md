## Slide Objective
对比状态机和纯 ReAct，让学员理解为什么需要 Runtime 来"管" LLM。

## Suggested Presentation
左边是第七课的纯 ReAct 模式。LLM 自主决定 THINK→ACT→OBSERVE，没有外部约束。没有停止条件，可能无限循环。工具失败直接报错。高风险操作无拦截。无执行记录。

右边是第八课的状态机 + Agent Runtime。Runtime 控制循环，最大 10 轮强制停止。每个状态有明确的转换条件。工具失败 → 重试 3 次 → 熔断 → 降级。高风险操作暂停，等待用户确认。每步记录 Trace。

注意底部的类比：LLM 是"大脑"，Runtime 是"操作系统"。大脑负责思考和决策，操作系统负责资源管理、任务调度、异常处理。你不会让员工自己决定"要不要走审批流程"——那是流程系统的事。

这个类比很重要。很多做 AI 的同学把 LLM 当成"万能的"——什么都让 LLM 决定。但在企业环境里，LLM 只是"执行单元"，决策权在 Workflow 层。就像公司里，员工做事，但有流程和审批。

## Key Emphasis
1. **学术与工程结合的核心认知：概率规划 vs 确定性 FSM 约束**：
   大模型基于自回归生成完成任务规划，在学术上属于典型的“认知/概率型规划（Probabilistic Planning）”，其每一步决策都伴随着采样概率与幻觉风险，天然存在因果颠倒、逻辑循环与前置条件遗漏。
   企业级架构的精髓绝非彻底摒弃大模型的推理能力，而是建立**“概率规划 + 确定性有限状态机（FSM）约束”**体系：
   - 允许大模型在受控范围内发挥概率推理与任务分解优势（想什么）；
   - 在执行层，必须由**确定性有限状态机（FSM）强制执行拓扑依赖校验、前置执行条件检查、不可逆终态保护与强制中断审批**（怎么管）。
   - 将不可控的大模型输出，收敛到企业 100% 确定、可测试、可审计的受控状态流中。
2. "LLM 是大脑（认知引擎），Runtime 是操作系统（确定性调度内核）"——这个类比要讲透。凡是涉及流程准入、资金安全、重试策略与状态终态的规则，必须由代码硬编码控制，绝不能写在 Prompt 里寄希望于模型的自觉性。

## Optional Extension
**学员问：Runtime 管得太多，会不会影响 LLM 的灵活性？**
答：Runtime 管的是"边界"，不是"内容"。LLM 在边界内自由发挥——想调什么工具、怎么推理、怎么回答。但边界是确定的：最多 10 轮、高风险要确认、失败要重试。就像公司里的员工手册——规定了流程，但不限制你的创造力。

**学员问：LangGraph 是不是就是这个？**
答：LangGraph 把这套模式做成了框架——状态图、节点、边、条件。**Demo 做法**：自己写状态机 + Runtime 边界（MAX_ITERATIONS、确认、重试）。**生产做法**：AgentScope Java 2.0 或 LangGraph 接管循环编排的胶水，但"管什么"（边界清单）还得你定义——第八课手搓、第九课用 AgentScope Java 2.0 重构、第十课对比 LangGraph，三步下来你就理解了 Workflow 的本质。

## Take Away
分工判据：凡是"必须每次都一样"的行为（停止条件、确认、重试、记录）写进 Runtime 代码，绝不写进 Prompt。

## Why This Slide Matters
跳过这页，学员会只画状态机不写 Runtime——状态成了摆设，没有循环边界和异常处理，画多少图也约束不住 LLM。
