## Slide Objective
【P0 级重点重构】统一确立**“三级自动容错 + 错误重规划 + 人工接管”协同防御体系**：深入讲解三级自动容错（重试 Retry、熔断 Circuit Breaker、降级 Fallback）、任务级恢复策略（错误重规划 Error Replanning）与终极安全防线（人工接管 Human-in-the-Loop, HITL）的分工逻辑与协同决策流。

## Suggested Presentation
各位学员，很多初学者在设计 Agent 时，往往只知道“报错就重试”，或者“重试失败就抛异常挂掉”。
在复杂的企业分布式微服务环境下，单点异常形态各异：有的是网络偶发瞬态抖动，有的是下游服务雪崩，有的是商品缺货等业务语义冲突，有的则是涉及高危资金扣款。**单一策略根本无法解决复杂生产问题！**

这一页我们统一确立规范的**“三级自动容错 + 错误重规划 + 人工接管”协同防御体系**：

### 1. 协同防御机制逐级布防（左侧）
- **自动容错 ①：重试机制（Retry）— 处理瞬态网络故障**
  - **适用场景**：网络偶发抖动、连接闪断、MCP Server 瞬时只读超时。这类故障通常持续数百毫秒到数秒，过一会儿就会自动恢复。
  - **核心参数**：最多重试 3 次，采用指数退避算法（1s → 2s → 4s），并必须引入随机抖动（Full Jitter），防止成千上万个并发 Agent 在同一秒重试引发“惊群效应”。
  - **红线底线**：重试只适用于**只读查询**或**已绑定幂等键的写操作**！绝不允许对非幂等接口进行裸重试，否则就是重复扣款事故。
- **自动容错 ②：熔断机制（Circuit Breaker）— 防止故障持续扩散**
  - **适用场景**：下游微服务发生真机宕机或网络光缆中断。此时如果数百个 Agent 继续重试，会瞬间将下游打死，引发企业服务级联雪崩。
  - **核心机制**：当同一 Tool 连续失败 5 次时，立即触发熔断器（Circuit Breaker 打开），在 60 秒内强制切断对该工具的所有物理调用；到期后进入半开状态（Half-Open）试探性放行 1 笔请求。
- **自动容错 ③：服务降级兜底（Fallback）— 提供替代结果或静态兜底**
  - **适用场景**：熔断开启或服务不可用时，不能让前端直接白屏报错。
  - **核心机制**：系统自动跳过宕机服务，使用备用轻量模型生成兜底说明或调用备用静态规则模板（如“商品库存服务暂时维护，已为您保留查询意向”），确保主干流程活着。
- **额外任务恢复策略：错误重规划（Error Replanning）— 重新规划失败任务路径**
  - **适用场景**：工具返回的是明确的业务不可用（例如“目标型号笔记本已售罄下架”或“收货地址超出配送范围”）。此时网络没有任何问题，即使重试 100 次也必定失败。
  - **核心机制**：Agent Runtime 捕获该结构化业务错误，将其作为观测回执（Observation）重新组装进对话上下文，**驱动 TaskPlanner 重新生成替代执行路径**（例如自动改为检索同价位备选机型），实现系统的动态自愈。
- **终极安全防线：人工接管（Human-in-the-Loop, HITL）— 处理业务决策与人工授权**
  - **适用场景**：三级自动容错全部耗尽、重规划陷入多轮无法收敛的死循环，或者操作命中高危资金与核心系统数据变更（如确认下单）。
  - **核心机制**：状态机进入受控挂起状态（进入 `CONFIRMING` 终态），将当前的 Checkpoint 快照持久化，并通过 Webhook 抛出工单，通知人工专员在管理后台审核批准。

### 2. 五层协同决策流（右侧）
讲师要引导学员理清这五层的联动顺序：
异常发生时，系统首先判定是否为网络瞬态抖动（走 ① Retry）；若持续故障超阈值，则触发 ② Circuit Breaker 熔断防雪崩；若需要优雅答复，则走 ③ Fallback 服务降级；若属于业务语义冲突且存在替代方案，则触发 🔄 Error Replanning 驱使大模型重排步骤；若全部手段耗尽或涉及高危动作，则果断上升为 🛡️ Human Escalation 转人工接管。

## Key Emphasis
1. **统一容错定义层级**：自动容错三级（Retry 瞬态故障 $\to$ Circuit Breaker 防扩散 $\to$ Fallback 降级兜底），任务恢复策略（Error Replanning 动态自愈），终极防线（HITL 人工接管）。
2. **Demo 与生产落地映射**：
   - Demo 中的 `ErrorRecovery.java` 实现了 ① Retry、② Circuit Breaker 与 ③ Fallback，配合 `ConfirmationService` 实现人工介入雏形；
   - 生产环境中必须通过 Runtime 将上下文回填至 `TaskPlanner` 补齐 🔄 错误重规划，并对接工单系统实现 🛡️ 人工审批闭环。

## Optional Extension
**学员问：错误重规划（Replanning）会不会无限循环？**
答：必须在 Runtime 设定最大重规划次数限制（通常限制为 1~2 次）。如果大模型重排了 2 次依然无法绕过业务障碍，系统判定该任务不可自愈，立即终止重规划，直接触发人工介入接管或向用户诚实报错。

## Take Away
**协同防御口诀**：**瞬态靠重试、雪崩靠熔断、降级靠兜底、业务靠重排、终局靠人工**。五层逐级布防，才是企业级 Agent 可靠运行的工程真谛。
