## Slide Objective
建立"为什么不能相信 LLM"的认知。不是说 LLM 不好，而是说 LLM 的行为特性不适合直接用于企业生产环境。

## Suggested Presentation
左边四个问题是 ReAct 模式的致命缺陷。注意，这不是 LLM 的 bug，而是 LLM 的本质特性。

不确定性——同样输入，LLM 可能走不同路径。我做过一个测试：同一个问题"推荐一台笔记本"，连续问 10 次，有 3 次没查知识库就直接回答了。你没法写单元测试，因为结果不可复现。企业系统要求确定性：同样输入必须同样输出。

不可控——LLM 可能跳过步骤、重复调用、调错工具。我让 Agent "先查库存再推荐"，它有时直接推荐不查库存。更夸张的是，我让它查价格，它调了 3 次同一个工具，参数一模一样。你说"不能重复调"，Prompt 写得再好，LLM 也只是"大概率"遵守，不是"一定"遵守。

无限循环——ReAct 循环没有停止条件。LLM 可能一直 THINK→ACT→OBSERVE 不停，token 烧完也不停。这不是假设——我在测试中真的遇到过，Agent 陷入了一个"查价格→觉得不对→再查→还是不对→再查"的死循环，烧了 5 万 token 才超时。

无审计——出了问题，不知道 LLM 为什么做了这个决定。用户投诉"推荐了不合适的商品"，我无法回溯推理过程。没有 Trace，无法调试。这是最让我头疼的——你连 bug 都复现不了。

右边四个是企业的需求。Workflow 就是用确定性的机制（状态机、Runtime、Tracing）来约束非确定性的 LLM。

## Key Emphasis
核心认知：LLM 是"大脑"，但大脑不能直接管理自己。需要一个"操作系统"——Workflow——来约束、调度、监控 LLM 的行为。

特别强调"不确定性"和"不可控"的区别：不确定性是"同样的事可能有不同的结果"，不可控是"你让它做的事它可能不做"。两个问题叠加，Agent 就是一个"随机执行的系统"。

## Optional Extension
**学员问：能不能用 temperature=0 让 LLM 确定性输出？**
答：temperature=0 只能让输出更稳定，但不能保证完全确定。LLM 的推理过程（调不调 Tool、调哪个 Tool）仍然不可预测。确定性要靠状态机和 Runtime 来约束，不是靠调参数。

**学员问：GPT-4o 的 Function Calling 不是已经很准了吗？**
答：Function Calling 的准确率确实在提升，但"准"不等于"可控"。它可能 99% 的时候调对 Tool，但那 1% 在企业环境里就是事故。Workflow 的价值是让那 1% 的错误可追溯、可恢复。

## Take Away
LLM 的问题是本质特性，不是 bug。用确定性约束非确定性，这是 Workflow 的核心价值。

## Why This Slide Matters
如果跳过这页，学员会以为"用更好的模型就能解决问题"。这页建立的认知是：模型能力再强，也需要运行时管理。
