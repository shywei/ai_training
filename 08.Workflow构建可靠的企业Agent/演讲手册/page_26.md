## Slide Objective
总结核心概念，预告下节课内容。一句话带走，让学员记住 Workflow 的价值。

## Suggested Presentation
今天三个核心能力。

Agent Runtime——ReAct 循环引擎，TaskPlanner 任务规划，六大组件协作。这是 Agent 的"操作系统"。没有它，LLM 只是一个"想到哪算哪"的推理引擎；有了它，Agent 才是一个"可靠执行"的系统。理解了 Runtime，就理解了 LangChain、LangGraph、Spring AI 的底层设计。

容错——重试、熔断、降级。这是生产环境的底线。MCP Server 挂了，Agent 不能跟着一起崩。三级容错让 Agent 在工具不可靠时仍然能提供服务。这不是"锦上添花"，而是"必须有"。

人在回路——高风险操作必须人工确认。这是企业安全的底线。AI 不应该对所有操作都有执行权。ConfirmationService 把"暂停→确认→恢复"的复杂性封装了，让安全控制变得简单。

今天的一句话：Workflow 不是流程，而是让 AI 在企业中可控运行的机制。很多人以为 Workflow 就是画流程图——不是。Workflow 是状态机 + Runtime + 容错 + 确认 + 追踪的完整体系。它的价值不是"让 Agent 按流程走"，而是"让 Agent 在企业中可控地运行"。

第九课预告——用 AgentScope Java 2.0 重构。先升级 Spring AI 2.0，再用框架重构同等功能，两套代码并排对比，看清框架接管了什么、边界在哪。手搓理解原理，框架提升效率——省的不是行数，是胶水。今天手搓 AgentRuntime 这 670 行里的连接、协议、会话、状态管理，框架能帮你接管；但什么算高风险、任务怎么拆、状态怎么流转，还得你写。具体能接管到哪一层，第九课两套代码并排数给你看。

## Key Emphasis
"Workflow 不是流程，而是让 AI 在企业中可控运行的机制"——这是本课的核心句，要强调。

三个核心能力不是独立的——Runtime 是骨架，容错是肌肉，人在回路是安全带。三者协作，Agent 才能在企业中可靠运行。

## Optional Extension
**学员问：AgentScope Java 2.0 真的能替代手搓的这些代码吗？**
答：要分两层看，别拍脑袋给百分比。第一层，胶水层与基础设施——连接、协议、会话、记忆压缩、事件流、子 Agent 调度——框架能接管，这才是它真正省力的地方。第二层，业务语义——什么算高风险、什么时候该确认、任务怎么拆、状态怎么流转——框架替代不了，还得你写。也别走向另一个极端，说"状态机/容错/人在回路框架都不管"——框架能做的和框架该做的别混为一谈。省的不是行数，是胶水；替代不了的是"想清楚业务"这件事。到底接管到哪一层、边界在哪，第九课两套代码并排数给你看。

**学员问：手搓过一遍再用框架，有什么好处？**
答：三个好处。第一，你能看懂框架的源码——因为它就是你写的那套逻辑的封装。第二，你能判断框架的局限——知道什么能做什么不能做。第三，你能做定制——框架不支持的功能，你知道怎么自己实现。这就是"手搓理解原理，框架提升效率"。**Demo 做法**：手搓 AgentRuntime（670 行）看清循环、确认、容错每个决策点。**生产做法**：用 AgentScope Java 2.0 重构接管胶水层（第九课两套代码并排对比），高风险定义、状态流转这些业务边界照样自己写。

## Take Away
评价 Agent 方案先看四件套：状态机、三级容错、人在回路、Trace——Prompt 写得再好，缺这四样就不是企业方案。

## Why This Slide Matters
跳过这页，学员回项目会直接上框架却不定义高风险和状态流转边界——框架接管了胶水，业务安全没人管。

## 课后扩展学习导读（深水区进阶指引）
对于希望在企业级复杂工作流架构、长周期持久化与可观测性体系进一步深潜的学员，本课根目录下特别沉淀了一份高质量的进阶资料：[扩展学习指南.md](../扩展学习指南.md)。
- **核心定位**：第八课是第二阶段“生产级导购 Agent 手搓实战”的收官之作。670 行手搓 Runtime 跑通了单机内存级 7 状态机，而《扩展学习指南.md》遵循 3W 精选导读法则，专为帮助学员跨越到工业级分布式持久化工作流架构而设计。
- **四大核心主题导读**：
  1. **持久化执行引擎（Durable Execution）**：深入 Temporal 与 Restate 架构，拆解 Event Sourcing（事件溯源）与 Replay（确定性重放）底层机制，实现 Pod 崩溃重启或跨天等待后不丢失状态且不重复执行外部副作用。
  2. **复杂工作流中的分布式 Saga 事务**：精读 Chris Richardson《微服务架构设计模式》Saga 原理，严格区分可补偿事务、支点事务（Pivot Transaction）与可重试事务，解决 LLM 动态决策下的逆向补偿与幂等闭环。
  3. **确定性与动态推理融合拓扑**：横向对比有限状态机（FSM）、有向无环图（DAG / LangGraph Pregel 超步模型）与目标导向行动规划（GOAP），掌握“外层确定性状态机围栏 + 内层微观 LLM ReAct”的生产级分层架构。
  4. **OpenTelemetry GenAI 工业级可观测性**：基于官方 `gen_ai.*` 语义约定标准，规范化采集 Token 消耗、工具耗时与 Trace 树，并建立敏感数据脱敏与单会话 Token 熔断断路器。
- **自测检验**：指南末尾准备了 3 道大厂架构级自测题（含长流程重放幂等陷阱、Saga 动态决策补偿一致性破坏排查与 OTel Token 暴涨自动告警拦截），请学员课后精读指南并尝试独立思考作答！
