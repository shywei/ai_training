CHAPTER 03

状态机的结构 — Node · Edge · Condition

三个核心元素
Node（节点）
Agent 所处的当前状态。每个节点定义了"在这个状态下，Agent 能做什么"。
例：EXECUTING 节点 → Agent 可以调用工具、思考、返回结果。
Edge（边）
状态之间的转换路径。每条边定义了"从状态 A 到状态 B 的条件"。
例：EXECUTING → COMPLETED 的边，条件是"所有步骤完成"。
Condition（条件）
触发转换的判断逻辑。不是 LLM 决定的，是代码硬编码的确定性逻辑。
例：retryCount >= 3 → EXECUTING → FAILED。
Checkpoint 与 Resume
Checkpoint（检查点）：在关键节点保存 Agent 的完整状态——当前步骤、已收集的工具结果、状态机位置。就像游戏的存档点。

Resume（恢复）：从检查点恢复执行。Agent 挂了、用户取消后反悔、超时后重试——都能从最近的检查点继续，不用从头来。

确定性 vs 非确定性
LLM 是非确定性的：同样输入可能不同输出。
状态机是确定性的：同样条件一定走同样路径。
Workflow 的价值就是用确定性约束非确定性。
