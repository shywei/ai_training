CHAPTER 03 · 核心机制

状态机结构 — Node · Edge · Durable Execution 持久化重建

状态机三大核心原语
Node（节点）— 当前计算单元
定义该状态下允许执行的动作（如 PLANNING 拆任务、EXECUTING 调工具、CONFIRMING 等待审批）。
Edge（边）— 状态转换路径
严格定义流转走向，杜绝非法跨跃（如 COMPLETED 终态不可逆流回 EXECUTING）。
Condition（条件）— 确定性判定逻辑
代码硬编码规则，非大模型自主决定（如重试计数超限 → 强制流转 FAILED）。
🔗 对齐 2026 现代图编排框架（StateGraph）
• State & Reducer ↔ WorkflowTrace 全局状态汇总
• Conditional Edges ↔ 条件路由分支（工具执行 / 重试判定）
• Interrupt & Checkpoint ↔ CONFIRMING 断点挂起与上下文持久化
持久化执行与故障重建（Durable Execution & Rehydration）
💾 1. 状态持久化策略（Node Checkpointing）
• 实时快照写入：每个 Node/Step 执行完成后，必须实时将状态机位置、变量上下文、已完成的工具调用结果写入持久化存储（PostgreSQL / Redis）。
• 乐观锁防护（Version Lock）：单记录维护版本号 version，杜绝多 Worker 竞争引发的脏写与双花执行。
🔄 2. 跨进程故障重建（Process Rehydration）
• 故障场景：系统宕机、K8s Pod 重启漂移、进程 OOM 崩溃或网络会话闪断。
• 重水化恢复（Rehydration）：新 Pod/进程根据 traceId 读取底层 Checkpoint 快照，在内存中精确重构状态机与上下文变量，直接从中断节点继续往下推进，绝不需要从头重新规划，且避免重复调用外部已有副作用工具。
Demo 现状：状态保存在内存 Map（traces / pendingConfirmations），单机简单直观。
生产级标准：全量引入 Durable Execution，状态落库 + Checkpoint 恢复，保障任务跨分钟/跨天断点续传。
