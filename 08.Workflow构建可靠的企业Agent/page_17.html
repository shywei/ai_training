CHAPTER 05 · 三级容错 3/3

③ 降级（Graceful Degradation）— 触发条件 · 兜底取值 · 失败模式

■ 触发条件（什么时候降级）
· 路径 A · 熔断命中：executeToolCall() 入口返回 getDegradationMessage()，作为"工具结果"注入对话，下一轮 THINK 自己决定怎么答
· 路径 B · 重试耗尽：executeToolCall() 返回 null → 直接 buildFinalAnswerPrompt() 强制收敛出最终回答
· 路径 C · 规划失败：TaskPlanner 失败 → 返回空步骤列表 → 降级为单步执行（不规划）
■ 兜底取值（降级降成什么样）
· 降级消息模板："[系统提示: 工具 X 当前不可用（连续失败 N 次），请基于已有信息回答用户。"
· 回答为空时兜底："抱歉，处理过程中遇到了问题，请重新描述您的问题。"
· 输出仍走 guardrails.sanitize() 脱敏；trace.recordEvent("…降级…") 留痕
· 降级目标：有回答 > 报错，但回答必须标记来源
■ 失败模式（降级会怎么坏）
· 编造：提示词只说"基于已有信息"，没禁"编造" → LLM 可能编一个价格
· 假成功：降级回答无标记，用户当正常答案用
· 故障被降级吞掉：只看回答不看 trace，降级率不上指标 → 事故在监控里"不存在"
代码锚点 — ErrorRecovery.getDegradationMessage() + AgentRuntime 两条降级路径
// 路径 A：熔断命中 → 系统提示注入对话，循环继续
return "[系统提示: 工具 " + toolName + " 当前不可用（连续失败 "
      + info.failureCount + " 次），请基于已有信息回答用户。";

// 路径 B：重试耗尽 → executeToolCall() 返回 null
log.warn("⚠️ 降级: 工具调用失败且重试耗尽，降级为直接回答（基于已有信息）");
traceService.recordEvent(traceId, "... 降级: 工具调用失败且重试耗尽...");
String answer = callLLM(buildFinalAnswerPrompt(...), reasoningModel);
// answer 为空 → "抱歉，处理过程中遇到了问题，请重新描述您的问题。"
✗ Demo vs 生产 · 三格
✗ 降级 = 让 LLM 自由发挥
问题：提示词未禁编造、输出无降级标记、故障被降级掩盖，降级率不是指标。
不解决：用户拿编造的价格做决策；故障全被降级吞掉，监控上看不出事故。
怎么解决：分级降级（缓存兜底 → 简化回答 → 明确报错三档）；提示词硬约束 + 输出校验（价格/库存字段必须来自工具结果，第四课结构化输出）；响应带降级标记、降级率当 SLO 一等指标；trace 留痕可查。
取舍：约束越死长尾灵活度越低，但对事实类字段宁可呆板不可编造。
