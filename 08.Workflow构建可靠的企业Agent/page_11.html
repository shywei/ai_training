CHAPTER 04

THINK → ACT → OBSERVE — 循环细节

实际执行例子（用户："帮我对比拯救者和 MacBook 的价格"）
THINK 1："需要查拯救者价格" → ACT 1：TOOL_CALL:search_knowledge(拯救者笔记本)
OBSERVE 1：拯救者 Y9000P ¥8999, i7/16GB/512GB
THINK 2："还需要查 MacBook" → ACT 2：TOOL_CALL:search_knowledge(MacBook Pro)
OBSERVE 2：MacBook Pro 14 ¥14999, M3/18GB/512GB
THINK 3："信息足够，直接回答" → 最终回复："拯救者 ¥8999 更便宜..."
为什么本课 Demo 用 TOOL_CALL:工具名(参数) 文本协议？
• 为什么第七课看起来像"黑盒"？因为开启了 Spring AI 默认的自动工具代理循环，框架在底层自动完成了 tool_calls → 执行 → 回传，外部看不到中间每一步状态。
• 本课 Demo 为何用文本协议？纯粹为了教学直观（零框架黑魔法），让你在日志和代码里一眼看清 THINK → ACT → OBSERVE 的字符串流转。
⚠️ 生产级白盒 Agent Runtime 标准做法（严禁文本正则！）
生产环境严禁使用文本正则解析工具调用（遇嵌套 JSON 参数、特殊字符或多工具并行必崩）！
正确做法：仍使用 OpenAI 原生结构化 tools / tool_calls 协议，但关闭框架自动内部循环（如 Spring AI 设置 internalToolExecutionEnabled(false)），由我们自己的 AgentRuntime while 状态机循环拦截模型返回的 ToolCall 结构化数组，依次经过：
状态机流转 → ConfirmationService 高危拦截 → ErrorRecovery 重试/熔断 → 执行并回传 role:"tool" 消息（第九课重构时正式切换为此模式）！
AgentRuntime.java — 循环核心
while (iteration < MAX_ITERATIONS) {
  iteration++;

  // THINK（Demo 教学用文本提取；生产级用原生 tool_calls 结构化返回）
  String thinking = callLLM(thinkPrompt, model);
  String toolCall = extractToolCall(thinking);

  if (toolCall != null) {
    // ACT（经过 ConfirmationService 拦截 + ErrorRecovery 重试/熔断）
    String result = executeToolCall(toolCall);
    // OBSERVE
    conversationHistory.append(result);
  } else {
    // 直接回答
    finalAnswer.append(thinking);
    break;
  }
}
Demo 教学实现：手搓 while 循环 + TOOL_CALL: 文本提取，直观展示 ReAct 闭环
