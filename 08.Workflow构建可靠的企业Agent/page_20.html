CHAPTER 08

Demo vs 生产 — 具体差距

持久化 Checkpoint
问题：状态在内存，重启丢失。
后果：Agent 执行到一半挂了，用户从头来。
做法：状态序列化到 Redis/MySQL。
分布式 Tracing
问题：Trace 存在内存，重启丢失。
后果：多实例 Trace 查不全。
做法：接入 OpenTelemetry/Jaeger。
SSE 真正流式
问题：Demo 执行完才逐字返回。
后果：用户体验差，等 5-10 秒空白。
做法：LLM stream=true + reactive 管道。
规划触发 — 混合路由
问题：Demo 用关键词触发规划。
后果：漏触发（"区别"类表述）→ 复杂任务单轮糙答；误触发 → 白花规划调用。
做法：规则快路径 + 快模型兜底分类。
确认超时 + 并发控制
问题：确认无超时，单线程无并发。
后果：工作流永远挂起；多人超卖。
做法：5 分钟自动取消；乐观锁。
LLM 成本控制
问题：每次规划/思考都调 LLM。
后果：token 费用爆炸。
做法：语义缓存、规划缓存、小模型做简单任务。
超时分级 + 熔断恢复探测
问题：写死 15s 超时；熔断后不探测恢复。
后果：等太久；恢复后又触发熔断。
做法：分级超时；半开状态探测。
