CHAPTER 04 · HARNESS 驾驭层体系详解

Harness 驾驭层全景架构：六大支柱与三大安全执行基石

Coding Agent 绝非裸模型聊天，而是“认知推理大脑 + Harness 驾驭层 + 安全执行基石”构建的可控研发闭环。
核心底座：Coding Agent 三大安全执行基石（严禁裸奔执行）
没有安全护栏的 Agent 等同于拥有 rm -rf 权限的高危脚本
1. Tool Permission（授权策略）
明确工具与命令白名单。只读工具（Read/Grep）自动放行；写与系统命令分级授权，默认禁止高危提权。
2. Approval Policy（人工审批）
高危动作必须阻断并弹窗审批（HITL）：涉及 git push、修改 .env 密钥、跑迁移脚本必须人类一键确认。
3. Sandbox（多维沙箱隔离）
文件系统受限在工作区 Workspace；非特权 Shell 隔离执行；出向网络（Egress）严格白名单拦截外联泄密。
① System Prompt（出厂系统底座）
厂商固化的底层行为规范、内置工具调用协议与基础安全边界。类似 OS 内核。
② Rules / `AGENTS.md`（项目常驻规范）
随代码库版本提交的工程宪法（构建命令、分层架构与代码红线），概率性约束行为。
③ `Hooks`（生命周期确定性护栏）
在 PreToolUse/PostToolUse 触发的强制脚本，自动拦截高危命令、格式化与跑单测门禁。
④ `Skills`（按需加载专业工作流）
封装特定 SOP（TDD、慢 SQL 诊断）的按需指令包，采用渐进式披露省下 90% 上下文。
⑤ `MCP & CLI`（外部系统与工具连接）
用 CLI 操作本地 Git/Maven，用 MCP 标准协议接入企业飞书、Jira 需求单与测试库。
⑥ `Subagents & Context`（子智能体隔离）
主 Agent 派发只读探索子智能体在独立窗口查资料，带回高浓度结论，杜绝主窗口污染。
闭环执行流： [用户任务与项目 Context] → [Prompt/Rules 规划装配] → [LLM 决策意图] → [三大基石+Hooks 校验拦截] → [沙箱落地执行] → [测试结果反馈迭代]
