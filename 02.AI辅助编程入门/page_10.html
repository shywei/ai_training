2. `AGENTS.md` 黄金三段式模板（控制在 150 行以内！）
# 1. Build & Verify Commands (精确构建与单测命令)
- 编译检查：`mvn clean test-compile`
- 跑单个测试：`mvn test -Dtest=ClassName#methodName`
# 2. Architecture & Tech Stack (架构与技术栈基准)
- JDK 21 + Spring Boot 3.2 + MyBatis-Plus 3.5.5
- 统一响应包装：`Result<T>`，业务异常抛 `BizException(ErrorCode)`
# 3. Red Lines (工程禁令)
- 严禁使用 Lombok `@Data` 注解在 JPA Entity 上；
- 严禁未经批准修改 `db/migration/` 下已提交的 Flyway SQL。
3. 为什么需要 Scoped Rules（按目录/后缀动态挂载规则）？
如果把前端 Vue 规范、后端 Java 规范、DBA SQL 规范全部塞进根目录 `AGENTS.md`，不仅浪费 Token，还会互相干扰注意力。2026 主流工具均支持三层规则作用域（Scoped Rules）：
Layer 1 · 仓库根级常驻（Always On）
根目录 `/AGENTS.md`（或 `/CLAUDE.md`）：只放全仓通用的构建命令、核心目录导航与最高安全红线，每次会话自动命中 Prefix Cache。
Layer 2 · 按文件后缀 Glob 条件激活（File-Pattern Scoped）
在 `.cursor/rules/*.mdc` 或 `.claude/rules/*.md` 中通过 `globs`/`paths` 声明：**只有当 Agent 读写匹配文件时才自动注入上下文！**
---
description: MyBatis XML 与 SQL 编写规范
globs: ["src/main/resources/mapper/**/*.xml", "**/*.sql"]
---
- 严禁 `SELECT *`；分页查询必须显式命中联合索引；禁止使用 `#{}` 以外的 `${}` 拼接。
Layer 3 · 子模块就近覆盖（Subdirectory `AGENTS.md`）
在 Monorepo 大仓中，`/payment-service/AGENTS.md` 与 `/web-admin/AGENTS.md` 仅在 Agent 进入对应子目录工作时动态合并生效。
