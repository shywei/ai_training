CHAPTER 04 · HARNESS 驾驭层“六件套”详解

支柱 ④ 实战 · 手把手剖析一个企业级 Java `SKILL.md`

1. 标准企业级 Skill 目录结构（指令 + 模板 + 校验脚本）
.claude/skills/spring-flyway-migration/
├── SKILL.md                # 核心触发元数据 + 标准化作业步骤 SOP
├── templates/
│   └── V_template__desc.sql # 团队标准 DDL 幂等注释与索引命名模板
└── scripts/
    └── lint_mysql_ddl.py   # 校验是否缺失主键/注释/是否含高危锁表语句
2. `SKILL.md` 真实源码剖析（`spring-flyway-migration`）
---
name: spring-flyway-migration
description: 当用户要求新增/修改数据库表字段、生成 Flyway SQL 迁移脚本或同步修改 MyBatis-Plus Entity 时触发此技能。
---
## Step 1: 版本号计算与模板读取
1. 扫描 `src/main/resources/db/migration/` 下最新 `V{日期}.{序号}__*.sql` 文件；
2. 读取本技能目录下 `templates/V_template__desc.sql` 作为结构基准。
## Step 2: 集团 DBA 强制规范
- 所有新增表必须包含 `id`, `tenant_id`, `created_at`, `updated_at`, `is_deleted`；
- 严禁使用 `FLOAT/DOUBLE` 存储金额，金额字段必须为 `DECIMAL(18,4) NOT NULL`；
- 每个字段与表结尾必须携带 `COMMENT` 中文说明。
## Step 3: 脚本静态审查与 Entity 同步（闭环验证）
1. 生成 SQL 文件后，**必须运行** `python .claude/skills/spring-flyway-migration/scripts/lint_mysql_ddl.py <sql_path>`；
2. 校验通过后，同步更新对应 `Entity.java` 字段，并运行 `mvn test-compile` 验证。
3. 编写高命中率 `SKILL.md` 的四大工程心法
① `description` 就是路由触发器（Router Prompt）
Agent 靠阅读 `description` 决定是否加载该 Skill。切忌写“数据库辅助工具”这种空话，必须写明**“当用户要求 [具体场景 A / 关键词 B] 时触发”**！
② 确定性检查交给 `scripts/`，别让 LLM 心算
大模型容易漏看某个字段没加 `COMMENT`。在 Skill 中内置一个 30 行 Python/Bash 检查脚本让 Agent 调用，比写十遍“请仔细检查”靠谱百倍。
③ 样板文件放入 `templates/`（Few-Shot 锚点）
把团队最标准的 Controller/Test/SQL 样板放在技能包的 `templates/` 下，让 Agent 生成前先 `Read` 样板，输出的代码风格与老员工毫无二致。
④ 让 Agent 帮你写 Skill（`/learn` 经验沉淀）
当你带着 Agent 历经千辛万苦排完一个棘手 Bug 或完成一次标准接入后，直接下令：“把刚才我们的操作步骤与踩坑点提炼成一个 `SKILL.md` 保存到 `.claude/skills/`”，立刻完成团队经验固化！
