Context Engineering — Agent真正看到的世界

Prompt决定AI回答得怎么样；Context决定AI能完成多复杂的任务。
Agent真正看到的上下文（从高到低）
System Prompt
Agent的人格、能力边界、安全规则
框架内置
AGENTS.md
项目技术栈、规范、架构说明 — 你写的
项目级
Rules
代码风格、禁止操作、架构约束 — 你定的
项目级
Skills
可复用的任务流程、审查清单、工作流 — 你编的
项目级
Memory
历史决策、踩坑记录、你的偏好 — Agent积累的
跨会话
用户Prompt
你当前的指令
本次任务
当前代码 + Git Diff
Agent正在操作的文件、最近的变更
实时

工具返回值、之前的交互（可能被截断）
易丢失
关键认知
Prompt Engineering vs Context Engineering
Prompt Engineering：优化你写的那一句话
Context Engineering：优化Agent看到的所有信息

Prompt只是上下文的冰山一角。Agent的输出质量，
80%取决于它能看到多少项目信息，20%取决于你怎么问。
为什么Agent比网页对话强？
网页对话：只有 Prompt + 历史对话（最下面两层）
Agent编程：全部8层上下文都能看到

这就是为什么同一个模型，Agent能完成网页对话做不到的事。
你的工作：管理上下文
AGENTS.md — 告诉Agent"你是谁、在什么项目里"
Rules — 告诉Agent"什么能做、什么不能做"
Skills — 告诉Agent"这个任务怎么做"
Memory — 让Agent记住"之前发生过什么"

写好这四个文件，比写好一个Prompt重要10倍。
