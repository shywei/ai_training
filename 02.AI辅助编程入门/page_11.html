CHAPTER 04 · Skills实战

Skills详解：怎么写、怎么用、去哪找

真实Skill示例：TDD（测试驱动开发）
来源：mattpocock/skills · 32万+安装 · skills.sh
# .opencode/skills/tdd/SKILL.md
---
name: tdd
description: Test-driven development with vertical slices
license: MIT
---
## Philosophy
核心原则：测试应通过公共接口验证行为，
而非验证实现细节。代码可以完全重构，
测试不应随之改变。
## Anti-Pattern: Horizontal Slices
不要先写所有测试再写所有实现。
这会产出脆弱的、与实现耦合的测试。
## Process
1. Plan：确认接口变更，列出要测的行为
2. RED：写一个失败的测试（只写一个）
3. GREEN：写最少代码让测试通过
4. REFACTOR：所有测试通过后，消除重复
5. 重复 2-4，垂直切片推进
## Refactoring Rules
提取重复 → 模块深化 → SOLID原则
仅在所有测试通过后重构
SKILL.md 结构拆解
Frontmatter（必填） — name（小写连字符，匹配目录名）+ description（1-1024字）
正文内容 — 核心原则、流程步骤、反模式、规则约束等
触发条件 — 描述何时使用此Skill，Agent据此自动匹配
工具权限 — 可通过opencode.json配置Skill的访问控制
在OpenCode中使用Skills
一键安装（推荐）
# 从 skills.sh 安装
npx skills add mattpocock/skills --skill tdd
# 安装到 OpenCode
npx skills add anthropics/skills --skill frontend-design
# 查看已安装的 Skills
npx skills list
自动下载SKILL.md并配置到OpenCode的skills目录。
手动创建（自定义Skill）
# 存放位置（OpenCode自动扫描）
项目级：.opencode/skills/<name>/SKILL.md
全局级：~/.config/opencode/skills/<name>/SKILL.md
兼容Claude：.claude/skills/<name>/SKILL.md
# 必须的 Frontmatter
---
name: my-skill # 小写+连字符，匹配目录名
description: 一句话描述做什么
---
name格式：^[a-z0-9]+(-[a-z0-9]+)*$，必须与目录名一致。
