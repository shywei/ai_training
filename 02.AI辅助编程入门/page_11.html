CHAPTER 04 · HARNESS 驾驭层体系详解

支柱 ③ · `Hooks` 确定性护栏与三大安全执行基石联动

写在 `AGENTS.md` 里的规则是“概率性道德劝说”；凡是要求 100% 阻断的工程红线，必须通过 Hooks 联动三大安全基石（Permission / Approval / Sandbox）强制落地！
1. 生命周期三大切面：安全基石的动态执行门禁
① `PreToolUse`（工具执行前 · 权限校验与人工审批触发） Exit Code 2 = 阻断
• 联动 Tool Permission：正则拦截 rm -rf、git push --force、DROP TABLE 或访问 .env 密钥；
• 联动 Approval Policy：检测到部署命令或对外网络调用时，挂起 Agent 并触发工程师人工弹窗审批；
• 联动 Sandbox：校验命令操作路径是否严格限制在当前项目 Workspace 沙箱内。
② `PostToolUse`（写入后自动触发 · 质量自动化流水线） 自动格式化 & 编译
每当 Agent 修改完 .java 或 .ts，**无需模型操心，沙箱自动执行** spotless:apply 或 eslint --fix，并运行增量语法检查，有报错立刻把编译器输出喂回上下文。
③ `Stop / TaskComplete`（交付前门禁 · 自动化验收守门员） 单测红灯禁止交差
当 Agent 回复说“我改好了”时触发：自动运行受保护的单测套件与 Git Diff 敏感信息扫描。**单测不全绿，立刻打回并强制 Agent 继续修复 Bug！**
2. 实战配置示例（`.claude/settings.json` / OpenCode Hooks）
// 联动 Tool Permission 权限白名单 + 自动格式化
{
  "permissions": { "allow": ["Read", "Grep"], "deny": ["Bash(rm *)"] },
  "hooks": {
    "PreToolUse": [{ "matcher": "Bash", "command": "./scripts/sandbox-guard.sh" }],
    "PostToolUse": [{ "matcher": "Edit", "command": "mvn spotless:apply -q" }],
    "Stop": [{ "command": "mvn test -q || exit 2" }]
  }
}
对比维度 Rules (`AGENTS.md`) Hooks + 安全基石体系
执行强制力 概率性（可能被大模型遗忘） 100% 物理级拦截阻断
Token 消耗 每轮持续吃掉窗口与显存 0 Token（本地 Shell/沙箱运行）
破坏性防护 防不住 rm / 密钥泄密 权限审批 + 沙箱物理防御
架构师箴言： 把技术规范写进 `AGENTS.md` 是“向模型建议”；把安全红线写进 Hooks、Permission 和 Sandbox 是“向系统下令”。企业级工程落地，必须用确定性脚本为概率模型划死绝不可逾越的安全雷池！
