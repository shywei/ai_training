CHAPTER 01 · 从网页对话到 AGENT 编程

AI 辅助编程四代演进路线（2021–2026）

短短五年，AI 在软件工程中的角色从“智能输入法”演进为“受控工程智能体团队”。
GEN 1 · 2021–2022
单行/函数补全
Tab Autocomplete
代表：GitHub Copilot 早期
交互方式：写注释或函数签名，按 `Tab` 键采纳灰字补全。
感知范围：当前打开文件的光标前后几十行（FIM 填充模式）。
核心局限：只管局部语法顺滑，不懂业务架构，无法跨文件修改。
人类角色：逐行手写代码的码农
提效幅度：局部编码 +15%~20%
GEN 2 · 2023–2024
IDE 内联对话与局部编辑
Chat & Inline Apply
代表：Cursor Chat / Copilot Chat
交互方式：侧边栏 `@file` 提问，或选中代码块 `Ctrl+K` 局部重写，点击 Apply 合并。
感知范围：显式 `@` 引用的数个文件 + 向量检索（RAG）片段。
核心局限：不会自己跑编译和单测，每次修改仍需人肉点击验证。
人类角色：副驾驶指挥员 (Copilot)
提效幅度：模块开发 +30%~40%
GEN 3 · 2025
自主长任务 Agent 与
Vibe Coding（氛围编程）
代表：Claude Code 1.0 / Cursor Agent
交互方式：自然语言一句话描述需求，Agent 自主跨十几个文件改代码并跑终端命令。
高光与阴影：Karpathy 提出 Vibe Coding（不看代码全点 Accept），做 Demo 极爽。
惨痛教训：在企业存量工程中无规矩乱改，产出大量无法维护的“AI 意大利面条代码”。
人类角色：甩手掌柜（极易翻车）
适合原型验证，严禁直上生产
GEN 4 · 2026 主流范式 本课核心
Agentic Engineering
Spec 驱动 + Harness 确定性护栏
代表：Claude Code / Qoder / Kiro / Antigravity
规格驱动（SDD）：先对齐 `SPEC.md` 接口契约与拆解 `PLAN.md`，再授权编码。
Harness 六件套护航：用 `AGENTS.md` 立规矩、用 `Hooks` 强制执行格式化与测试门禁。
多 Agent 协同：主 Agent 调度只读 Subagent 探路，保持上下文纯净。
人类角色：架构师 + 规格制定者 + 审查官
生产级高质量交付 3x~5x 提效
2026 工程师分水岭：2025 年大家比谁能让 AI 吐出更多代码（Vibe Coding）；2026 年企业比拼的是 Agentic Engineering（智能体工程化）——谁能用更严密的 Harness 底座 + Spec 契约 + 自动化测试闭环 驯服 Agent 稳定产出生产级代码。
