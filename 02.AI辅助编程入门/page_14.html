CHAPTER 04 · HARNESS 驾驭层“六件套”详解

支柱 ⑤ · `MCP` 与本地 `CLI` 的边界权衡（Token 经济学警示）

1. MCP（Model Context Protocol）：AI 界的“万能 USB 接口”
由 Anthropic 发起并成为行业标准的开放协议。它让 Coding Agent 跨出本地代码库，直接读取飞书/钉钉需求文档、Jira 缺陷单、YApi/Apifox 接口定义、Sentry 线上报错、PostgreSQL 测试库表结构。
2. 2026 重大工程警示：MCP “工具贪婪症”引发的上下文雪崩！
很多开发者一上来给 Agent 挂载 10 个 MCP Server（GitHub MCP、GitLab MCP、Docker MCP、MySQL MCP、浏览器 MCP……），结果发现 Agent 变笨了、响应极慢且账单暴涨！为什么？
· 1 个大型 MCP Server（如官方 GitHub MCP）包含 40~60 个 Tool 定义；
· 每个 Tool 的 JSON Schema（名称+描述+参数结构）占用 300~500 Tokens；
· 挂载 8 个 MCP Server = 150+ 个 Tools 常驻注入上下文前端 ≈ 45,000+ Tokens！
· 哪怕你只是让 Agent 改一行 Java 注释，这 4.5 万 Token 的工具定义也会塞进请求！
双重副作用：① 严重挤占有效代码窗口；② 当工具数量超过 50 个时，大模型选错工具或传错参数的概率呈指数级上升！
3. 2026 黄金选型准则：本地成熟工具调 `CLI`，企业内网系统用 `MCP`！
✅ 优先让 Agent 直接调本地 CLI（0 额外 Schema Token！） 强烈推荐
大模型在预训练阶段早已把开源标准 CLI 背得滚瓜烂熟！直接通过内置 `Bash` 工具执行，**无需挂载任何 MCP Tool Schema**：
· 代码与 PR 管理：用 git / gh pr view / glab 替代 GitHub/GitLab MCP
· 构建与容器操作：用 mvn / gradle / docker ps / kubectl 替代容器 MCP
· 接口调试与数据查询：用 curl / jq / mysql -e 加上一句 `SKILL.md` 说明即可！
🔌 什么时候才真正应该接入或封装 MCP Server？ 保持 ≤ 3 个
1. 企业私有协同与知识系统：飞书文档/语雀/Confluence PRD 读取、Jira/Tapd 需求状态流转、内部 YApi 接口契约拉取（无标准 CLI 且需 OAuth 鉴权）。
2. 需要安全脱敏与只读网关的存储：通过企业统一封装的只读数据库 MCP（自动脱敏手机号/身份证，禁止写操作）供 Agent 排查数据。
3. 浏览器 UI 自动化与视觉验收：如 `Playwright / Chrome DevTools MCP`，让前端 Agent 自己打开页面截图验收。
实战铁律：日常保持常驻开启的 MCP Server 不超过 2~3 个；不常用的 MCP 随用随开！
