CHAPTER 04 · 关键区分

Agent与LLM：谁负责什么？

🧑‍💼
Agent = 秘书
搜资料 · 排顺序 · 去重 · 摘要
整理好交给专家
→
🧠
LLM = 专家
阅读 · 理解 · 推理 · 给建议
只看秘书整理好的材料
Agent 负责（准备信息） LLM 负责（理解信息）
搜索信息（代码、文档、日志）理解Context中的信息
读取规则（AGENTS.md、Rules、Skills）推理：应该做什么、怎么做
调用工具（MCP、文件系统、Shell）生成回答、代码、计划
构建Context、适配窗口容量结合反馈调整方案
Agent负责准备信息，LLM负责理解信息。
Context ≠ Context Window
Context（上下文）
Agent组织给模型看的所有信息
· AGENTS.md / Rules / Skills
· Memory中的历史经验
· 用户当前的Prompt
· 项目代码 / Git Diff
· MCP工具返回的结果
→ 是"内容"
Context Window（上下文窗口）
模型一次能够阅读的最大Token数量
· 像一本书一次最多能翻开的页数
· 超出容量的信息模型"看不到"
· Agent通过裁剪、摘要、RAG适配容量
· 不同模型窗口大小不同
→ 是"容量"
Context 是内容；Context Window 是容量。
完整的数据流
用户需求
↓
Agent （搜索 · 读取 · 整理 · 裁剪 · 摘要）
↓ 构建
Context → 塞进 → Context Window
↓ 交给
LLM （理解 · 推理 · 生成）
↓ 输出
Agent 执行 → 工具反馈 → 继续循环
