# Agent日常交互高阶心法

## Slide Objective
补充讲解日常开发过程中，如何通过精确提问、闭环验证、Git止损等机制，提高与 Agent 交互的成功率，减少 Token 开销并防范代码混乱。

## Suggested Presentation
好，刚才我们讲的技巧主要是如何写好项目级配置文件和提示词。但在大家实际打开终端或 IDE，真正开始跟 Agent 写代码的那一刻，才是对我们人机协作内功的最大考验。
根据我们一线研发团队在大量实战中交过的学费，这里有 5 个最实用、最硬核的日常交互心法。

第一个是“精确上下文控制”。很多新手喜欢直接问：“帮我改一下我的订单逻辑。”这样问，Agent 会盲目扫描整个项目库。记住我们的口诀：只给 Agent 看它需要看的文件。用 @Files 或 @Symbols 精确定位，不仅反应极快，还能大幅节省 Token。

第二个是“终端命令闭环验证”。大模型写了代码后，不要把它当成圣经，更不要人肉帮它找编译错误。直接在 Prompt 里告诉 Agent 运行 `mvn compile` 或单测命令。它能看到报错日志并自己定位修复，这个闭环让 AI 自己跑，比你人肉排障高效得多。

第三个非常关键，是“Git 快速止损与回滚”。Agent 遇到复杂逻辑，经常会出现“改了这里坏了那里，结果越修越乱”的雪崩。所以在大改前，必须 Commit 一次做检查点。一旦发现它连续两轮都找不到 Bug，立刻 `git reset --hard HEAD` 强行回滚！不要相信它说“我再试一次就能修好”，及时止损，重新调优你的 Prompt。

第四个是“临时脚本开路法”。遇到需要批量重命名文件、提取数据或接口联调等任务，写 Java 代码编译太慢了。直接叫 Agent：“写个 Python 脚本在 scratch/ 下跑一下，搞定即删。”用脚本干体力活，又快又省力。

最后一个是“小步快跑分步走”。大需求容易使 Agent 在长文本生成中逻辑过载。把它拆成 3 到 4 个轮次：第一轮输出重构计划，第二轮编写实体，第三轮实现逻辑并测试。这就像和同事交接工作，分步骤逐步确认，准确率能提升 80% 以上。

大家把这 5 个心法刻在脑子里，这是真正的“避坑保命与省钱”铁律。

## Key Emphasis
* 强调 `@` 引用精准指定 context 的重要性。
* 强调“及时 Git 回滚止损”的工程安全习惯，打破对 AI 修复错误的盲目信任。
* 强调让 Agent 在 terminal 运行编译命令自己跑验证闭环。

## Optional Extension
如果学员问起硬回滚会不会丢失自己写的代码？回答：只要你在让 Agent 开始工作前先做了 commit 或 stash，回滚就只会撤销 Agent 生成的错误修改，绝对是安全的。这正是我们强调 Checkpoint 的原因。

## Classroom Interaction
大家之前用大模型改代码，有没有经历过它把一个本来能编译的项目改到彻底崩盘、怎么也修不好的经历？（大家会心一笑，引导建立 Git Checkpoint 的意识）

## Take Away
不要当 AI 写的代码的人肉测试员，用精确输入与硬回滚控制 AI 的行为边界。

## Why This Slide Matters
这是纯干货实操心法。学员往往只知道怎么启动工具，却在面对复杂的 Bug 迭代和代码雪崩时手足无措。这一页教给他们防身和控场的最实用策略。
