# 模型形态与产品计费

## Slide Objective
让学员了解当前主流大模型的分类及计费模式，建立“模型选型与成本控制”的认知框架。

## Suggested Presentation
大家在用 AI 编程时，是不是经常纠结：我到底该选哪个模型？GPT-4o、Claude 3.5 Sonnet、还是 DeepSeek？
其实，模型主要分三类。第一类是“通用对话模型”，像 Sonnet 或者一些国内大模型，特点是快、便宜，能处理 90% 的日常任务；第二类是“推理模型”，比如 Opus 和 DeepSeek-R1，它们慢、贵，但能做深度思考，是复杂 Agent 编程的核心驱动力；第三类是“多模态模型”，能看懂图文。
怎么选？核心原则是：便宜模型用来执行具体任务，贵模型用来做规划和架构。
在计费方面，不管你是买包月（Coding Plan）还是按量计费（Token Plan），都要明白，让昂贵的推理模型去做代码解释或者翻译，是在烧钱。
开源的方案（比如 OpenCode Go + DeepSeek）虽然工具本身免费，但调用 API 依然有成本。选型关键，永远是让“任务复杂度”匹配“模型能力”。

## Key Emphasis
强调三种模型形态的差异（通用、推理、多模态）。
强调选型策略：“便宜模型执行，贵模型规划”，这是控制成本和提高效率的关键。

## Optional Extension
如果学员问及本地部署模型是否可行，讲师可以回答：对于普通开发者，云端 API 性价比最高。本地部署需要昂贵的显卡，且推理速度往往达不到流畅编程的要求，除非企业出于极高的数据安全要求才会考虑私有化部署。

## Take Away
任务复杂度必须匹配模型能力，用便宜模型执行，用贵模型规划。

## Why This Slide Matters
如果不讲清模型分类和计费，学员在实操中会盲目追求最贵最好的模型，导致成本失控或响应缓慢。

## Transition
选对模型只是第一步，哪怕用了最贵的模型，如果你不会提问，它依然是个笨蛋。那么，我们该怎么跟它“说话”呢？这就来到了第三章：提示词工程。
