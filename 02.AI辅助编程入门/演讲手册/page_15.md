## Slide Objective
讲透 Subagents（子智能体）的核心架构价值：通过只读沙箱实现上下文物理隔离，防范主窗口被巨量中间数据撑爆。

## Suggested Presentation
请看第 15 页：支柱 ⑥ · Subagents（子智能体）的核心价值：上下文隔离。
在解决复杂问题时，我们经常需要 Agent 去全仓翻阅几十个文件，或者去搜寻海量的错误日志。
如果只用一个主 Agent，当它在终端执行了 20 次搜索、阅读了 30 个无关的 Java 类后，主会话的上下文窗口就会被瞬间撑满，产生严重的上下文退化，再也记不住核心需求。
【Subagents（子智能体架构）】的精髓在于**【物理级上下文隔离】**：
主 Agent 充当“项目主管（Orchestrator）”，它自己绝不轻易去逐行翻阅几十个文件。
遇到庞大的调研任务时，主 Agent 唤起一个临时的只读子智能体（如 Explore Subagent 或 Review Subagent），把任务派发给它。
子智能体在一个全新的、完全独立的上下文沙箱里疯狂搜索、翻阅了 5 万字的日志；任务完成后，子智能体只向主 Agent 返回一份 **200 字的精炼结论报告**，随即立刻销毁！
主 Agent 的上下文窗口从始至终保持在最精炼、干净的黄金状态！这是企业构建复杂 Agent 系统的标配拓扑。

## Key Q&A / Clarifications
**Q：Subagents 会消耗更多的 API 调用次数吗？**
A：总调用次数可能微增，但由于子智能体避免了主上下文的指数级滚雪球膨胀，总 Token 消耗和费用反而大幅降低，且任务成功率大幅提升。
