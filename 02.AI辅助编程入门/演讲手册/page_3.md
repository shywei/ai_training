## Slide Objective
讲透网页端对话编程与 Coding Agent 的本质区别，用痛点对比促成学员心智的彻底跃迁。

## Suggested Presentation
请看第 3 页：网页对话编程的天花板 vs Coding Agent 的环境闭环。
直到今天，很多程序员还在这样写代码：在网页版 ChatGPT 或网页版 Claude 聊天框里，复制 200 行报错，打一段话：“请帮我看看这个 NPE 怎么修”，AI 回复一段代码；程序员再小心翼翼地把代码拷贝回 IDEA，点运行；结果又报了新错，再截图贴给 AI……
这在工程上叫做【人肉总线（Human Message Bus）】！你不仅充当了文本搬运工，而且 AI 根本看不见你的整个工程目录结构、看不见 pom.xml 依赖版本、也无法运行测试验证自己的修改。
而【Coding Agent】是具备环境交互闭环的全新物种：
它直接运行在你的工作区内。它能主动读取文件、调用 ripgrep 全局搜索符号、在终端执行 `mvn test` 或 `npm run build`。
当编译报错时，Agent 自己抓取终端输出，分析根因，修改源码，再次重新跑测试，**直到所有单测绿灯通过才向你交付！**
从“动嘴皮子的聊天顾问”到“拥有执行手脚与验证闭环的数字员工”，这就是两者的云泥之别。

## Key Q&A / Clarifications
**Q：Coding Agent 在本地运行命令安全吗？会不会误删数据库或执行危险脚本？**
A：这正是我们第四章要重点讲解的“Harness 驾驭层”和 Hooks 护栏机制。通过确定性白名单与审批机制，牢牢锁住危险操作。
