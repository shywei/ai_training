# 从网页对话到AI编程：为什么要升级？

## Slide Objective
解释为什么需要从网页聊天转向 Agent 编程。通过痛点对比，让学员产生共鸣，理解 Agent 编程是解决真实开发瓶颈的必然趋势。

## Suggested Presentation
相信在座的大部分人，最初接触 AI 编程，都是从打开一个网页对话框开始的。
你把需求贴进去，它给你一段代码，你再复制回项目里。一开始觉得很神奇，但用久了，你一定发现了问题。
什么问题？它的天花板太低了。
它看不到你的代码，你得手动复制粘贴；它不能执行代码，跑报错了你得再贴回去给它；它没有文件系统权限，甚至聊着聊着，它就把前面的需求给忘了。
这个时候你会发现：网页对话，你驱动一切。你成了那个搬运代码的“搬运工”。
我们需要升级。我们需要的是一个能干活的 Agent，而不是一个只会聊天的机器。
Agent 的核心是什么？是它能感知整个项目，能自己改代码，跑测试，甚至能记住你的技术栈和偏好。在这个模式下，是你定方向，Agent 去执行闭环。

## Key Emphasis
强调网页对话的“天花板”（人工搬运、无执行环境、上下文截断）。
强调 Agent 带来的核心质变：从“人驱动一切”到“AI自主执行闭环”。不要在此处过多解释 Agent 的底层技术实现。

## Optional Extension
如果学员提问为什么现在的网页版也支持传文件了，可以解释：虽然能传文件，但仍然无法主动修改你的本地项目并运行测试，它仍然是个被动的“咨询顾问”，而不是“开发助手”。

## Classroom Interaction
有没有人在网页里让 AI 改代码，结果来回复制粘贴报错信息，最后自己都搞晕了？（观察学员反馈并共鸣）

## Take Away
你需要的不是更好的聊天工具，而是一个能自动执行代码闭环的 Agent。

## Why This Slide Matters
如果没有这页，学员就不会有使用 Agent 的迫切需求，他们会觉得网页版也挺好。这页制造了痛点并给出了解决方案方向。
