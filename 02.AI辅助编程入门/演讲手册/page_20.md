# Agent实战技巧精讲

## Slide Objective
提炼使用 Agent 过程中的高级经验和避坑指南，帮助学员在课后实操时少走弯路，真正用好工具。

## Suggested Presentation
看到上面的演示，很多人回去一试发现：为什么我的 Agent 这么笨？
其实，差距就在这五个技巧里。
第一，也是最重要的，一定要写项目指令文件（AGENTS.md）。没有它，Agent 就像盲人摸象。你把技术栈、规范写进去，它每次都会自动读，这能减少 50% 的错误。
第二，提示词的黄金公式。不要再只说“帮我写个接口”，记住这个公式：角色 + 任务 + 上下文 + 约束 + 输出格式。
第三，用 Skills 固化你们团队的经验。那些每次发版都要检查的清单，直接写成 SKILL.md，以后就是自动化的了。
第四点非常关键，对于大任务，一定要求 Agent “先计划，再执行”。如果它一上来就狂改 10 个文件，一旦方向错了，你要花大量时间恢复代码。
第五，不要只让 AI 写代码，让它帮你 Review 代码，你可能会发现很多你根本没注意到的潜在漏洞。
核心记住一句话：Agent 不是“许愿池”，它是你的“同事”。你们是对话式协作的关系，你需要不断地给它方向、审查它的结果，并做出调整。

## Key Emphasis
重点强调项目指令文件（AGENTS.md/CLAUDE.md）的必须性。
强调“先 Plan 再 Code”的工程安全意识。
强调人机协同的关系定位。

## Optional Extension
如果学员问指令文件写多长合适？回答：控制在 1000 字以内，只写最核心的强制约束，不要写无关紧要的客套话。

## Classroom Interaction
大家现在用大模型写代码，出错了是直接关掉重写，还是会耐心地告诉它错误信息让它改？（引导大家接受“迭代修正”的工作流）

## Take Away
不要把 Agent 当成一次性生成的机器，而要把它当作需要被管理、约束和反复沟通的数字同事。

## Why This Slide Matters
这是全课的实战精华。缺乏这些技巧，学员的新鲜感很快会在反复的错误生成中消磨殆尽。
