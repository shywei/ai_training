CHAPTER 04 · HARNESS 驾驭层“六件套”详解

支柱 ⑥ · `Subagents`（子智能体）核心价值：上下文隔离（Context Isolation）

传统单 Agent 模式：找路过程瞬间污染主窗口 Context 爆炸
当你让主 Agent “排查为什么优惠券扣减偶发超卖并修复”时，它为了摸清跨模块调用链，不得不顺藤摸瓜读取 **25~30 个 Java 类、Mapper XML 和配置文件**：
[Main Context Window - 200K]
├── System + AGENTS.md (8K)
├── Grep & Read 25 个无关/半相关源码文件 (110K 垃圾噪音!)
├── 3 次编译失败的冗长 Maven 报错堆栈 (30K 噪音!)
└── 真正开始写修复代码时，主窗口已塞满 148K 历史包袱！
主会话窗口占用率（写代码前已达 75%+）：
规则

2026 Subagent 模式：独立沙箱探路，只回传精华结论 上下文物理隔离
主 Agent（Orchestrator）遇到复杂探查或专项任务时，自动派生一个拥有**全新独立上下文窗口**的 `Subagent`（如只读 `Explore` 侦察兵或 `Code Reviewer`）：
[主 Agent] ──派发任务──> [Explore Subagent (独立窗口, Fast 模型)]
                           ├── 翻阅 30 个文件排查调用链 (消耗在子窗口)
                           └── 子会话销毁，110K 过程垃圾直接丢弃！
[主 Agent] <──仅回传 300 字《根因定位与目标文件行号摘要》！
主会话窗口占用率（始终保持低于 15% 的高智商纯净区！）：
规则
摘要
82% 纯净窗口留给核心架构推理与精准编码！
三大典型 Subagent 分工：① `Explore`（只读快速搜库定位行号）；② `Test-Runner`（跑全量测试并只回传失败用例摘要）；③ `Security-Reviewer`（独立视角交叉审查 Diff）。
记住这句话：Subagent 的第一价值不是“多线程并发”，而是“替主 Agent 挡掉翻箱倒柜的脏活，保护主上下文窗口的纯洁性”！ Context Hygiene = High IQ
