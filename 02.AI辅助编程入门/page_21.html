CHAPTER 08 · 实操

Agent日常交互高阶心法

技巧1：精确上下文控制（@ 引用）
拒绝让 Agent 盲目扫描整个项目库。主动使用 @Files 或 @Symbols 锁定关联范围，防止注意力分散并大幅节省 Token。
# 精确提问示例
"修改 `@OrderServiceImpl.java` 中的计算逻辑，使其入参字段与 `@OrderDTO.java` 严格对齐。"
技巧2：终端命令闭环验证
不要充当 AI 的人肉编译器。在 Prompt 中明确授权 Agent 运行本地终端命令，让其在沙箱内完成“编译-报错-修复”闭环。
# 编译验证指令
"实现接口后，在终端运行 `mvn clean compile` 验证。若报错请读取错误日志自行修正，直至编译通过。"
技巧3：Git 快速止损与回滚
Agent 容易陷入“越修越错”的循环中。大改前必须做 Git Commit 暂存。如果 Agent 连续两轮修不好 Bug，立刻硬回滚，调整 Prompt 重新开始。
# 止损口诀
大改前：git commit -m "checkpoint"
改砸时：git reset --hard HEAD & 重新调整Prompt
技巧4：临时脚本开路法
遇到数据迁移、批量重命名、或接口联调等繁重任务，指示 Agent 在 scratch/ 目录下编写轻量脚本（Python/Bash）直接执行。
# 临时脚本指令
"在 `scratch/` 下写个 Python 脚本，读取 `data.json` 转换为格式化 SQL，运行它并将结果输出。"
技巧5：小步快跑任务分步走
大需求容易使 Agent 的长文本生成逻辑过载。将大目标拆解为 3-4 步渐进式交互，每一步输出并验证无误后，再推进下一步。
# 分步提问示例
Turn 1: "先阅读项目结构，输出重构计划（不改代码）"
Turn 2: "按照计划，先编写 Entity 类，并编译验证"
Turn 3: "编写业务实现与单元测试"
金牌防坑铁律
如果大模型开始胡言乱语：1. 检查是不是上下文文件给得太多了；2. 检查是否有历史报错没有丢给它；3. 立刻回滚，不要让它“越修越乱”。
