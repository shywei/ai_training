CHAPTER 01 · 从网页对话到 AGENT 编程

网页对话编程的天花板 vs Coding Agent 的环境闭环

网页端 Chat 编程：程序员沦为“人肉 I/O 总线” 脱离工程环境
1. 视野盲区：手动摘抄代码，丢失跨文件调用链
网页 AI 看不到你的 `pom.xml`、Entity 定义和公共工具类。只能靠你手工复制片段，一旦涉及 5 个以上文件联动，立刻幻觉百出（编造不存在的方法）。
2. 反馈断裂：人肉充当“代码搬运工 + 报错传声筒”
AI 吐出代码 → 你复制到 IDE → 编译红线报错 → 你截图或复制堆栈贴回网页 → AI 道歉再给一版。单次需求来回倒腾 10 趟，心流彻底破碎。
3. 手脚被缚：没有文件系统与 Shell 终端执行权
不能用 `ripgrep` 搜索引用、不能跑 `mvn test` 验证断言、不能读 Git 历史对比变更。它只是一个“隔岸观火的参谋”，无法对最终工程交付负责。
4. 记忆清零：每次新建会话都要重新交代项目背景
没有项目级 `AGENTS.md` 与 `Rules` 自动挂载，每次都要重复强调“本项目用 Spring Boot 3.2 + JDK 21 + MyBatis-Plus”，极易漏掉团队红线。
Coding Agent：驻场入驻工程环境的“特种兵” 感知 → 行动 → 验证闭环
1. 原生仓库感知（Read / Grep / LSP / AST）
Agent 直接驻留在工作区目录，按需调用 `Grep` 搜索全库引用、读取上下游接口定义与 `git diff`，自己动手找齐上下文，拒绝盲目猜代码。
2. 多文件精准外科手术（Edit / Patch / Write）
一次性跨越 Controller、Service、Mapper、DTO 和单元测试文件施加原子化 Diff 修改，无需人类手动查找行号与复制粘贴。
3. 终端执行与自愈闭环（Bash / Compile / Test）
改完代码自动在终端执行 `mvn test` 或 `npm run build` → 捕获编译器/单测报错 → 自主定位根因并修正代码 → 重跑直至绿灯通过！
Agentic Loop 工程自愈闭环公式
[人类下达目标 & 验收标准] ➔ Grep/Read 探查 ➔ Edit 修改代码 ➔ Bash 跑单测/编译 ↺ (若红灯则读日志自动重试) ➔ [全绿交付 Diff]
本质跃迁：网页对话是“人服务 AI”（你喂料、你跑腿、你验证）；Coding Agent 是“AI 闭环交付，人做架构与验收”。
Human-in-the-Loop ➔ Human-on-the-Loop
