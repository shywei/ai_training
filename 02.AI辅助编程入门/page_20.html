CHAPTER 06 · 上下文退化原理与单兵防坑铁律

单兵日常高效交互五条铁律 —— 拒绝“AI 越修 Bug 越多”

01
Plan Mode 先行：想清楚再动刀，严禁上来就直接改代码
面对超过 2 个文件修改的任务，先切换至 Plan Mode（只读规划模式）。要求 Agent 先梳理涉及文件、依赖关系并列出 Task List。人类架构师花 1 分钟确认方案没硬伤后，再授权进入 Act Mode 开始编码。
防无头苍蝇
02
@ 精准喂料：用显式引用限定输入边界，杜绝全仓盲猜
提问时务必附带明确锚点：@PaymentService.java、@order_schema.sql 或指定报错行号。绝不要说“看看我的项目为什么下单失败”，漫无目的的全盘扫描会迅速将垃圾文件灌满上下文并稀释核心逻辑。
省Token防中毒
03
频繁快照，小步提交：Git 是你最强的“后悔药与止损线”
Agent 每成功实现一个小功能或跑通一个单测，立即执行 git commit -m "feat: xxx"。一旦发现 Agent 改偏了或把无关文件改坏，立刻 git reset --hard HEAD 彻底止损，绝不在被污染的代码上继续跟它争辩！
秒级止损机制
04
十五轮法则：聊到第 15 轮未果，果断执行断舍离
当会话超过 15 轮，或者上下文中堆满了长篇报错日志时，必须果断执行 /compact 压缩记忆，或者让 Agent 输出一份当前进展总结，直接开一个全新的 Clean Session 继续。千万不要在一个充满错误自回归的脏上下文里死磕！
清空错误累积
05
临时脚本开路：批量重构与脏活让外部独立脚本先验证
遇到上百个文件的批量替换、正则重构或数据库数据清洗时，不要让 Agent 逐个文件手写修改。命令它先在 scratch/ 目录下写一个轻量 Python 或 Shell 脚本执行 dry-run，跑通输出确认无误后再一键合入代码库。
安全高效防脏
日常交互二十字口诀： 先想后动刀，精准喂材料；小步常提交，十五轮就跑，脚本先验好！ 从源头消灭 90% 的 Bug 循环
