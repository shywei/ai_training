Demo 架构 — 组件与日志

v2.0 新增文件（Tag: v1.2.1）
auth/
  User.java + UserMapper + AuthController

memory/
  SessionMemory.java        Redis + 滑动窗口(MAX 20, 24h TTL)
  SummaryPipeline.java      累积摘要压缩(阈值 8 条, 保留 4 条)
  MemoryManager.java        context 构建(MySQL画像+Redis摘要/历史)
  UserProfile.java          画像实体(facts/preferences/tasks/constraints)
  UserProfileMapper.java    MyBatis Plus
  UserProfileExtractor.java @Async 异步抽取合并(写入 MySQL)

core/
  LlmInteractionLogger.java LLM 交互日志
日志文件（演示重点）
logs/llm-interactions.log（或 llm-chat.log）
对话请求/响应及 [Memory Injection] 完整 context 注入情况。
logs/llm-summary.log
SummaryPipeline 累积摘要压缩请求（含旧摘要）与 LLM 返回的新摘要。
logs/llm-profile.log
UserProfileExtractor 异步画像抽取（旧画像 JSON + 新对话 → 合并 JSON）。
模型配置（从 application.yml 读取）
agent.model.fast      -> 快模型：日常对话路由 & SummaryPipeline 摘要压缩
agent.model.reasoning -> 推理模型：复杂推理路由 & UserProfileExtractor 画像抽取
可在 Demo (v1.2.1) 验证哪些点（详细步骤见手册 page_17）
① 失忆基线
新会话问“我叫什么”→ 不知；查交互日志 context=null
② Redis 缓冲验证
redis-cli LRANGE session:{sid}:messages 0 -1 查列表
③ TTL 滑动刷新
redis-cli TTL 查看倒计时；新发消息后 TTL 重置回 24h
④ 满 8 条累积摘要
触发 SummaryPipeline，看 llm-summary.log 与 [对话摘要]
⑤ 画像合并抽取
带“记住”关键词或清空会话，看 llm-profile.log 合并 JSON
⑥ 画像跨 Session
查 MySQL user_profile 表；清空会话/重登后偏好依然生效
