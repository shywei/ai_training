CHAPTER 02 · 记忆架构体系

【架构重构】记忆系统双层解耦架构 — 逻辑记忆分类 vs 物理存储映射

课程工程分类模型：严禁将功能类型、时间生命周期与物理存储混为一谈！区分原始记录载体（会话流水）与认知记忆类型（工作/情景/语义/程序），第二层物理存储按访问模式与生命周期选型。
🧠 第一层 · 逻辑记忆分类体系（工程分类模型：流水载体 + 四大认知记忆类型） 认知功能与数据职责解耦
① 会话历史 (流水载体) 记录载体
核心：原始交互时序记录载体（工程流水）。
定位：承载原始日志；作为下述认知记忆抽取源头。
★ Demo 落地 (Redis)
② 工作记忆 临时
核心：当前任务运行态草稿纸（Scratchpad）。
价值：支撑 ReAct 循环与多步拆解，随任务销毁。
运行态 Context Window
③ 情景记忆 事件
核心：含时空因果的历史经历与成败案例。
价值：从历史挫败复盘，避免同类场景再次犯错。
事件记录 + 向量知识图谱
④ 语义事实与画像 静态
核心：客观事实、长效偏好与用户画像 Profile。
价值：高密度结论，每轮全量或相似检索注入。
★ Demo 落地 (MySQL)
⑤ 程序记忆 技能
核心：任务执行策略、操作技能与工作流 SOP。
价值：固化最佳工具调用轨迹与反思策略。
Prompt 策略模板库 / 规则集
💾 第二层 · 物理存储实现与生命周期治理（Storage Implementation & Lifecycle — 存哪里与怎么管） 按生命周期、读写频率与检索方式选型
Redis 内存缓存
映射：近期会话近景窗口（Sliding Window）。
机制：List 存最近 20 条，配 24h 滑动 TTL 衰减淘汰；极高读写吞吐，容忍易失。
MySQL 关系库
映射：结构化用户画像（user_profile 表）。
机制：ACID 事务，每用户一行；大模型异步抽取，执行新旧偏好覆盖合并。
pgvector 向量库
映射：跨会话非结构化长期语义记忆。
机制：切片 Embedding + HNSW 索引，按余弦相似度 Top-K 召回历史事实。
摘要压缩与遗忘治理
映射：上下文防膨胀与合规遗忘。
机制：SummaryPipeline 滚动摘要；Mem0 状态冲突消解；Ebbinghaus 衰减曲线与级联删除。
分层落地：逻辑记忆与物理存储不是一一对应关系！一个数据库可以承载多种记忆，一种逻辑记忆也可分级沉淀至不同介质。
