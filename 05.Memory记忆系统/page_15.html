CHAPTER 08 · 生命周期治理

记忆全生命周期治理 — 写入、冲突、遗忘与并发控制

✍️ 写入策略与门槛
写入机制：
· 同步写：强一致约束（用户显式纠正偏好），立即生效；
· 异步缓冲写：主流方案（消息队列解耦削峰，后台 LLM 提取画像，不阻塞主对话响应）；
· 定时批处理：低峰期批量聚类沉淀。

入库准入门槛：
严加过滤！仅记住长期偏好与客观事实；临时密码、短信验证码、无关闲聊与一次性需求坚决不入库。
★ 生产规范：重要画像支持用户确认
⚔️ 冲突消解与事实覆写
业务痛点：
用户偏好反转（“上月预算5000，今天改口预算15000”），新旧记忆冲突导致回答自相矛盾。

借鉴 Mem0 状态处理思想（ADD/UPDATE/DELETE/NOOP）：
新记忆入库前与已有记忆计算语义相似度，由 LLM 判定流转：
· ADD：全新事实，直接插入；
· UPDATE：新事实更新/推翻旧偏好；
· DELETE：用户显式要求清除；
· NOOP：语义重复，无变动忽略。
★ 核心法则：时间戳生效 + 事实覆写
⏳ 遗忘曲线与合规清理
时间衰减（遗忘曲线）：
模拟艾宾浩斯遗忘模型，检索打分引入时间加权衰减因子：
Score = Sim · e^(-λ·Δt) · Weight
久未访问的边缘记忆自然沉降降权。

TTL 与合规被遗忘权：
· Redis 设空闲与绝对双 TTL 上限防 OOM；
· 遵守 GDPR / 个保法要求，支持按 userId 级联物理清除（MySQL + Redis + pgvector 一键清除）。
★ 合规底线：不可删除即不可控
🔒 并发控制方案矩阵
并发写覆盖（Lost Update）：多 Pod 并发处理同一用户导致读-改-写覆盖。
方案权衡矩阵（拒绝盲目加锁）：
· MySQL 乐观锁：version 字段 CAS 比较重试，低冲突高吞吐，首选方案；
· 原子更新/追加：利用 Redis RPUSH / 数据库行级局部原子更新，无需读取整行；
· 幂等写入：按 msgId / traceId 唯一索引判重防重放；
· 分布式锁：仅用于跨系统高危一致性，绝非所有记忆写入通加分布式锁！
★ 架构准则：轻量原子与乐观锁优先
⚠️ 架构说明（Demo 教学简化 vs 生产级差异）： Demo 中采用“固定满 8 条对话触发摘要压缩”或“固定 5 轮从 Redis 刷入持久库”，属于教学演示简化（Educational Simplification）； 生产实践中多采用动态 Token 预算阈值触发（达窗口 65%）、基于语义完整性的任务边界触发（识别话题收尾）或异步周期性事实合并触发。
