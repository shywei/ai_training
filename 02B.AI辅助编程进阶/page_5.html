CHAPTER 01 · SPEC-DRIVEN DEVELOPMENT 企业级闭环

企业级 SDD 四步实操 SOP（人机协同控制点）

STEP 01 · 只读调研 Plan Mode
扫描存量代码，起草 Spec
开启只读 Plan 模式，禁止修改任何源码。让 Agent 检索工程结构与二方包，输出 requirements.md 与 design.md。
# 只读起草指令:
"请先检索相关模块，不要修改源码。针对幂等需求编写 requirements.md (EARS) 与 design.md，明确复用类。"
STEP 02 · 最高杠杆点 人类把关
审查并修正 Spec 架构契约
在写代码前拦截 80% 跑偏！花 5 分钟把关：是否漏用公司二方包？事务边界是否安全？异常码与降级是否规范？
# 人类架构纠偏:
"design.md 第2节有误：不要自己写锁，改为复用 RedissonLockTemplate；库存不足需抛特定异常。"
STEP 03 · 切片拆解 Task Slicing
生成 tasks.md 单步执行
审批通过后拆解为原子任务列表。严禁一次性跑全部任务，每次只授权执行 1 个 Task 并即时审查。
# 单步切片指令:
"基于 design.md 生成 tasks.md（每项限改≤3个文件并绑定单测）。先只执行 Task 1，汇报单测结果。"
STEP 04 · 闭环与清理 Verify & Clear
跑单测打勾 + 跨任务重置
单测通过自动勾选 [x]。每完成 1~2 个任务执行 /clear 清理历史对话，新会话读 .specs/ 无损接力。
# 无损接力指令:
"/clear 之后：读 .specs/ 目录，查看 tasks.md 进度，继续执行下一个未勾选的 Task 2 并跑通单测。"
缺陷放大定律：在需求阶段纠正 1 个设计缺陷成本为 $1，进入代码实现纠正需 $10，上线引发故障排查需 $100+！审 Spec 具有最高杠杆比。
