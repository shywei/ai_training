CHAPTER 05 · GIT WORKTREE 并行与 CI/CD 无头 AGENT

高阶提效 ① · 基于 git worktree 的多 Agent 并行研发工作流

痛点破局：同一目录开多个 Agent 改代码必然发生文件踩踏。方案：用 Git 原生 `git worktree` 秒级挂载共享 `.git` 的独立代码目录，一人指挥 3 个并发 Agent！
Worktree 1：主线特性 feat/pii
目录：`../wt-feat-pii` (分配端口 :3001)
Agent #1 任务：根据 SDD tasks 实现 PiiMaskUtils 脱敏并跑单测。
后台自主迭代 Task 2/4 中...
Worktree 2：紧急 Bug hotfix/json
目录：`../wt-hotfix` (分配端口 :3002)
Agent #2 任务：无需 git stash 打断主线！在独立目录复现线上 JSON 异常并微创修复。
零上下文污染，即修即提 PR
Worktree 3：方案竞标 exp/refactor
目录：`../wt-exp` (分配端口 :3003)
Agent #3 任务：探索激进重构方案，跑基准 Benchmark 测试，择优合入主线。
探索分支，随时安全丢弃
架构师警钟：Git Worktree 不等于独立的运行与网络环境！
必须配合动态端口与测试沙箱
工作区隔离：Worktree 仅隔离源码目录与工作分支，避免多 Agent 冲突。
端口冲突防范：各分支单测需配置动态随机端口（如 port=0），防止本地端口冲突。
数据库隔离：严禁多 Agent 共享同一物理测试库！使用 H2 内存库或 Testcontainers 容器隔离。
范式明确定位：此为研发态 Multi-Agent（代码任务并行），绝非第 10 课生产运行时业务 Multi-Agent。
# 30秒极速创建多 Worktree 并行研发环境:
$ git worktree add ../wt-feat-pii -b feat/pii-guard && cd ../wt-feat-pii && opencode run "按 tasks.md 开发"
$ git worktree remove ../wt-feat-pii // 任务完成安全卸载，.git 对象天然复用
