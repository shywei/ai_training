CHAPTER 03 · AGENTIC TDD 验证闭环与防作弊纪律

运动员与裁判员绝对分离：AI 辅助深度 Code Review 与人类最终把关清单

双智能体交叉审查架构（Cross-Agent Review）：
铁律：写代码的 Agent 绝不能充当代码审查员！自己的代码自己看，天生存在证实偏差（Confirmation Bias）。必须拉起一个独立只读会话的 Reviewer Agent 专职挑刺！
1. Coder Agent（编码特种兵）
专注执行 `tasks.md` 切片，拥有文件写权限与终端编译运行权，负责实现特性并跑通单测。
2. Reviewer Agent（红军挑刺专家）
只读权限！对比 `git diff` 与 `requirements.md (EARS)`，使用严格 Prompt 针对安全性、边界条件、并发竞争进行攻击性挑刺。
# 独立 Reviewer Prompt:
"请审查 git diff。重点检查：1. 是否篡改任何单测断言？2. 是否存在空 catch 吞异常？3. 并发场景是否安全？仅列出严重漏洞阻断合并。"
人类架构师最终把关清单（PR 合并前 5 问） 人工最后防线
1. 架构对齐：是否遵循已有模块职责？有无私自引入未审批的三方 Jar 包或造轮子？
2. 安全与合规：日志是否打印了明文手机号/身份证？SQL 查询是否绑定参数防注入？
3. 并发与事务：分布式锁的释放顺序是否在事务提交之后？回滚策略是否覆盖了外部 RPC？
4. 契约兼容：DTO/枚举修改是否考虑了老版本客户端与下游 Kafka 消费兼容？
5. 回滚方案：一旦线上报错，能否通过开关配置或数据库回滚脚本 1 分钟内止损？
五项全过方可点击 Merge，任何一项存疑立即打回重做！
