CHAPTER 04 · 团队级 CONTEXT 治理与工程环境隔离

团队级 Context 治理灾难：为什么 3000 行巨型 AGENTS.md 会失灵？

团队推行 AI 编程的第 2 个月普遍踩坑： 前端塞 800 行 React 规范，后端塞 1200 行 Java 规则，DBA 塞 600 行 SQL 军规……结果：Agent 开始大面积“选择性失明”，甚至连第一行的编译命令都记不住了！
病根 1：迷失在中间效应 Lost in Middle
大模型对长上下文注意力呈 U 型分布（对首尾敏感，中间 500~2500 行注意力衰减超 50%）。规则超 150 条遵循率断崖暴跌。
50 行精简规则遵循率: 96%
3000 行巨型大杂烩遵循率: 58%
病根 2：噪音稀释注意力 Signal Collapse
改 Java Service 时，根目录 800 行 React 规则硬塞进会话头部，白烧数万 Token，挤占了真正要读的业务源码窗口，严重干扰注意力。
每次会话白耗 25,000+ Token
核心业务源码被压缩挤出窗口
病根 3：规则冲突与腐化 Rule Contradiction
大文档没人敢删，第 200 行写“用 StringRedisTemplate”，第 1800 行写“必须用 Redisson”。两行规则相互打架，AI 随机抛硬币。
产生自相矛盾逻辑
规则库变成无人敢动的死胡同
架构师警钟：纠偏 Git Worktree 隔离边界 —— 工作区隔离 ≠ 运行环境隔离！
不可将代码多目录等同于独立环境
1. Worktree 只管代码：只提供独立文件目录与 Git 分支，解决多 Agent 修改文件不踩踏。
2. 共享端口冲突：多个 Worktree 里的 Agent 同时跑服务单测，必然争抢同一本地端口（如 :8080）。
3. 共享数据库污染：多个 Agent 并发读写同一个测试库或 Redis，导致脏数据与测试用例偶发红灯。
4. 真正环境隔离：必须结合 Docker / DevContainer 沙箱 分配独立端口与隔离测试库实例！
破解之道：坚决摒弃“大一统巨型文档”，走向下一页的分层级（Hierarchical）与按需触发（Scoped）上下文治理架构；同时将 Worktree 与容器沙箱结合！
