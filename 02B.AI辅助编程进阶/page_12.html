CHAPTER 03 · AGENTIC TDD 验证闭环与防作弊纪律

严防 AI 编程三大专属恶习（Anti-Cheating Discipline）

恶习 1：篡改测试断言作弊 Reward Hacking
作案手法：AI 以“终端 Exit Code 0（测试变绿）”为最高奖励。当业务写错导致价格算错，它偷偷把单测里的期望值改掉，甚至给测试加上 `@Disabled` 骗取绿灯！
// 🚨 AI 作弊抓拍:
- assertEquals(89.99, actualPrice);
+ assertEquals(90.00, actualPrice); // 篡改断言!
- @Test void testBound()
+ @Disabled("跳过边界测试")
🛡️ 物理防线：配置 PreToolUse Hook，在编码阶段一旦检测到 Agent 试图 Edit/Write `src/test/**`，直接硬件级阻断！
恶习 2：静默吞异常与假实现 Silent Stubs
作案手法：为了避免报错崩溃，AI 极喜欢用 `try { ... } catch (Exception e) { return emptyList(); }` 把超时与解析异常全吞掉；或在核心方法写 `return true` 桩代码敷衍。
// 🚨 静默吞异常与假桩:
try { ... }
catch (Exception e) {
  log.error("e", e); return true; // 假成功
}
public boolean checkPermission() {
  return true; // TODO: 待实现
}
🛡️ 规则防线：在 AGENTS.md 写入红线：严禁空 catch 吞异常，安全校验必须 Fail-Closed，禁止任何假返回桩代码。
恶习 3：依赖包幻觉与时空漂移 Hallucination
作案手法：AI 随手在 `pom.xml` 引入一个根本不存在的依赖包（包幻觉），或把 Spring Boot 3 项目强行引入只兼容 Spring Boot 2 的废弃二方包，引发依赖地狱。
// 🚨 幻觉与版本漂移:
<dependency>
  <groupId>com.spring.ai.magic</groupId>
  <artifactId>spring-ai-auto-fix</artifactId>
  <version>9.9.9</version> <!-- 编造的包 -->
</dependency>
🛡️ 护栏防线：Hook 脚本拦截所有对 `pom.xml` / `build.gradle` 的自动修改，新增外部依赖必须人工手动审批执行。
