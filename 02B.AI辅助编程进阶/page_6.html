SDD 实战对比：在 Spring Boot 电商交易系统中新增“订单幂等与库存预占”特性

反面：一句话 Vibe Coding 盲写 生产事故高危
模糊提示词：“帮我给 OrderService 的 createOrder 加上防重幂等和扣库存，用 Redis 实现。”
@Transactional
public OrderDTO createOrder(CreateOrderReq req) {
  // ❌ 漏洞1: 非原子并发穿透 + 忘设TTL永久死锁
  String key = "order:" + req.getUserId() + ":" + req.getSkuId();
  if (Boolean.TRUE.equals(redis.hasKey(key))) return null; // NPE
  redis.opsForValue().set(key, "1");
  try {
    // ❌ 漏洞2: 先查后扣非原子，高并发必然超卖
    int stock = Integer.parseInt(redis.get("stk:" + req.getSkuId()));
    if (stock > 0) redis.set("stk:" + req.getSkuId(), String.valueOf(stock-1));
    return orderMapper.insertOrder(req);
  } catch (Exception e) {
    // ❌ 漏洞3: 静默吞异常，导致 @Transactional 事务不回滚！
    log.error("error", e);
    return new OrderDTO(); // 假成功脏数据
  }
}
诊断：AI 未知已有 Lua 脚本，写出非原子穿透代码，且捕获异常未重抛直接废掉 Spring 事务！
正面：Spec-Driven 规格驱动工程产出 复用基建 · 原子安全 · 边界清晰
SDD 规格约定：EARS 契约拦截重放 + 强制复用 Lua 原子预占 + 独立事务与异常回滚补偿。
// ✅ 1. 幂等锁置于事务外部，防止锁在事务提交前释放
public OrderResp submitOrderWithIdem(String tenantId, String idemKey, CreateOrderReq req) {
  String redisKey = String.format("ord:idem:%s:%s", tenantId, idemKey);
  // ✅ 2. 原子 SET NX EX 15m，重放直接返回业务幂等码
  Boolean locked = redis.setIfAbsent(redisKey, "PROCESSING", Duration.ofMinutes(15));
  if (!Boolean.TRUE.equals(locked)) throw new BizException(DUPLICATE_ORDER);
  boolean stockReserved = false;
  try {
    // ✅ 3. 复用存量 Lua 脚本原子预占库存，杜绝超卖
    stockReserved = stockLuaService.tryReserveStock(req.getSkuId(), req.getQty());
    if (!stockReserved) throw new BizException(STOCK_INSUFFICIENT);
    return orderTxService.createOrderInNewTx(tenantId, req);
  } catch (RuntimeException ex) {
    // ✅ 4. 失败补偿：释放预占库存 + 删幂等Key允许重试，异常上抛回滚
    if (stockReserved) stockLuaService.releaseStock(req.getSkuId(), req.getQty());
    redis.delete(redisKey);
    throw ex;
  }
}
