CHAPTER 02 · 存量复杂工程（BROWNFIELD）破局与安全重构

复杂跨模块 Bug 根因分析（RCA）四步法与防篡改边界

告别“把一行报错贴给 AI 瞎猜乱改”： 直接贴报错只会让 AI 顺拐打补丁。必须严格执行排障流水线：写复现单测 → 提出假设并验证 → 实施微创手术 → 补充防御性断言。
STEP 1: 编写复现红灯单测
先复现，严禁碰源码
用真实入参写单元测试，亲眼看到红灯报错完全复现线上堆栈。
// 复现用例必须变红:
@Test void shouldFailOnEscaped() {
  // 确认抛出 JSONParseException
}
STEP 2: 提出假设与验证链
建立科学假设链
命令 Agent 列出 3 个根因假设，要求给出代码行号证据，排除伪因。
# 假设检验提示:
"分析堆栈，给出3个根因假设。为什么状态机没忽略转义？给出证据。"
STEP 3: 最小范围微创手术
精准修复，杜绝乱改
仅修改引发根因的最小代码（≤ 10 行）。严禁顺手重构无关代码！
# 最小 Diff 修复:
if (c == '\\' && !isEscaped) {
  isEscaped = true; continue;
}
STEP 4: 补齐防御性回归网
红灯变绿 + 全套全绿
第一步的红灯单测变绿，且全套既有测试 100% 保持绿灯，合入回归库。
# 运行回归命令:
$ mvn test -Dtest=RcaRegressionTest
[INFO] BUILD SUCCESS
架构师警钟：纠偏 Hook 防篡改边界 —— 本地 Hook 可以被绕过！
不可把本地 Hook 等同于绝对安全防线
本地 Hook 脆弱性：开发者或 Agent 可能使用 --no-verify 跳过钩子，或误改本地配置。
1. 远程不可控 CI：云端流水线强制重新拉取权威单测执行，彻底脱离本地篡改影响。
2. 主干分支保护：受保护分支禁止任何人/Agent 直接 push，必须走 PR 校验。
3. 强制 Code Review：运动员与裁判员绝对分离，资深工程师核对测试断言真实性。
工程纪律：没有写出“复现红灯单测”前绝不动源码；本地 Hook 提供第一道防线，远程 CI + 分支保护 + Code Review 筑牢防篡改终极屏障！
