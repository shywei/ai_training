## Slide Objective
阐明自动化验证闭环作为 Coding Agent “感知双眼”的底层机理，系统讲解编译检查（1.5s）、方法级定向单测（2.0s）与静态规范扫描（1.0s）构成的“三道秒级门禁”，并确立标准 Agentic TDD（测试先行驱动自愈）的工业级操作闭环。

## Suggested Presentation
各位开发者，很多人经常疑惑：为什么人类工程师自己写代码时可以通过脑内推演，而 Coding Agent 离开自动化测试就寸步难行？

请大家理解一个底层现实：**自动化测试与编译器报错，就是大模型的“眼睛”！**
如果一个 Agent 生成完代码后没有任何终端反馈，它其实是在一间黑屋子里蒙着眼睛默写代码——这种“开环生成”的一发命中率通常不足 45%；
而一旦我们把它接入秒级的自动化工具链，赋予它在终端看到编译报错和断言失败堆栈的能力，它就能依托自身强大的上下文推理能力，在毫秒级展开**自愈循环（Self-Healing Loop）**——编写测试 → 触发红灯 → 编写实现 → 修复报错 → 单测变绿。在闭环驱动下，Agent 的一次性交付成功率会直接飙升至 **92% 以上**！

为了让 Agent 的自愈循环高效运转，企业级工程必须构建**三道秒级反馈门禁**：

**第 1 道门：编译器静态类型检查（~1.5 秒）**
大模型偶尔会产生幻觉——比如调用一个不存在的方法名、漏写泛型或者参数类型搞错。Java 等强类型语言的编译器就是天然的“防幻觉第一道粗滤器”。
我们在 `AGENTS.md` 中约定编译命令：
`mvn test-compile -T 1C -q`
加上 `-q` 静默参数，只有在报错时才打印 ERROR 行，避免成千上万行无用的依赖下载日志撑爆上下文。

**第 2 道门：方法级定向单测（~2.0 秒 —— 全流程灵魂核心！）**
大家一定要注意：**严禁让 Agent 每次改一行代码就去跑根目录全量的 `mvn test`！**
在很多大项目中，全量单测跑一次要 15 分钟，甚至要启动完整的 Spring 上下文和数据库连接，不仅极慢，而且会把模型拖入漫长的等待中。
我们必须在 `AGENTS.md` 中教会 Agent 跑**精确到方法级的定向单测**：
`mvn test -Dtest=PiiMaskUtilsTest#shouldMaskPhoneAndIdCard -q`
利用纯内存 Mock（如 Mockito），2 秒钟内就能拿到清晰的断言对比！Agent 靠这个 2 秒级的高频反馈，可以飞速迭代 3 轮直至全绿。

**第 3 道门：Spotless / Checkstyle 规范门禁（~1.0 秒）**
千万不要在 Prompt 里浪费几十行 Token 去跟大模型磨叽：“大括号不要换行、每一行不要超过 120 字符、import 必须按字典序排列……”大模型对排版字符的计数天生不精确！
规范问题统一交给确定性的 Linter 工具：
`mvn spotless:apply checkstyle:check -q`
让工具在任务收尾时一键自动格式化，生成的 Git Diff 保证 100% 严丝合缝契合团队规范。

请看屏幕下方的 **Agentic TDD 标准四步循环**：
1. **锚定测试（Red）**：根据需求契约先写 JUnit 用例，运行并确认失败；
2. **锁死测试**：锁定 `src/test/` 权限，防止 AI 偷改断言；
3. **迭代自愈**：编写业务代码，利用定向单测反馈自主纠错；
4. **全绿交付（Green）**：单测全绿 + 规范检查通过，勾选任务，优雅交付。

## Key Q&A / Clarifications
**Q：在 Spring Boot 项目中，单测一跑就要加载 `@SpringBootTest` 启动容器，怎么做到 2 秒级反馈？**
A：必须在团队内推行**单元测试（Unit Test）与集成测试（Integration Test）的物理分层**！
在 Agentic TDD 阶段，强制要求 Agent 编写基于 `@ExtendWith(MockitoExtension.class)` 的纯内存单元测试，依赖的下游一律使用 `@Mock` 模拟，绝不加载任何 Spring 容器和外置中间件，这样 JVM 初始化与执行通常可在 1~2 秒内完成。对于需要启动 Docker 容器或加载完整上下文的集成测试（如 Testcontainers），留到特性收尾或 CI 流水线阶段统一执行。

**Q：有些开发觉得先写测试再写实现很别扭，Agentic TDD 会不会拖慢进度？**
A：对于人类手写单测而言确实存在心理负担，但对 Agent 来说完全相反！因为让 Agent 先写出几个明确的入参断言 `@Test`，本质上是给它后面的实现代码提供了一个**绝对可收敛的评测基准（Evaluator）**。有测试当裁判，Agent 可以自主试错 3 轮直接把正确代码试出来；如果没有测试，Agent 自信地写出一堆漏洞百出的代码，最后还得人类花半小时肉眼帮它找 Bug，综合耗时反而高出数倍。
