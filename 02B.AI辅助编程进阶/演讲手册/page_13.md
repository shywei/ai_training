## Slide Objective
确立“运动员与裁判员绝对分离（Cross-Agent Review）”的审查哲学，掌握让独立只读 Review Agent 针对 Java / Spring Boot 并发、事务、N+1 SQL 等隐蔽缺陷进行深度找茬的技巧，并建立人类工程师不可外包的“最终合并把关五大铁律”。

## Suggested Presentation
各位请看屏幕，当 Agent 按照 tasks 完成了代码编写并且单测变绿后，很多开发者习惯在同一个聊天窗口里追问一句：“你觉得这段代码写得好不好？有没有什么 Bug？”
注意，**这是极其业余的做法！**
因为写代码的这个会话上下文里充斥着它刚才的思考路径和辩解逻辑，它存在严重的**自洽确认偏误（Confirmation Bias）**，哪怕代码里有明显的死锁风险，它大概率也会告诉你“代码结构优秀、完全符合规范”。

在专业工程界，我们坚决贯彻：**运动员与裁判员绝对分离！**
审查必须分两关推进：

**第一关：独立只读 Review Agent 交叉找茬（Cross-Agent Review）**
必须彻底新开一个纯净的会话（或者唤醒一个使用异构大模型的只读 Subagent）。让它只读对比 `git diff main...HEAD` 与 `.specs/` 设计文档。
大家看左侧针对企业级 Java / Spring Boot 项目整理的**五大必查靶点**：
1. **并发与线程安全**：检查 Spring 单例 Bean 中是否错误地定义了包含请求状态的成员变量、是否误用了非线程安全的 `SimpleDateFormat`；
2. **Spring 事务陷阱**：重点抓捕同类内部 `this.method()` 自调用导致 AOP 代理失效、以及在 `@Transactional` 大事务方法内部嵌套远程 RPC 或阻塞式 HTTP 调用的低级失误；
3. **数据库与性能灾难**：严查在 for 循环内部执行 SQL 查询（N+1 查询）、未经限制的深分页、以及无界内存集合引发的 OOM；
4. **安全与数据越权**：检查接口是否真正做到了 `tenantId` 租户隔离和水平越权校验，日志中是否打出了明文身份证或 Token。

大家看左下角的 **Review 提示词模板（/review-pr）**：指令第一句就是“**禁止表扬代码！** 只输出达到 BLOCKER 或 WARNING 级别的实质性隐患，每条必须指出文件名、行号以及具体的故障触发入参。”这种批判性 Agent 通常能在 30 秒内抓出人类肉眼极难发现的深层并发与事务死锁隐患。

**第二关：人类工程师最终拍板五大铁律（责任绝不可外包！）**
虽然 AI 能帮我们挡掉 80% 的机械缺陷，但大家必须清醒：**线上如果发生生产事故，背锅被问责的永远是点了 Merge 按钮的人类工程师，而不是大模型！**
在点击合并前，人类必须亲自逐项核对右侧的五大铁律：
1. **先审 `src/test/` Diff**：花 1 分钟看新增单测的断言是否真实有效，确认既有测试未被弱化；
2. **核心领域模型与 DDL 变更 100% 逐行精读**：数据表结构、资金与订单状态流转，必须由人类架构师亲自精读确认；
3. **架构边界与依赖合规**：确认 `pom.xml` 未被偷偷加包；
4. **可观测性与降级预案**：关键路径是否有足够的日志打印？万一下游超时是否有熔断降级兜底？
5. **最重要的底线——“凌晨两点排障测试”！**
每次合并代码前，在心底自问一句：
> **“如果这段代码今晚凌晨 2 点在生产环境触发 P1 报警，把我从睡梦中叫醒，我能在 5 分钟内不靠 AI 解释，讲清楚它的完整执行链条与事务边界吗？”**
如果答案是“不能”，那么不管单测多绿，都绝不允许点击 Merge！你必须先弄懂它，或者要求其重构精简。

## Key Q&A / Clarifications
**Q：为什么推荐使用异构模型（比如用 Claude Code 编写代码，用 DeepSeek-R1 或 GPT-4o 审查代码）？**
A：不同模型厂商在预训练语料和对齐策略上存在不同的偏置（Bias）。同一款模型往往具有相同的“思维盲区”；而使用异构模型开展 Cross-Review，由于推理机制与注意力权重的差异，往往能以完全不同的思维视角洞察到原模型遗留的逻辑漏洞和边界死角。

**Q：有些 PR 包含 15 个文件改动，人类逐行看确实看不过来怎么办？**
A：如果一个 PR 包含 15 个文件改动，说明**任务拆解（SDD 切片）本身就做错了！** 在 SDD 规范下，一个 PR 对应的应该是 `tasks.md` 中的 1~2 个原子切片，文件改动一般应控制在 3~5 个以内。将大 PR 拆解为多个小步交付的微型 PR，是保证人类 Reviewer 保持高质量把关心智的前提。
