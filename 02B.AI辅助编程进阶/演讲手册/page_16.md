## Slide Objective
阐述“Compound Engineering（复利工程）”在企业级 AI 规模化落地中的核心价值，建立“捕获翻车 → 提炼 3 行反模式疫苗 → 随 PR 提交入库 → 全员永久免疫”的标准化研发飞轮，展现团队工程认知资产持续复利增值的演进曲线。

## Suggested Presentation
各位请看大屏幕上的这个概念——**Compound Engineering（复利工程）**。这是当前硅谷顶尖技术团队在实践 AI 原生软件工程时最推崇的理念。

大家可以对照一下我们身边的团队：
**平庸的团队**在用 AI 时是怎么做的？小张让 AI 写了一段代码，AI 犯了一个经典的低级错误（比如用 `Double` 算金额导致精度丢失、或者在事务里调了外部 HTTP 接口）。小张在聊天框里把 AI 骂了一顿，然后手工改掉了。
结果下周，小李让他的 AI 做另一个模块时，AI **又犯了一模一样的错误**！小李又得重新踩坑、重新肉眼排查一遍。整个团队每天都在打地鼠，同样的坑被 50 个人重复踩 100 遍，效率毫无沉淀。

而**顶尖的工程团队**建立了一套如同人体免疫系统一样的自愈机制：
只要有任何人在 Code Review 或者单测中抓到了 AI 的一次典型翻车，**必须当场将其提炼为 3 行高浓缩的“反模式疫苗”，提交进 Git 仓库。团队所有人 `git pull` 的瞬间，全公司几十名开发者的 AI 智能体，瞬间获得永久群体免疫！**

这就是 **Compound Engineering 的四步飞轮**：

**STEP 1 · 捕获典型翻车（Catch）**
在日常 PR 评审或单测回归中，捕捉到一类有代表性的 AI 编码缺陷。
例如屏幕下方的真实案例：某位同学让 AI 生成解析 LLM JSON 返回值的 DTO。大模型定义了一个普通的内部类，但漏掉了 Jackson 的 `@JsonIgnoreProperties(ignoreUnknown = true)` 注解。结果线上大模型偶尔在 JSON 里多吐了一个冗余字段，Jackson 反序列化直接报错，整个服务链路崩塌。

**STEP 2 · 提炼反模式疫苗（Codify）**
不要写几百字的长篇说明，大模型看不进去！推行标准的三段式疫苗模版：
**“❌ 禁止 + ✅ 必须 + 1 行正确范例”**。
在 `.opencode/rules/llm-dto.md` 中快速追加 3 行：
- ❌ **禁止**：接收大模型响应的 DTO 缺少 `ignoreUnknown = true`；
- ✅ **必须**：优先使用 Java 17 的不可变 `record`，并显式标注字段描述。

**STEP 3 · 随 PR 入库共享（Commit —— 核心考核点！）**
团队必须立下一条硬性研发制度：
**修复该 Bug 的 Git 提交中，必须同时包含这两部分内容：① 修复业务代码与复现单测；② 对应的 3 行 Rule 规则更新！**
如果没有提交防复发规则，该 PR 直接不予批准合并！

**STEP 4 · 全团队永久免疫（Immunize）**
当这个 PR 被合入主干后，第二天全团队拉取最新代码。无论其他人使用的是 Claude Code 还是 Cursor，只要他们的光标碰到 DTO 类文件，这条规则就会自动生效，从此在整个公司范围内彻底杜绝同类故障的发生！

大家看右侧的 **12 周复利演进曲线**：
- **第 1 周**：AI 啥都不懂，PR 返工率高达 40%；
- **第 4 周**：积累了 18 条核心反模式规则和 6 个模块 AGENTS.md，返工率暴降至 15%；
- **到第 12 周**：团队积累了 30 多条千锤百炼的疫苗和多个领域 Skill，**哪怕今天新入职一个完全不懂业务的校招应届生，在团队 Harness 底座的加持下，第一天就能写出符合资深首席架构师水准的高可靠代码！**

请大家品味这句结语：
**业务源码仅仅是系统当前状态的瞬间快照，而 `.specs`、`AGENTS.md` 和 `.rules`，才是整个研发团队十几年工程智慧与避坑经验的数字克隆体！**

## Key Q&A / Clarifications
**Q：如果规则越写越多，会不会过几个月之后又变成了前面讲的 3000 行巨型规则？**
A：不会，因为我们有前面第 15 页讲的**分层与按需触发机制（Scoped Rules）**！新增的规则并不是塞在全局根目录下，而是按照文件名后缀（Glob）或子模块目录精准沉淀的。同时，团队应在每个季度组织一次“规则大扫除（Rule Pruning）”：如果某条规则已经被 Spotless 插件或底层二方包内置逻辑从物理层面拦截了，就应当将其从 Markdown 规则中移除，保持规则库始终精炼敏捷。

**Q：有些老员工觉得写 Rule 很麻烦，如何激励大家主动贡献疫苗？**
A：可以将“工程免疫资产贡献（Rule/Skill Commit）”纳入技术团队的季度工程卓越（Engineering Excellence）度量指标。把过去单纯统计“写了多少行代码”，转变为统计“贡献了多少条被全员复用的 Rule、拦截了多少次潜在 Bug”。谁贡献的规则在 CI 中拦截次数最多，谁就代表了团队最高的技术沉淀水平。
