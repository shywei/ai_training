## Slide Objective
掌握使用只读 Subagent、阿里 Qoder Repo Wiki 或 Claude Code 对陌生存量多模块项目开展“三层逆向测绘”的标准工作流，输出模块依赖拓扑、端到端调用时序与“历史怪癖防坑清单（Gotchas）”，并将成果结构化固化至 `AGENTS.md`，化黑盒系统为白盒地图。

## Suggested Presentation
各位请设想一个场景：今天上午你刚入职一家新公司，或者刚转岗到一个核心老业务组。主管把一个包含十几个子模块、几十万行代码的 GitLab 仓库链接丢给你：“这周先把这个系统熟悉一下，下周改一个核心计价功能。”
过去，我们可能需要硬着头皮抓耳挠腮读两周源码，甚至连工程怎么本地启动都要踩三天坑。

现在，在 2026 年，接手陌生存量项目的第一步，我们直接指挥只读 Agent 开展**三层逆向测绘工作流**：

**第 1 层：Maven / Gradle 模块依赖拓扑扫描（Macro Topology）**
命令 Agent 解析根目录与各子模块的 `pom.xml`，自动提取模块间依赖关系与 Spring Bean 的跨层注入，输出清晰的 Mermaid 拓扑图。这一步的核心收益在于明确**“架构单向依赖红线”**——比如让团队所有人一眼看清：`order-service` 依赖 `core-service`，`core-service` 提供通用底层业务逻辑与工具基建，两者之间严禁反向或循环引用。

**第 2 层：核心业务入口与端到端调用链时序（Call Sequence）**
从前端 Controller、MQ 消费者或定时任务入口出发，让 Agent 追踪一条典型的核心链路。在我们的企业级演练靶场中，它会自动梳理出：用户请求首先进入 `OrderController` → 通过 `ValidationService` 开展前置校验与幂等检查 → 进入 `OrderEngine` 执行领域处理与库存预占 → 最终通过 `ResponseFormatter` 格式化并返回。整个链条上的所有核心类名、数据读写点被一览无余地标注出来。

**第 3 层：“历史怪癖与隐式坑点清单”（Gotchas & Traps —— 拆弹清单）**
这是最体现经验价值的一层！我们专门命令 Agent 去搜索代码中所有的 `TODO`、`FIXME`、`HACK`，以及包含特殊判断、字符串截断、转义处理的存量方法，把它整理为《绝对禁止随意删除的历史兼容清单》。
大家看示例中针对靶场提取的关键点：
1. `LegacyParser.extractJson`：存量文本解析中混杂着 `<think>` 标签过滤与转义字符判断，提取首个有效 JSON 对象的逻辑被下游多处调用隐式依赖，重构时绝对不能擅自改动边界输入行为！
2. `PiiMaskUtils.mask`：敏感数据脱敏逻辑中，手机号正则必须带有前后非数字边界断言，防止误伤 18 位身份证或 20 位订单流水号；缺失断言会导致部分长数字串被误拦截。

大家看屏幕左下方的**标准只读逆向测绘 Prompt**，这段提示词大家可以直接收藏复制：
启动只读 Subagent，严禁修改任何文件，要求从拓扑、调用链、历史怪癖三方面扫描，并最终将结论整理为根目录与各子模块的 `AGENTS.md`。

**一次测绘，全员受益！** 当这份文档生成并提交到 Git 仓库后，未来不仅新员工上手只需要 2 分钟，甚至后来的 Coding Agent 每次启动时，只需花 1 秒钟读完这份地图，就能瞬间拥有资深架构师的全局视野！

## Key Q&A / Clarifications
**Q：项目代码量极大（例如几百万行），模型单次上下文装不下，怎么进行全局测绘？**
A：绝不能一次性把所有代码直接往 Prompt 里塞。必须使用**自顶向下的分治扫描（Top-Down Chunked Exploration）**：
第一步：只让 Agent 读取 `pom.xml` / `build.gradle` 和目录树结构（仅占用 2000 Token），生成宏观拓扑；
第二步：针对筛选出的核心业务入口（如标注 `@RestController` 的类），通过只读 Subagent 并行追踪单个 Controller 的下游调用链；
第三步：利用全局正则检索（Grep）专门匹配 `FIXME|HACK|// fallback` 注释。这样即使是上百万行的工程，也能以极低的 Token 成本高效构建出精准地图。

**Q：测绘生成的 Mermaid 拓扑图放在哪里最合适？**
A：最佳实践是直接作为 Markdown 代码块放入根目录的 `AGENTS.md` 中。因为现代主流 Agent（如 Claude Code、Cursor、Antigravity）都能完美解析 Markdown 中的 Mermaid 语法，大模型可以直接在内部推理中将其还原为有向无环图（DAG），从而在后续生成新类时精准遵循包依赖规范。
