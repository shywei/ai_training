## Key Q&A / Clarifications
**Q：作为团队 Tech Lead，推动这套体系在团队内部落地，最容易遇到的阻力是什么？该如何破局？**
A：最常见的阻力通常是“习惯惯性”——部分工程师习惯了口语化提需求的随意性，或者觉得写 Spec 和配 Hook“多此一举”。破局的最佳策略是**“标杆样板打法”**：不要一开始搞全员大推，而是挑选团队内一个痛点最深的核心存量模块（比如计价模块或权限模块），由 1~2 名骨干带头落地分层 AGENTS.md 与特征测试重构。当大家亲眼看到一个过去没人敢碰的祖传老类在半小时内被安全重构、且后续需求交付提速 3 倍且零 Bug 时，事实将成为最强有力的推广利器。

**Q：完成 02 与 02B 课程后，下一步全员统一的学习目标是什么？**
A：无论是完成第 02 课直接推进的普通学员，还是修完 02B 进阶深潜的高级工程师与 Leader，下一步全员的标准统一主线都是进入《第 03 课：AI Agent架构认知入门》！在第 03 课中，我们将跳出单一代码辅助工具视角，全面建立智能体系统的宏观认知拓扑，为后续 04~08 课亲手编写企业级 Agent 奠定坚实的系统架构基础！

## 课后扩展学习引导（Post-Class Deep Dive Guide）
各位骨干与架构师，完成课堂演示之后，如果大家想在企业存量复杂工程中继续深化“规格驱动开发”与“AI 代码治理护栏”，请务必精读本课程根目录下的**《扩展学习指南.md》**！

这份指南严格遵循 3W 法则（Why-Where-What），精选了四大深水区主题，直击一线痛点：
1. **EARS 需求工程规范**：如何运用 5 大结构化句式彻底消灭口语化需求的二义性，并理性认知其消除自然语言歧义与数学级形式化验证（Formal Verification）的本质边界；
2. **ArchUnit 架构守护硬护栏**：摆脱依赖 Prompt 软提醒的低效防守，在 Java 单测中毫秒级硬性拦截“Controller 直调 Mapper”与跨层依赖腐化；
3. **Git Worktree 并发多智能体工作流与 CI 分支保护**：如何单机高效并发编排多个 CLI Agent 独立作业，并在 GitHub/GitLab 远端筑牢防御 `--no-verify` 本地绕过的不可越雷池；
4. **存量老系统特征测试（Golden Master）**：面对零单测的祖传老代码，如何利用特征测试锁定行为全貌，构筑不可动摇的安全网后再放手让 AI 重构。

指南最后还为大家设计了 3 道直击灵魂的架构思考题（附参考思路）。建议大家作为团队 Tech Lead，将其作为内部分享与技术评审的研讨材料，真正将课程价值转化为组织级工程复利！
