本项目为《课程设计总纲》第 09 课《从手搓到框架：框架的边界》**第 1 级阶梯对照工程**（Git Tag: `v6.0-springai2`）。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       全课程三套工程同屏对照架构体系                               │
└─────────────────────────────────────────────────────────────────────────────┘
  ① enterprise-ai-agent 【手搓原版】
     ├── 技术栈: Spring AI 1.0.0-M4 + Spring Boot 3.4.1 + Java 17
     ├── 端口: 8080 (永久冻结于 commit 0839d6b / v5.0-workflow)

  ② enterprise-ai-agent-springai2 【现代基础设施版（本项目）】
```

## 2. 运行环境与端口拓扑矩阵

本工程完全复用 `ai_training/enterprise-ai-agent` 既有的 Docker 中间件（MySQL / Redis / PostgreSQL+pgvector）和双 MCP Server（8081 / 8082），无需重复启动中间件容器。

| 组件 / 服务 | 监听端口 | 宿主技术栈 | 职责说明 |
|:---|:---:|:---|:---|
| **MySQL 8.0** | `3306` | Docker (`enterprise-ai-agent`) | 用户画像与商品结构化表 |
| **Redis 6+** | `6379` | Docker (`enterprise-ai-agent`) | 执行状态 Checkpoint 热缓存与会话记忆 |
| **PostgreSQL 14+ (pgvector)** | `5432` | Docker (`enterprise-ai-agent`) | 向量知识库 + `agent_execution_checkpoint` 表 |
| **mcp-product-server** | `8081` | Spring Boot 3.4.1 (Java 17) | 商品价格与库存 MCP 查询服务 |
| **mcp-knowledge-server**| `8082` | Spring Boot 3.4.1 (Java 17) | 政策手册与向量检索 MCP 服务 |
| **agent-runtime (手搓)** | `8080` | Spring AI 1.0-M4 (Java 17) | 手搓原版服务（可对照运行） |
| **springai2 (本项目)** | `8083` | **Spring AI 2.0.2 GA (Java 21)** | **现代基础设施对照服务** |
| **Vue Web UI** | `3000` | Node.js 16+ / Vue 2.7 | 统一前端界面 |

## 3. 快速启动四步法

### 步骤 1：启动公共 Docker 中间件与初始化 Checkpoint 表
在终端中进入原工程目录启动 Docker：
```bash
cd ai_training/enterprise-ai-agent
docker compose up -d
```

为 PostgreSQL 实例执行本工程专属的检查点快照表结构（位于 `docs/schema-checkpoint.sql`）：
```bash
# 登录 PostgreSQL 容器执行创建表
docker exec -i enterprise-ai-agent-postgres psql -U postgres -d knowledge_db < ../enterprise-ai-agent-springai2/docs/schema-checkpoint.sql
```

### 步骤 2：启动双 MCP Server（保持 8081 与 8082 运行）
```bash
# 窗口 1: 启动商品服务
cd ai_training/enterprise-ai-agent/mcp-product-server
mvn spring-boot:run

# 窗口 2: 启动知识服务
cd ai_training/enterprise-ai-agent/mcp-knowledge-server
mvn spring-boot:run
```

### 步骤 3：配置大模型密钥
在环境变量中配置 SiliconFlow（或 OpenAI 兼容）API Key：
```bash
# Windows PowerShell
$env:SILICONFLOW_API_KEY="sk-your-actual-key"

# Linux / macOS
export SILICONFLOW_API_KEY="sk-your-actual-key"
```

### 步骤 4：编译并启动本项目 (端口 8083)
```bash
cd ai_training/enterprise-ai-agent-springai2
mvn spring-boot:run
```
启动成功日志中将出现：
```
Started SpringAi2AgentApplication in X.XXX seconds (process running for X.XXX)
Tomcat started on port 8083 (http) with context path '/'
```

## 4. 关键功能实操验证命令清单

### ① 复杂导购多步对比任务（REST 同步）
验证 `ChatClient` 链式调用、`@Tool` 声明式工具和 Advisor 责任链：
```bash
curl -X POST "http://localhost:8083/api/v6/workflow" \
  -d "message=请帮我对比联想拯救者Y9000P和苹果MacBook Pro的价格、库存和质保政策&sessionId=sess-100&userId=U001"
```
**预期返回**：
```json
{
  "executionId": "exec-xxxx",
  "traceId": "trace-v6-xxxx",
  "checkpointId": "chk-3-xxxx",
  "status": "completed",
  "mode": "workflow",
  "stepCount": 3,
  "steps": [
    {"stepNumber": 1, "action": "调用 queryProductInfo 查询联想拯救者 Y9000P 规格与价格", "status": "completed"},
    {"stepNumber": 2, "action": "调用 queryProductInfo 查询 Apple MacBook Pro 16 规格与价格", "status": "completed"},
    {"stepNumber": 3, "action": "调用 searchKnowledge 检索退换货质保政策，基于预算场景输出综合对比分析", "status": "completed"}

  "message": "联想拯救者 Y9000P 价格为 ¥8999，库存 15 件；Apple MacBook Pro 16 价格为 ¥19999..."
```

### ② 实时流式响应与可观测遥测（SSE 流式）
验证 `TelemetryStreamAdvisor`（TTFT 监测与流式打点）：
```bash
curl -N "http://localhost:8083/api/v6/workflow/stream?message=我想买一台适合剪辑4K视频的电脑&sessionId=sess-101&userId=U001"
```

### ③ 人在回路（HITL）高额下单拦截与确认
发送超过 5000 元的高风险下单请求：
```bash
curl -X POST "http://localhost:8083/api/v6/workflow" \
  -d "message=帮我创建订单，购买一台联想拯救者Y9000P，金额8999元，地址为北京市海淀区中关村南大街1号&sessionId=sess-102&userId=U001"
```
**返回状态为挂起确认**：
```json
{
  "executionId": "exec-8888",
  "checkpointId": "chk-1-xxxx",
  "status": "confirming",
  "state": "CONFIRMING",
  "pendingConfirmation": {
    "warning": "检测到高额订单或敏感变更，金额超过 ¥5000.00，请人工核实确认"
  }
}
```
**用户人工批准继续执行**：
```bash
curl -X POST "http://localhost:8083/api/v6/workflow/confirm" \
  -d "executionId=exec-8888&checkpointId=chk-1-xxxx&confirmed=true"
```

### ④ 【深度深水区 1】断点复水恢复（Rehydration）
当服务重启或 Pod 漂移后，根据 `executionId` 和 `checkpointId` 恢复任务执行栈：
```bash
curl -X POST "http://localhost:8083/api/v6/workflow/rehydrate" \
  -d "executionId=exec-8888&checkpointId=chk-1-xxxx"
```

### ⑤ 【深度深水区 1】时光倒流与分支衍生（Time-Travel Forking）
从某一历史 Checkpoint 分叉独立执行树：
```bash
curl -X POST "http://localhost:8083/api/v6/workflow/fork" \
  -d "sourceExecutionId=exec-8888&checkpointId=chk-1-xxxx"
```

### ⑥ 查询执行链路因果 Checkpoint 历史
```bash
curl "http://localhost:8083/api/v6/workflow/checkpoints?executionId=exec-8888"
```
