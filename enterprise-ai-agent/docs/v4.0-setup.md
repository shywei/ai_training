# v4.0-tool 部署指南

## 依赖环境

| 组件 | 版本要求 | 用途 |
|------|----------|------|
| JDK | 17+ | Spring Boot 3.x 要求 |
| Maven | 3.8+ | 构建工具 |
| Redis | 6+ | Session Memory |
| MySQL | 8+ | 用户画像 + 商品结构化数据 |
| PostgreSQL | 14+ (pgvector) | 向量存储（知识库 + 用户记忆） |
| Node.js | 16+ | 前端构建 |

## 架构概览

```
agent-runtime (:8080)        MCP Client
    │
    ├── mcp-product-server (:8081)     商品查询（价格/库存）
    │       └── MySQL
    │
    └── mcp-knowledge-server (:8082)   知识检索 + 记忆 + 画像
            ├── PostgreSQL + pgvector（知识向量 + 记忆向量）
            └── MySQL（用户画像）
```

**agent-runtime 不直接访问 PostgreSQL**，所有向量操作通过 MCP 协议调用 mcp-knowledge-server。

## 2. 配置文件

### agent-runtime

编辑 `agent-runtime/src/main/resources/application.yml`：

```yaml
# SiliconFlow API Key
spring.ai.openai.api-key: YOUR_API_KEY

# Redis
spring.data.redis.host: localhost
spring.data.redis.port: 6379

# MySQL
spring.datasource.url: jdbc:mysql://localhost:3306/agent_db?...
spring.datasource.username: root
spring.datasource.password: root

# MCP Server 连接
mcp:
  product:
    server-url: http://localhost:8081
  knowledge:
    server-url: http://localhost:8082
```

### mcp-knowledge-server

编辑 `mcp-knowledge-server/src/main/resources/application.yml`：

```yaml
# PostgreSQL + pgvector
spring.datasource.url: jdbc:postgresql://localhost:5432/agent_db
spring.datasource.username: postgres
spring.datasource.password: postgres

# MySQL（用户画像）
mysql.datasource.url: jdbc:mysql://localhost:3306/agent_db?...
mysql.datasource.username: root
mysql.datasource.password: root

# SiliconFlow Embedding API
embedding:
  api-key: YOUR_API_KEY
```

## 3. 启动顺序

```bash
# 1. 启动 MCP Knowledge Server（端口 8082）
cd mcp-knowledge-server
mvn spring-boot:run
# 启动时自动索引商品知识库（首次约 10 秒）

# 2. 启动 MCP Product Server（端口 8081）
cd mcp-product-server
mvn spring-boot:run

# 3. 启动 Agent Runtime（端口 8080）
cd agent-runtime
./mvnw spring-boot:run

# 4. 启动前端
cd web
npm install && npm run dev
```

## 4. 知识库管理

### 自动索引

mcp-knowledge-server 启动时自动检查 vector_store，无数据则从 products.json 索引。

### 手动索引（前端）

打开前端 → 点击「加载商品知识」按钮 → 走 MCP 协议：

```
前端 → POST /api/agent/knowledge/index?force=true
     → McpKnowledgeClient.indexKnowledge(true)
     → MCP Tool: index_knowledge
     → mcp-knowledge-server 重建索引
```

### 手动索引（API）

```bash
curl -X POST "http://localhost:8080/api/agent/knowledge/index?force=true"
```

## 5. 演示流程

### 演示 1：LLM 路由（意图分类）

```
用户输入："推荐一台写代码的笔记本"
→ 后端日志：[Router] 用户意图: KNOWLEDGE

用户输入："ThinkPad X1 Carbon 多少钱"
→ 后端日志：[Router] 用户意图: TOOL

用户输入："你好"
→ 后端日志：[Router] 用户意图: CHAT
```

### 演示 2：Knowledge 路由（RAG 检索）

```
用户输入："推荐一台适合剪视频的笔记本"
→ 路由：KNOWLEDGE
→ MCP Tool: search_knowledge("推荐一台适合剪视频的笔记本")
→ 返回 MacBook Pro 14、华硕 ROG 等
→ LLM 基于检索结果推荐
```

### 演示 3：Tool 路由（MCP Function Calling）

```
用户输入："MacBook Pro 14 多少钱，有货吗"
→ 路由：TOOL
→ LLM 调用 mcp_queryProductInfo("NB002")
→ MCP Tool 返回：价格 14999 元，库存 89 件，在售
→ LLM 整合回复
```

### 演示 4：记忆保存（系统自动沉淀）

```
多轮对话后（超过10条消息），系统自动触发记忆沉淀：
→ MemoryManager.checkAndPrecipitate()
→ LLM 从对话中提取关键信息（对话摘要）
→ McpKnowledgeClient.saveMemory() → MCP → pgvector
→ Redis 清空，历史上下文由 pgvector 语义检索提供

清空会话后再次对话：
用户输入："推荐一台笔记本"
→ 路由：KNOWLEDGE
→ context 中包含：## 相关记忆（从 pgvector 语义检索）
→ LLM 基于记忆 + RAG 个性化推荐
```

### 演示 5：混合对话

```
用户："推荐一台游戏本"        → KNOWLEDGE → RAG 推荐
用户："拯救者多少钱"          → TOOL → 查价格
用户："和 MacBook 比呢"       → KNOWLEDGE → RAG 对比
用户："记住我更喜欢拯救者"    → CHAT → 会话结束时自动沉淀到记忆
```

## 6. MCP 能力清单

### mcp-knowledge-server（:8082）

| 类型 | 名称 | 说明 |
|------|------|------|
| Tool | search_knowledge | 商品知识语义检索（RAG） |
| Tool | search_memory | 用户记忆语义检索 |
| Tool | save_memory | 写入用户记忆（系统自动沉淀，不暴露给 LLM） |
| Tool | index_knowledge | 索引商品知识库（force 参数） |
| Resource | user://{userId} | 读取用户画像 |

### mcp-product-server（:8081）

| 类型 | 名称 | 说明 |
|------|------|------|
| Tool | queryProductInfo | 查价格 + 库存 + 状态（MySQL） |
| Tool | queryPrice | 只查价格（MySQL） |
| Tool | queryStock | 只查库存（MySQL） |

## 7. 常见问题

### Q: Tool 调用没有触发？
A: 检查后端日志，确认 `[Router]` 显示 `TOOL`。如果显示 `CHAT` 或 `KNOWLEDGE`，说明路由判断没有识别为 Tool 意图。尝试更明确地说"多少钱"、"有货吗"。

### Q: MCP Server 连接失败？
A: 检查 MCP Server 是否已启动。agent-runtime 日志会显示 `[MCP] 连接 MCP Server 失败`。Agent 仍可正常运行，只是 MCP Tool 不可用。

### Q: 知识库索引失败？
A: 检查 mcp-knowledge-server 日志，确认 PostgreSQL + pgvector 可用，schema-knowledge.sql 已执行。

### Q: 前端没有显示路由标签？
A: 确认前端是最新版本（v4.0-tool）。刷新页面清除缓存。
