# v3.0-knowledge 部署指南

## 前置依赖

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| JDK | 17+ | 与 v2.0 相同 |
| Maven | 3.8+ | 与 v2.0 相同 |
| MySQL | 8.0+ | 用户画像、用户表（与 v2.0 相同） |
| Redis | 6.0+ | Session Memory（与 v2.0 相同） |
| **PostgreSQL** | **15+** | **v3.0 新增**，用于知识库存储 |
| **pgvector** | **0.5+** | **v3.0 新增**，PostgreSQL 向量扩展 |

## 安装 PostgreSQL + pgvector（Windows）

### 方式一：PostgreSQL 安装包（推荐）

1. 下载 PostgreSQL 16：https://www.postgresql.org/download/windows/
2. 安装时记住密码（默认用户 `postgres`）
3. 安装完成后，启用 pgvector 扩展：

```sql
-- 方法A：如果安装包自带 pgvector
CREATE EXTENSION IF NOT EXISTS vector;

-- 方法B：手动安装 pgvector
-- 1. 下载 pgvector Windows 版：https://github.com/pgvector/pgvector/releases
-- 2. 解压到 PostgreSQL 的 lib 和 share/extension 目录
-- 3. 然后执行 CREATE EXTENSION
```

### 方式二：Docker（最简单）

```bash
docker run -d \
  --name pgvector \
  -e POSTGRES_PASSWORD=postgres \
  -p 5432:5432 \
  pgvector/pgvector:pg16
```

## 初始化数据库

```bash
# 1. 创建数据库（如果不存在）
psql -U postgres -c "CREATE DATABASE agent_db;"

# 2. 执行 pgvector 建表脚本
psql -U postgres -d agent_db -f docs/schema-knowledge.sql

# 3. 执行 MySQL 建表脚本（用户表 + 商品表）
mysql -u root -p agent_db < docs/schema.sql
```

注意：MySQL 和 PostgreSQL 是两个独立的数据库，分别存储不同类型的 数据：
- MySQL：用户、商品结构化信息（价格、库存）
- PostgreSQL + pgvector：向量数据（商品描述、用户记忆）

## 配置

在 `application.yml` 中配置 PostgreSQL 连接（v3.0 新增部分）：

```yaml
spring:
  datasource:
    pgvector:
      url: jdbc:postgresql://localhost:5432/agent_db
      username: postgres
      password: postgres
      driver-class-name: org.postgresql.Driver
```

也可以通过环境变量覆盖：
- `PG_HOST` — PostgreSQL 主机（默认 localhost）
- `PG_USER` — 用户名（默认 postgres）
- `PG_PASS` — 密码（默认 postgres）

## 数据分层架构

v3.0 的核心设计：商品数据按特性分层存储。

| 数据类型 | 存储 | 谁来查 | 课程 |
|---------|------|--------|------|
| 商品描述、亮点、适用场景、配置参数 | pgvector | 系统自动检索（RAG） | 第六课 |
| 价格、库存、销量、上架状态 | MySQL | LLM 通过 Tool 调用 | 第七课 |
| 用户画像 | MySQL | 结构化标签 | 第五课 |
| 用户记忆 | pgvector | 语义检索 | 第六课 |

v3.0 检索流程（只涉及知识检索）：
1. pgvector 语义检索 → 返回商品描述（名称、配置、亮点、适用场景）
2. 注入 Prompt → LLM 基于描述推荐商品

v4.0 增强（第七课）：
- LLM 识别到用户问价格/库存时，调用 Tool 查询 MySQL
- Tool 返回实时数据，LLM 整合后回复用户

## Embedding 模型

使用 SiliconFlow 免费的 BGE 模型生成向量：

```yaml
spring.ai.openai.embedding.options.model: BAAI/bge-large-zh-v1.5
```

- 模型：BAAI/bge-large-zh-v1.5
- 维度：1024
- 中文效果优秀，SiliconFlow 免费
- 需要 SiliconFlow API Key 支持 Embedding 接口

## 启动

```bash
cd agent-runtime
mvn spring-boot:run
```

启动后不会自动索引，需要手动触发。

## 索引知识库

```bash
# 1. 查看索引状态
curl http://localhost:8080/api/knowledge/status

# 2. 执行索引（首次）
curl -X POST http://localhost:8080/api/knowledge/index

# 3. 强制重新索引（清空后重写）
curl -X POST http://localhost:8080/api/knowledge/index?force=true
```

索引过程中会看到日志：
```
[Knowledge] 开始索引 12 个商品...
[Knowledge] [1/12] Embedding: ThinkPad X1 Carbon Gen12
[Knowledge] [2/12] Embedding: MacBook Pro 14 M3 Pro
...
[Knowledge] ✅ 索引完成，共 12 个商品，耗时 xxxms
```

如果索引失败，检查 PostgreSQL + pgvector 是否启动，schema-knowledge.sql 是否执行。

## 验证

### 1. 知识检索验证
1. 启动前端，登录
2. 输入"推荐一台写代码的笔记本"
3. 观察后端日志：
   - `[Knowledge] RAG 检索成功` — 说明向量检索正常
   - `llm-chat.log` 中 `[Memory Injection]` 应包含 `## 参考知识` 部分
4. Agent 应回复具体的商品推荐（引用配置、价格、亮点）
5. **验证数据分层**：回复中的价格应该来自 MySQL 实时查询，不是向量库

### 2. 记忆增强验证
1. 多轮对话后，说"记住我喜欢轻薄本"
2. 清空会话，重新登录
3. 输入"推荐一台笔记本"
4. 观察后端日志：
   - `[Memory] 语义检索到用户记忆` — 说明记忆向量检索正常
   - Agent 应回复中体现用户偏好
