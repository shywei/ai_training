# v5.0-workflow 部署指南

## 依赖环境

| 组件 | 版本要求 | 用途 |
|------|----------|------|
| JDK | 17+ | Spring Boot 3.x 要求 |
| Maven | 3.8+ | 构建工具 |
| Redis | 6+ | Session Memory |
| MySQL | 8+ | 用户画像 + 商品结构化数据 |
| PostgreSQL | 14+ (pgvector) | 向量存储（知识库 + 用户记忆） |
| Node.js | 16+ | 前端构建 |

**v5.0 无新增外部依赖**。Workflow 引擎是 agent-runtime 内部新增的组件，不引入新的中间件。

## 架构概览

```
agent-runtime (:8080)
    │
    ├── ShoppingAgentController    原有路径 /api/agent/chat（简单问题）
    │
    ├── WorkflowController         新增路径 /api/agent/workflow（复杂任务）
    │       └── AgentRuntime       ReAct 循环引擎
    │           ├── TaskPlanner    LLM 任务规划
    │           ├── ErrorRecovery  重试 + 熔断 + 降级
    │           ├── ConfirmationService  人在回路
    │           └── TraceService   执行追踪
    │
    ├── mcp-product-server (:8081)     商品查询
    │       └── MySQL
    │
    └── mcp-knowledge-server (:8082)   知识检索 + 记忆 + 画像
            ├── PostgreSQL + pgvector
            └── MySQL
```

**两条路径并存**：简单问题走 `/api/agent/chat`（原有，SSE 流式），复杂任务走 `/api/agent/workflow`（新增，JSON）。**前端统一调 `/api/agent/workflow`**，AgentRuntime 内部判断简单/复杂。`/api/agent/workflow/stream` 也支持 SSE 流式输出。两条路径共享 MCP Client、MemoryManager、PromptManager。

```yaml
agent:
  model:
    reasoning: Qwen/Qwen3-8B    # TaskPlanner 和 THINK 用
```

## 3. 启动顺序

```bash
# 1. 启动 MCP Knowledge Server（端口 8082）
cd mcp-knowledge-server && mvn spring-boot:run

# 2. 启动 MCP Product Server（端口 8081）
cd mcp-product-server && mvn spring-boot:run

# 3. 启动 Agent Runtime（端口 8080）
cd agent-runtime && ./mvnw spring-boot:run

# 4. 启动前端
cd web && npm install && npm run dev
```

## 4. 新增 API 端点

### 复杂任务入口

```bash
POST /api/agent/workflow?message=帮我对比拯救者和MacBook的价格&sessionId=default&userId=U001
```

返回：
```json
{
  "traceId": "trace-a1b2c3",
  "status": "completed",
  "message": "拯救者 ¥8999 更便宜...",
  "state": "COMPLETED"
}
```

如果需要确认：
```json
{
  "traceId": "trace-a1b2c3",
  "status": "confirming",
  "message": "⚠️ 操作确认...",
  "confirmRequired": true,
  "pendingTool": "place_order"
}
```

### 用户确认/取消

```bash
POST /api/agent/workflow/confirm?traceId=trace-a1b2c3&confirmed=true&sessionId=default&userId=U001&message=我要买拯救者
```

### 查询执行状态

```bash
GET /api/agent/workflow/status?traceId=trace-a1b2c3
```

### 查看执行链路

```bash
GET /api/agent/workflow/trace?traceId=trace-a1b2c3
```

### 查看所有 Trace

```bash
GET /api/agent/workflow/traces
```

### 熔断管理

```bash
GET  /api/agent/workflow/circuit-breaker       # 查看熔断状态
POST /api/agent/workflow/circuit-breaker/reset  # 重置熔断器
```

## 5. 演示流程

### 演示 1：多步对比查询

```
POST /api/agent/workflow
message: "帮我对比拯救者和 MacBook 的价格，预算 8000"

→ TaskPlanner 规划 3 步
→ Step 1: search_knowledge("拯救者") → ¥8999
→ Step 2: search_knowledge("MacBook") → ¥14999
→ Step 3: LLM 综合对比 → 推荐拯救者

查看 Trace:
GET /api/agent/workflow/trace?traceId=trace-xxx
→ 看到完整执行链路、每步耗时、LLM 思考过程
```

### 演示 2：容错降级

```
停止 mcp-knowledge-server，然后：
POST /api/agent/workflow
message: "查询华为 MateBook 价格"

→ 第 1 次调用 → 超时
→ 等待 1s → 第 2 次调用 → 超时
→ 等待 2s → 第 3 次调用 → 超时
→ 重试耗尽 → 降级：LLM 基于已有信息回答

或者：连续 5 次失败后熔断，60 秒内跳过该工具
```

### 演示 3：人在回路

```
POST /api/agent/workflow
message: "我要买拯救者"

→ LLM 判断需要下单
→ ConfirmationService 拦截
→ 返回：status: "confirming", confirmRequired: true

POST /api/agent/workflow/confirm
traceId=trace-xxx&confirmed=true

→ 用户确认 → 执行下单 → 返回结果
```

### 演示 4：查看熔断状态

```
GET /api/agent/workflow/circuit-breaker
→ 返回各工具的失败计数和熔断状态

POST /api/agent/workflow/circuit-breaker/reset
→ 重置所有熔断计数器
```

## 6. 前端集成

前端需要新增 Workflow 相关的 UI：

1. **复杂任务输入框**：调用 `/api/agent/workflow` 而非 `/api/agent/chat`
2. **确认弹窗**：当 `status: "confirming"` 时显示确认/取消按钮
3. **Trace 查看器**：展示执行链路（步骤列表、耗时、状态）

如果前端暂未适配，可以直接用 curl 或 Postman 调用 API 演示。

## 7. 常见问题

### Q: TaskPlanner 规划失败？
A: 检查日志中 `[TaskPlanner]` 输出。如果 LLM 返回非 JSON 格式，TaskPlanner 会降级为单步执行（不规划，直接走 ReAct 循环）。

### Q: 工具调用一直重试？
A: 检查 ErrorRecovery 日志。最多重试 3 次，指数退避 1s→2s→4s。如果 MCP Server 完全不可用，会触发熔断。

### Q: 确认请求没有返回？
A: 确认只在 LLM 判断需要调用高风险 Tool（如 place_order）时触发。如果 LLM 没有调用 Tool，不会触发确认。尝试更明确地说"下单""购买"。

### Q: Trace 查不到？
A: Trace 存在内存中，重启 agent-runtime 后丢失。用 `GET /api/agent/workflow/traces` 查看最近 50 条。

### Q: 熔断后怎么恢复？
A: 等待 60 秒自动恢复，或调用 `POST /api/agent/workflow/circuit-breaker/reset` 手动重置。
