CHAPTER 02 · 运行时引擎与上下文工程

企业级 Agent 架构核心公式与能力演进层级拆解

ENTERPRISE AGENT SYSTEM FORMULA · 企业级智能体黄金公式
Enterprise Agent = LLM 路由大脑 + 认知层 (Prompt + Memory + RAG) + 执行层 (Tool + MCP) + 运行时治理 (FSM + HITL + Trace)
五层系统能力层层筑基
系统级能力演进阶梯：从“单次 API 调用”到“生产级自主可控智能体系统”
阶梯 ① · 交互与指令 能力基石
大模型交互与 Prompt 工程
• 解决什么：让模型听懂业务规矩并稳定输出 JSON
• 核心组件：LlmRouter（快慢模型路由）、PromptManager、SSE 流式输出、JSON 自愈重试
此时局限：无记忆，会话结束即忘；无私域业务知识
阶梯 ② · 记忆机制 状态留存
Memory 三层记忆系统实现
• 解决什么：跨轮次、跨会话记住“人”（画像与历史）
• 核心组件：MemoryManager、Redis 短期窗口+摘要、MySQL user_profile、pgvector 语义记忆
此时局限：具备用户认知，但缺少企业私域知识库支撑
阶梯 ③ · 知识增强 专业壁垒
企业知识库与 RAG 检索
• 解决什么：让模型掌握企业内部“事”（商品参数/售后规则）
• 核心组件：文档切块、Embedding 向量化、PostgreSQL pgvector 混合检索 + Rerank 重排
此时局限：具备事实知识，但缺乏与实时业务系统的交互操作手脚
阶梯 ④ · 系统连接 业务执行
Tool Calling 与 MCP 协议
• 解决什么：连接外部微服务查实时价格库存、算优惠、建订单
• 核心组件：标准协议解耦（领域工具/知识服务）、函数调用（Function Calling）、工具鉴权与治理
此时局限：多步调用缺乏显式状态机约束，高危操作缺乏审批闭环
阶梯 ⑤ · 确定运行 生产闭环
Workflow 状态机与运行时治理
• 解决什么：多步可控编排、故障自愈与高危操作人工审批
• 核心组件：AgentRuntime FSM 状态机、TaskPlanner、ConfirmationService、TraceService
最终交付：可控、可审、可降级，具备工业级 SLA 的企业智能体！
高阶演进维度：从单智能体系统向 工业级编排框架 迁移，进阶至 Multi-Agent 多智能体协同，最终沉淀为 企业级 AI 基础设施中台。 下面进入 Chapter 03 逐一拆解五大组件 →
