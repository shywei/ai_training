## Slide Objective
深入辨析组件边界与存量系统融合的五大典型疑难（RAG vs Memory、微调 vs Agent、规则引擎共存等），提供清晰的设计决断准则。

## Suggested Presentation
请看第 20 页：组件边界与存量系统融合辨析（五问五答）。
在系统设计评审会上，工程师最常为这些边界争得面红耳赤：
1. **RAG vs Memory 到底有什么区别？**
   —— **RAG 是公域/客体知识（客观世界的事实、企业的产品与制度，所有用户共享）；Memory 是私域/主体记忆（特定用户的偏好、历史会话与个人属性）。** 存储介质和召回逻辑完全不同！
2. **有了 Agent，企业还需要做大模型微调（Fine-Tuning）吗？**
   —— **分工不同！** 微调解决的是“语言风格、特殊领域特定语法、结构化遵循能力”；而 Agent 解决的是“实时数据感知、系统工具调用与复杂流程编排”。企业落地永远是“微调打底模 + Agent 建系统”；
3. **已经有了成熟的规则引擎（如 Drools），怎么与 Agent 融合？**
   —— 让规则引擎成为 Agent 的一个【只读验证 Tool】！模型负责发散思考并起草方案，调用规则引擎校验合规性，驳回修改；
4. **Tool 调用失败时，系统该如何兜底？**
   —— 建立阶梯式容错：单次超时自动重试（带 Exponential Backoff）→ 重试失败降级为备用方案 → 无法恢复时向人类求助，切忌直接在循环中死扛；
5. **如何防止 Agent 在高并发下把下游业务微服务打垮？**
   —— 在 Tool 调用层必须强制配备令牌桶限流（Rate Limiting）、熔断保护与防重幂等设计！

## Key Q&A / Clarifications
**Q：可以在 Agent 内部直接写 SQL 操作线上数据库吗？**
A：生产绝对红线！严禁赋予 Agent 任意拼接执行原生 SQL 的工具，必须将数据访问封装为参数类型严格、权限受控、具有参数校验的专用 API。
