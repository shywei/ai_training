## Slide Objective
精讲认知层组件 ②：Memory 三层记忆体系，讲清短期窗口、画像与语义记忆的存储分层。

## Suggested Presentation
请看第 10 页：认知层组件 ② · Memory 三层记忆体系。
在企业应用中，用户绝不希望每次打开 APP 都像面对一个失忆的陌生人。
但如果把一年前的全部对话记录无限追加到 Prompt 里，不仅会导致 Token 账单爆炸，更会引发严重的“Lost in the Middle”上下文退化！
因此，在工业级参考架构中，必须构建一套**【冷热分层、各司其职的三层记忆体系】**：
1. **短期工作记忆（Working Memory）**：
   基于 **Redis** 存储。维护最近 8~10 条滑动窗口消息。响应极快（毫秒级），解决当前会话多轮指代与上下文承接；
2. **长期事实画像（Entity & User Profile）**：
   基于 **MySQL** 关系型数据库存储。通过后台异步管道（`@Async UserProfileExtractor`），定期从历史对话中提炼出用户的持久事实标签（如“偏好轻薄本、预算6000元、讨厌机械键盘”），以紧凑的 Key-Value 形式随 System Prompt 注入；
3. **情境语义记忆（Episodic Semantic Memory）**：
   基于 **PostgreSQL + pgvector**。将过往历史对话片段切块向量化存储，每次对话前按语义相关度做余弦相似度召回。
三层立体协同，兼具极致低成本与终身记忆能力！

## Key Q&A / Clarifications
**Q：三层记忆的数据一致性如何保障？**
A：短期窗口数据强一致读写；长期画像采用“异步提取 + 版本快照”机制，后台定时消费或在会话结束时触发抽取，既保障了主请求的超低延迟，又保证了画像的持续沉淀更新。
