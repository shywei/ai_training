需要强调的是，本课作为架构总纲，是纯理论与参考架构认知课，不包含任何 Demo 代码实操演练，我们完全用通用的业务案例举例讲解：
大家看整个架构被清晰地划分为四大分层协同体系：
- 最上层是【客户端交互层】：提供基于 SSE（Server-Sent Events）的实时流式打字机交互，支持思考过程可视化展示与人机确认卡片；
- 核心层是【核心智能体引擎宿主 (Agent Runtime)】：
  - 承载安全护栏（GuardrailsService）、提示词管理（PromptManager）、多模型动态路由（LlmRouter）；
  - 运行受控状态机引擎（FSM & TaskPlanner）、审批拦截（ConfirmationService）、容错自愈与全链路追踪（TraceService）；
- 服务层是【标准化工具微服务 (MCP)】：
  - **领域工具微服务 (Domain Tool Server)**：以标准协议暴露商品查询、详情与交易接口；
  - **知识检索微服务 (Knowledge Retrieval Server)**：负责向量混合检索、企业私域规范与长期记忆召回；
- 基础设施层是【三大存储底座与大模型集群】：
  - Redis 负责短期工作记忆窗口与会话摘要；MySQL 负责确定性业务数据与结构化用户画像；PostgreSQL + pgvector 负责私域知识与长期语义记忆向量存储。
整套架构层次严密、职责单一，是工业界构建大型高可用智能体系统的事实参考标准！

## Key Q&A / Clarifications
**Q：为什么把领域工具和知识检索拆分为独立的微服务，而不是全部写在 Agent Runtime 内部？**
A：为了实现【系统解耦与独立伸缩】！在企业生产环境中，商品服务由电商业务团队维护，知识库检索由数据团队维护。通过标准化的协议（如 MCP）解耦，Agent Runtime 只需要作为标准客户端接入，业务微服务可以独立迭代、独立鉴权扩容，避免单体大杂烩。
