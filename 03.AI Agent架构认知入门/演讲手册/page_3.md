## Slide Objective
深刻剖析从裸 LLM 到 Agent 系统的必然性，建立“大模型是认知推理核心，Agent 是由上下文、记忆、工具与运行时构成的完整应用系统”的基石认知。

## Suggested Presentation
请看第 3 页：为什么只有大模型不够？—— 从裸 LLM 到企业级 Agent 系统。
在第 01 课中，我们已经论证了大模型的四大天生缺陷：概率幻觉、知识截止、无状态失忆与无执行手脚。
如果你只做一个裸 LLM 调用：用户发一句话，后端直接透传给大模型，大模型吐出一串文本直接返回给前端。这种架构在企业真实生产中会瞬间暴露出三大致命死穴：
1. **输入维度**：裸模型只能被动接收用户输入的几个词，它不知道当前用户是谁、过去的购买偏好是什么（无记忆），也查不到企业最新的商品库存与售后政策（无知识）；
2. **处理维度**：裸模型是一锤子买卖（One-shot），无法像人类工程师一样进行多步任务规划、无法面对执行错误自主纠错反思；
3. **输出维度**：裸模型只能输出无害的自然语言字符串，它无法直接调用支付网关扣款、无法修改数据库、无法给库管发通知。

**这就是为什么我们必须构建 Agent 系统！**
大模型只是这台系统的【认知与决策引擎（Cognitive & Decision Engine）】；而 Agent 系统则是围绕它搭建的动态上下文工程、长期记忆（Memory）、私域知识库（RAG）、传感器与执行机械手（Tools），以及强有力的运行时控制状态机！

## Key Q&A / Clarifications
**Q：传统微服务系统 + 大模型 API，算不算是 Agent？**
A：如果你的微服务只是硬编码调一次 LLM 总结文本，那叫“AI-Enhanced App”；只有当系统能够让模型根据环境反馈**自主决定调用哪些工具、何时循环重试、何时达成目标**，并在确定性工程机制下运行时，才属于真正的 Agent 范式。
