## Slide Objective
传授架构师能力裁剪五问决策树，掌握根据业务风险、数据动态性与确定性要求进行技术选型的系统方法。

## Suggested Presentation
请看第 17 页：架构师能力裁剪决策树——拿到业务需求后按顺序问这“五问”。
很多架构师最容易犯的错误就是“拿着锤子找钉子”，不管什么需求都堆全套组件，导致系统复杂度过高崩溃。
请牢记这五问决策法，逐层加减模块：
- **第一问【任务需要动态调取外部未公开事实吗？】**：
  如果需要查最新商品、内部制度 → **引入 RAG 模块**；纯创意写作则无需 RAG。
- **第二问【任务需要跨多个会话记住用户偏好与状态吗？】**：
  如果需要跨天推荐、记住用户忌口与历史偏好 → **引入三层 Memory 体系**；一次性翻译工具直接无状态。
- **第三问【任务需要真正读写外部生产数据库、发邮件或调三方接口吗？】**：
  需要操作真实系统 → **引入 Tool Calling 与 MCP 协议**，并配套沙箱审批；只看不改则无需写工具。
- **第四问【核心路径包含强合规、审批流或绝对不可逆的资金操作吗？】**：
  一旦出错会引发法律或资损风险 → **强制引入 Workflow 状态机与 Human-in-the-loop 人工兜底**；普通头脑风暴可用 Autonomous Agent。
- **第五问【任务过于复杂，单个 Agent 会由于工具过多导致注意力漂移吗？】**：
  单 Agent 工具超过 10 个或流程超过 5 步 → **拆解为 Multi-Agent 多智能体协同**！
按需裁剪，如无必要，勿增实体！

## Key Q&A / Clarifications
**Q：一个内部员工 IT 报销政策答疑助手，需要用状态机和 MCP 吗？**
A：如果只是答疑政策条款，只需 Model + RAG 即可，连 Tool 都不需要！过度增加状态机只会增加系统维护成本。
