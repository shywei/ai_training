CHAPTER 01 · 范式边界：BUILDING EFFECTIVE AGENTS (ANTHROPIC 经典谱系)

架构第一分水岭：Workflows（确定性编排）vs Autonomous Agents（自主智能体）

① Workflows（工作流编排）：代码控制流（Code-Driven Control Flow） 路径预定义 · 可预测 · 易测试
LLM 和工具按照开发者预先写死的代码分支/图拓扑执行，包含 Anthropic 总结的 5 种标准设计模式：
1. Prompt Chaining（提示词串行链） Step 1 → Gate 校验 → Step 2 → Step 3
将任务拆成固定线性步骤，中间可插入代码断言（Gate）。例：先生成商品文案 → 代码校验违禁词 → 再翻译多语言。
2. Routing（意图路由分流） Classifier → 分发至专用分支/模型
入口先用轻量模型分类意图，再路由给不同 Prompt 或流程。例：闲聊走 Fast 模型、退换货走售后流程、导购走推荐流程。
3. Parallelization（并行化：Sectioning / Voting） 并发执行 → Aggregator 聚合
子任务切片并发或多次采样投票。例：业务回答生成与安全合规审查（Guardrails）并行调用，大幅降低首字延迟。
4. Orchestrator-Workers（主从动态拆解） 中央 Orchestrator 拆解 → Workers 并发 → 汇总
子任务数量无法提前写死，由主模型根据输入动态拆解派发给多个专职 Worker，最后由 Synthesizer 合并结果。
5. Evaluator-Optimizer（评估-优化循环） Generator 生成 ⇄ Evaluator 评审打回
一个模型生成方案，另一个评估器（代码或模型）按评分标准打回修改，直到达标或达到最大迭代次数。
② Autonomous Agents：模型控制流 Model-Driven Loop
不预设固定步骤，由模型根据每一步的环境反馈（Observation）自主决定下一步调什么工具、循环多少轮、何时终止：
while (!taskDone && step < MAX_STEPS) {
  action = llm.decideNextAction(context, tools);
  observation = executeTool(action); // 真实环境反馈
  context.append(action, observation);
}
✓ 适用场景：开放式问题、步骤数不可预知（如全栈 Coding、复杂跨品类导购探索）
⚠ 生产风险：死循环烧光 Token、乱调高危接口、延迟与成本成倍放大
企业级最佳实践：用“状态机 Workflow”关住“自主 Agent”的笼子
在生产环境中，我们既不用纯写死的传统规则，也不放任无边际的裸 ReAct 循环，而是采用受控自主架构（Bounded Autonomy）：
• 宏观骨架用 Workflow 状态机（FSM）：INIT → PLANNING → EXECUTING → WAITING_CONFIRM → COMPLETED，严格卡住最大步数（如 maxSteps=5）与状态合法迁移；
• 微观节点内用 Autonomous Loop：在 EXECUTING 态内允许模型自主选工具、查 RAG；一旦触发下单/扣款等高危操作，状态机强制切入 WAITING_CONFIRM 等待人工审批！
