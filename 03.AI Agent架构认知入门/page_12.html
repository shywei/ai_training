CHAPTER 03 · 认知层与执行层组件拆解 · 工具调用 (TOOL CALLING)

执行层组件 ① · Tool Calling 原理与三大协议垂直分层定位

纠偏三大协议混淆：MCP、A2A 与 AG-UI 属于不同维度的垂直架构分层，并非同级替代关系。
Tool Calling 第一性原理（意图与执行分离）： 大模型自己绝不会直接发 HTTP 请求或连数据库！它只负责输出结构化意图（如 tool_calls: [{name: "get_product", arguments: {"id": 101}}]），由 Agent 运行时宿主拦截并执行后，将结果喂回模型上下文。
① 下行层 · MCP 协议 Agent ➔ Tools / Data
工具与上下文互操作标准（Anthropic 主导）
• 垂直定位：向下连接确定性外部工具、数据资源与环境上下文。
• 核心原语：Tools（可执行接口）、Resources（只读数据源）、Prompts（标准提示词）。
• 解决问题：解耦 N 个模型宿主与 M 个企业系统的集成复杂度，从 O(N×M) 降为 O(N+M)。
角色比喻：给 Agent 配备各种规格标准化的“精密扳手与探针”。
② 横向层 · A2A 协议 Agent ➔ Agent
智能体间分布式协作标准（Linux 基金会托管）
• 垂直定位：横向连接跨组织、跨微服务、具备自主决策力的不同智能体。
• 核心原语：Agent Card（能力名片发现）、Task（长任务生命周期与状态机）、Artifact（交付工件）。
• 解决问题：实现跨业务系统多智能体协商，而不是简单当作从属工具调用。
角色比喻：智能体之间平等对话、协同推进任务的“职业队友”。
③ 上行层 · AG-UI 协议 Agent ➔ Frontend UI
人机流式交互事件标准（前端界面协议）
• 垂直定位：向上连接人类工程师与前端 Web/App 界面。
• 核心原语：流式正文 TEXT_CHUNK、思考流 THINKING_STEP、工具执行卡片 TOOL_STATUS 与人工确认弹窗 HITL_CARD。
• 解决问题：标准化多模态富交互界面，告别单调文本打字机。
角色比喻：智能体向人类汇报工作与索取授权的“可视化大屏看板”。
企业级 Tool / MCP 生产治理五道防线（绝不能裸奔上线）：
1. 读写分级鉴权
查询只读放行；改价/建单等写操作严格校验调用方权限。
2. 幂等性保障 (Idempotency)
带全局 requestId，防止模型超时重试导致重复扣款。
3. 熔断降级与超时
下游微服务卡死时秒级 Fallback，防 Agent 阻塞耗尽线程池。
4. 参数防注入校验
对模型生成的入参做严格正则表达式与类型断言校验。
