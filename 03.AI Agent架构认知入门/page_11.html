CHAPTER 03 · 认知层与执行层组件拆解 · 知识检索 (RAG)

认知层组件 ③ · Knowledge 企业知识库与生产级 RAG

形态 A：半结构化商品/FAQ 条目型知识库 导购推荐主场景
• 数据特点：天然以单件 SKU 或单条问答为单位（含商品卖点、适用人群、材质说明 + 品类/价格带 Metadata）。
• 切块策略：一物一块（Entity-Level Chunking），将结构化属性与描述拼成语义完整的文本块向量化，严禁把同一个商品拦腰截断！
形态 B：非结构化长文档知识库（PDF / Word / Wiki） 售后保修/合规手册
• 数据特点：几十页的《三包退换货政策》《户外装备保养指南》，含章节标题、表格与跨段逻辑。
• 切块策略：Markdown 标题层级切分 + 滑动窗口 Overlap（10%~15% 重叠），并在每个 Chunk 头部注入父标题面包屑路径。
企业级 RAG 双阶段流水线（基于 PostgreSQL `pgvector`）
【离线构建流水线 Indexing Pipeline】文档变更时异步触发：
1. ETL 解析清洗
提取正文/表格，剔除页眉页脚乱码
→
2. 语义分块 & 元数据
绑定 category / brand / doc_id
→
3. Embedding 向量化
转化为 1024/1536 维稠密浮点向量
→
4. 存入 pgvector
HNSW 向量索引 + JSONB 元数据索引
【在线检索增强流水线 Retrieval & Generation Pipeline】用户提问时毫秒级执行：
1. Query 改写与扩展
结合对话历史补全指代词，提取过滤条件
→
2. Hybrid 混合召回 (Top-20)
向量语义检索（懂同义词）+ 关键词/元数据过滤（准锁型号SKU）
→
3. Rerank 交叉精排 (Top-5)
Cross-Encoder 深度重打分，剔除噪音块
→
4. 注入 Context 有据生成
要求模型严格基于检索块回答并附来源
架构师铁律：RAG 解决的是“相对静态的知识文档与商品特征”；像“每秒变化的库存余量、秒杀实时价”绝不能放进向量库，必须走下一页的 Tool/MCP 查 MySQL！
