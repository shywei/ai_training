CHAPTER 02 · 运行时引擎与上下文工程

Agent 运行时是怎么“思考与行动”的？—— 三大核心认知循环

① ReAct 循环 Reason + Act
边想边做、走一步看一步：每次推理只决定当前下一步动作，拿到工具真实返回（Observation）后再决定是否继续。
1. Thought（推理思考）
“用户想买2000元内降噪耳机，我需要先搜商品库，再查用户的会员折扣。”
2. Action（发起工具调用）
输出 search_products(category="耳机", maxPrice=2000)
3. Observation（观察环境反馈）
MCP Server 返回 3 款耳机 JSON 数据，追加回 messages 进入下一轮 Thought。
工程特性：Tool Calling 多轮工具调用循环的核心机制；优点是灵活快速，缺点是长链路下容易偏离全局目标。
② Plan-and-Execute 先全局规划 · 再分步执行
谋定而后动：面对多步骤复杂任务，先由 Planner 生成完整步骤清单（DAG/Step List），再交由 Executor 逐项推进。
1. Planner（全局任务拆解）
生成显式计划：[Step1: 查用户尺码画像, Step2: 检索冲锋衣知识库, Step3: 查实时库存价格, Step4: 组装对比表]
2. Step Executor（分步受控执行）
按序执行每个子步骤（内部可用轻量模型或单步 ReAct），状态清晰可追踪。
3. Replanner（动态重规划）
若 Step3 发现某款缺货，Replanner 动态修正后续步骤，替换为同档次备选款。
工程特性：适用于长程复杂任务；通过规划（Plan）与执行（Execute）解耦，降低单步上下文负载，支持子步失败重规划。
③ Reflection 自我反思 Verify + Self-Correction
先验校验与错题重做：绝不盲目信任模型的第一次输出，通过确定性校验器或 Critic 模型捕获错误并闭环修正。
1. Draft Generation（初次生成）
模型生成 JSON 结构化导购推荐或工具调用参数。
2. Critic / Validator（校验拦截）
发现 JSON 反序列化失败、必填字段缺失，或推荐价格超出用户预算红线。
3. Self-Correction（带错重试）
将精确报错信息（Exception / Critic 意见）拼回上下文，让模型自我修复后输出。
工程特性：适用于结构化输出校验、代码自愈重试与业务合规性审查，大幅降低幻觉与接口调用错误率。
生产级组合拳：宏观任务用 Plan-and-Execute 排步骤 → 单步执行用 ReAct 调工具 → 输出与异常用 Reflection 兜底校验。 三大循环的本质：不断更新 Context 并再次调用 LLM →
