CHAPTER 01 · 范式边界：什么是真正的 AGENT

为什么只有大模型不够？—— 从裸 LLM 到企业级 Agent 系统

裸大模型（Stateless LLM API） 只有“缸中之脑”
每次 HTTP 调用都是无状态函数 Text_Out = f(Text_In)，在企业落地时面临四大硬伤：
❶ 无状态失忆（No Memory）
关掉窗口或换个 Session 就忘记用户尺码、过敏源与历史偏好，无法提供连续服务。
❷ 私域知识盲区与幻觉（No Private Knowledge）
不知道企业内部退换货新规、今日促销价与非公开商品手册，只能靠猜（产生严重幻觉）。
❸ 有嘴无手，无法改变外部世界（No Action / Tools）
只能生成“建议您去查库存”，不能真正查询 MySQL 实时库存、创建订单或发起退款。
❹ 缺乏多步状态控制与安全护栏（No Runtime Governance）
无法保证复杂任务的执行顺序、报错重试、高危动作人工确认（HITL）及全链路审计。
结论：单次调用 LLM 只是“文本生成器”，无法直接交付企业级业务结果。
企业级 Agent 系统完整形态（System Architecture） 大脑 + 记忆 + 知识 + 手脚 + 护栏
🧠 核心推理大脑（LLM Router：Fast Model 意图路由 + Reasoning Model 深度规划）
负责意图理解、任务拆解、工具选择与最终回复生成（本身不存状态、不直接连数据库）
📘 认知层（Cognitive Layer）— 让大脑“想得准”
• Prompt 工程与指令体系：定义角色边界、JSON Schema 约束与 Few-shot 示范
• Memory 记忆机制：记“人”——工作记忆滑动窗口 + 用户画像 + 长期语义记忆
• Knowledge / RAG 知识增强：记“事”——检索企业私域领域知识库与规范政策，消除幻觉
⚡ 执行层（Execution Layer）— 让系统“办成事”
• Tool Calling 工具调用：模型输出结构化调用意图，宿主执行真实业务 API
• MCP 标准化协议：解耦 Agent 引擎与外部领域微服务（商品/知识/订单服务）
• Workflow 状态机编排：控制多步循环、重试降级与人工确认（HITL）
🛡️ 运行时治理底座（Governance & Observability）— 让生产“敢上线”
• Guardrails 安全护栏：防 Prompt 注入、PII 脱敏
• ErrorRecovery 三级容错：工具重试、熔断与兜底
• Trace & Evals：全链路耗时/Token 追踪与评测
架构师第一定律：不要试图通过“换个更大的模型”解决系统架构问题——缺记忆补 Memory，缺私域数据补 RAG，缺执行补 MCP Tool，缺可控性补状态机。
