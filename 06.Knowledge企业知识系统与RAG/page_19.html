四个关键架构设计决策
数据分层
商品描述 → pgvector（语义检索）| 价格库存 → MySQL（第七课 Tool）| 会话 → Redis（缓冲）
设计原因：价格库存实时变化，放向量库会存旧值误导用户；按读写模式分层：静态描述给 RAG“懂”，实时库存走 Tool“查”。
手动索引触发（KnowledgeController）
显式调用 POST /api/knowledge/index 触发 KnowledgeService.indexProducts()
设计原因：如果启动即全量自动重建，每次重启都烧 Embedding Token 且流水线黑盒不可见；手动 API 触发让 Data Pipeline 每一步清晰可观测。
自动沉淀（checkAndPrecipitate）
Redis 会话达到阈值自动提要并通过 UserMemoryService 向量化沉淀至 pgvector user_memory
结论与过程记忆不重叠
MySQL user_profile 存结构化画像（结论）| pgvector user_memory 存对话语义片段（过程）
