④ Self / Corrective RAG
质量门 + 自纠
做法：检索结果先过相关性质量门：不合格 → 改写重查 → 仍不合格 → 拒答或兜底。
适用：金融、合规、医疗等高严密问答。
高可靠场景必选
前沿范式 — 各解决一类难题，按场景选型
GraphRAG
思路：抽取实体-关系知识图谱 + 社区摘要，沿图多跳检索。
适用：跨文档多跳推理、全局归纳（“这批合同的共性风险”）。
RAPTOR
思路：自底向上递归聚类摘要成树（叶=原文块、根=全局摘要）。
适用：超长年报、制度汇编，兼顾局部细节与跨章节全局问题。
Multimodal RAG
思路：文本 + 表格（Docling/MinerU）+ 架构图/截图（VLM）统一索引。
适用：带复杂图表的产品手册、财报、工单排障。
Agentic RAG ★2026 主线
思路：LLM 从“答案生成器”升级为“检索决策者”：Plan → Search → Read → Reason 多轮自主检索。
适用：复杂开放任务——查几次、换什么词、够不够，由 Agent 自主循环决定。
Deep Research
思路：多源多轮自主搜索 + 交叉验证 + 综合长报告生成。
适用：行业调研、竞品尽调、深度研报生成。
v1.3 架构落点（agent-runtime 单体直连 MySQL + pgvector）： 商品知识检索由 RetrievalService.java（基于 VectorStoreConfig 的 PgVectorStore）负责；用户语义记忆由 UserMemoryService.java + UserMemoryMapper.java（操作 pgvector user_memory 表，配合 MySQL UserProfileMapper）负责；两者在 MemoryManager.buildContext() 中汇合。（注：到了第七课 v4.0，我们再将知识与记忆服务抽取为独立的 MCP Server。）
