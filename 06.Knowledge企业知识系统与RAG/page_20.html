❌ 生产级知识管道还要补什么 — 六项三格（问题 / 不解决 / 2026 生产方案）
✗ 1 复杂文档版面感知解析（淘汰传统 Tika 裸抽）｜问题：Demo 只读 products.json（KnowledgeService），传统 Apache Tika 抽 PDF 会打碎表格行列与多栏结构。
不解决：PDF 保修手册、复杂跨页参数表、扫描件合同进不了库，或表格错行导致严重幻觉。
怎么办：升级为 2026 版面感知解析（MinerU / IBM Docling）+ VLM 原生解析（Qwen-VL / OlmOCR），保留标题树并将跨页表格转为结构化 Markdown/HTML（表格摘要向量化 + 原表回传）。
✗ 2 高阶分块（Parent-Child + Contextual Retrieval）｜问题：Demo 一商品一 chunk；长文档若按固定字数裸切会切断语义并丢失主语指代。
不解决：LLM 拿没头没尾的半句话生成，编造率居高不下。
怎么办：Markdown 章节切父块（1000字）+ 子块（200字）建索引（Parent-Child），配合 Contextual Retrieval 注入 50 字文档背景前缀。
✗ 3 Hybrid Search（BM25 + 向量 RRF 融合）｜问题：RetrievalService 仅走单路 PgVectorStore 余弦检索，对型号/SKU（如“NB001”）不敏感。
不解决：用户搜精确型号时召回失败，核心导购场景失灵。
怎么办：pgvector 稠密检索 + PostgreSQL 全文检索（tsvector / BM25）双路召回，经 RRF（倒数排名融合）合并。
✗ 4 Rerank 精排（Cross-Encoder）｜问题：双编码器余弦分数只是粗排，Top-K 直接截断会把排第 4~6 的最佳文档丢掉。
不解决：注入次相关文档，回答跑偏。
怎么办：双路召回 Top-20 后接 bge-reranker-v2-m3 / Qwen3-Reranker 精排取 Top-3~5（+30~100ms 延迟）。
✗ 5 RAG Evaluation 与 CI 门禁｜问题：调阈值、换模型靠人工试问，无量化基线。
不解决：改一处坏十处，线上静默退化。
怎么办：建黄金评测集，每次变更跑 Recall@K / Precision@K / Faithfulness 回归门禁（见 page_17）。
✗ 6 语义缓存、多租户权限隔离与防间接注入｜问题：高频问题重复检索生成；vector_store 无部门级 ACL 过滤。
不解决：Token 成本高；跨部门知识越权泄露。
怎么办：Redis 语义缓存（TTL）+ metadata tenant_id/dept_id 检索层预过滤 + <retrieved_context> 标签隔离。
