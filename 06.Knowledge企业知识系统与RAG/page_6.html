CHAPTER 02

企业知识全景 — 知识从哪来

知识来源不只是文档
数据库（结构化）
商品表、FAQ 表、知识库表
CRM、ERP、API 接口
本课 Demo 用这个
文档（非结构化）
PDF、Word、Excel
Wiki、Confluence、客服记录
生产中常见的挑战
知识的"文档"不一定是文件
RAG 管道的输入是文本内容，不管这文本是从 PDF 解析出来的，还是从 MySQL 字段拼接出来的。
商品导购场景：MySQL product 表 → 提取描述字段 → Embedding → 向量存储
多种知识怎么管理？
共享一张表 + metadata 过滤（推荐）
商品、FAQ、报告都存同一张 vector_store 表
metadata 加 type 字段区分，查询时按类型过滤
一次检索可跨类型搜索
商品导购的知识流
MySQL product 表（数据源）
  ↓ 提取描述字段
products.json（Demo 用 JSON 模拟）
  ↓ Embedding
vector_store 表（向量索引）
  ↓ 语义检索
商品 ID → 回 MySQL 查实时价格库存（第七课 Tool）
Demo：26 个商品，4 个品类
笔记本(12)、手机(6)、耳机(4)、平板(4)
每个商品：名称、品牌、配置、亮点、适用场景
一个商品 = 一个 Chunk，天然分块
JSON 天然有结构边界，分块最简单
注意：商品的价格和库存不放知识库——这些是实时数据，放 MySQL，第七课 Tool 调用查询。
