Prompt + RAG 集成 — 检索结果怎么用

不是把检索结果塞进去就行
检索结果需要格式化后注入 Prompt。
LLM 需要知道"这是参考知识，请基于它回答"。
否则 LLM 可能忽略检索结果，自己编造。
RAG 结果注入 Prompt 的格式
## 参考知识（从商品库检索）

## 用户问题
推荐一台写代码的笔记本
System Prompt 加入知识使用规则
"请优先参考以下知识回答，不确定时说不知道"
"推荐商品时引用具体的配置、亮点来说明理由"
"不要编造不存在的商品名称和配置"
不加这个规则，LLM 会忽略检索结果自己编造。
🚨 Token 预算与溢出截断
企业级 context 拼接包含四路信息，容易超出模型的最大 Context Window。Demo 为了简化没有进行长度裁切；生产环境中，必须在 Java 端进行 Token 预算限制与基于优先级（知识 > 画像 > 历史）的截断机制，防止调用超限。
💻 Demo：MemoryManager.buildContext()
public String buildContext(String sessionId,
    String userId, String userMessage) {
  StringBuilder sb = new StringBuilder();

  // ① 用户画像（MySQL — 始终查询）
  UserProfile profile = profileMapper.selectOne(...);
  if (profile != null)
    sb.append(profile.toContextString());

  // ② 相关记忆（pgvector — 始终查询）
  String mem = memoryService.search(
    userId, userMessage);
  if (mem != null)
    sb.append("## 相关记忆\n").append(mem);

  // ③ 对话历史（Redis — 沉淀后为空）
  // ④ 参考知识（pgvector — 关键词过滤后）
  String rag = retrievalService.retrieve(
    userMessage);
  if (rag != null)
    sb.append("## 参考知识\n").append(rag);

  return sb.toString();
}
