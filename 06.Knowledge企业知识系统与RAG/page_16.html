CHAPTER 05 · 生产优化

企业优化 — 生产环境必须做的四件事

⚡ 1 · Cache 语义缓存（性价比最高）
痛点：高频相似问题（如“推荐轻薄本”）反复重复检索与生成，白烧 Token 与延迟。
方案：Redis 缓存高频问题 Embedding 向量与回答，相似度 > 0.92 直接秒级命中返回。
落地优先级：第 1 个做（改动最小、见效最快，延迟从 3s 降至 30ms）
🔍 2 · 真正的 Hybrid Search（稠密+稀疏+RRF）
痛点：纯向量检索对型号（ThinkPad X1）、SKU、错误码极不敏感。
标准范式：pgvector 稠密向量 + PostgreSQL tsvector BM25 双路召回 $\to$ RRF 融合。
P0 澄清：元数据过滤（WHERE 约束）不是混合检索！必须是双路打分与 RRF 融合。
落地优先级：第 2 个做（彻底解决型号搜不准硬伤）
🔄 3 · Query Rewrite 与多查询扩展（解决口语不对齐）
痛点：用户口语表达模糊、含代词指代（“那个商务本”）或多意图，直接检索严重失准。
方案：快模型消解指代补齐实体、Multi-Query 并发扩展 3 个子查询、HyDE 假设性文档检索。
落地优先级：第 3 个做（多轮与复杂表达场景首选，召回率提升 30%+；Rerank 已在 P12/P15 落地）
📈 4 · RAG Evaluation 量化评测（度量衡闭环）
痛点：调切块大小、换 Embedding、调阈值全凭个人主观感觉，改动是否导致退化无人知晓。
方案：建立黄金评测集，自动跑通检索标准指标（Recall/MRR）与 Ragas 端到端诊断指标。
落地优先级：第 4 个做（但基线测试集越早建越好，保障调优不退化）
生产落地路径：Cache 降成本延时 $\to$ 真正 Hybrid Search 保型号 $\to$ Query Rewrite 拓召回 $\to$ Evaluation 护航回归。
