★ 高阶必选 1：Parent-Child Retrieval（父子文档索引 / Small-to-Big）
机制：将长文档切为父块（Parent，1000~2000字完整章节）与子块（Child，200字细粒度句群）；仅对子块做 Embedding 建索引（高精度命中），命中后通过 parent_id 把完整父块回传给 LLM，兼顾检索精度与上下文完整度。
★ 高阶必选 2：Anthropic Contextual Retrieval（上下文背景前缀注入）
痛点：长文档切片后变成“该型号支持 7 天无理由”，主语指代丢失导致无法召回。
做法：入库前用轻量模型（结合 Prompt Caching）为每个切片生成 50 字文档背景前缀（如“[背景：本文出自联想 ThinkPad 2026 退换货政策第3章]”）拼在切片头部再做 Embedding + BM25，检索失败率直降 67%。

for (Section parent : parents) {
  parentRepo.save(parent.getId(), parent.getText()); // 存1000字父块
  for (String child : tokenSplitter.split(parent.getText(), 200)) {
    // 2. Contextual Retrieval：注入 50 字文档与章节背景前缀
    String ctxPrefix = "[文档:" + docTitle + " | 章节:"
        + parent.getHeaderPath() + "] ";
    Map<String, Object> meta = Map.of(
        "type", "policy", "parent_id", parent.getId());
    vectorStore.add(List.of(new Document(ctxPrefix + child, meta)));
  }
