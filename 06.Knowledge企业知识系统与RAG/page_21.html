第五课（v2.0）的局限
长期记忆只存了 MySQL 结构化画像（user_profile）。
“喜欢轻薄本”是高度浓缩的结论标签，丢失了原始对话中的具体背景与细节（如“平时还做视频剪辑，希望显卡强一些”）。

第六课（v1.3）的增强：双层长期记忆
历史对话经提要与 Embedding 后存入 pgvector user_memory 表（UserMemoryService + UserMemoryMapper）。
当用户问“给我推荐几款电脑”时，按语义相似度精准召回历史对话细节！
同一个 pgvector，商品知识（vector_store）和用户记忆（user_memory）分表共用。

💻 v1.3 代码：UserMemoryService.java & UserMemoryMapper.java
// UserMemoryService.java — agent-runtime 直接读写 pgvector user_memory 表
public void saveMemory(String userId, String content, String type) {
  float[] embedding = embeddingModel.embed(content);
  userMemoryMapper.insertMemory(userId, content, type, embedding);
}

public String search(String userId, String query) {
  float[] queryVec = embeddingModel.embed(query);
  // 按 userId 过滤 + pgvector 余弦相似度检索 Top-3 记忆片段
  List<UserMemory> memories =
      userMemoryMapper.searchSimilar(userId, queryVec, 0.3, 3);
  return formatMemories(memories);
}
数据分层全景：各司其职
• pgvector（语义理解层）：vector_store（商品描述）+ user_memory（用户历史对话片段）
• MySQL（精确事实层）：product_info（实时价格库存）+ user_profile（结构化画像结论）
• Redis（高速缓冲层）：当前会话近期消息，满阈值经 checkAndPrecipitate() 沉淀至 pgvector
演进说明：在 v1.3 中，UserMemoryService 在 agent-runtime 内直连 PG；在第七课 v4.0 中将进一步抽取到 MCP Server 背后。
