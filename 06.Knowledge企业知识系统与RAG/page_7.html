CHAPTER 02 · 知识全景

企业多元数据接入矩阵 — 向量数据库绝非万能银弹

⚠️ 架构核心原则：向量数据库绝非万能银弹（Vector DB is NOT a Silver Bullet）！
切忌将企业所有数据盲目做 Embedding 塞进向量库！必须根据数据类型与查询特征，选择最优访问路径。
① 结构化数据 (Structured Data) 精确计算与聚合
数据形态：业务订单表、商品属性规格库、ERP/CRM 表格、经营财务事实表。
避坑红线：严禁将表格直接切块向量化！向量检索无法计算求和、过滤求极值。
特征优势：高一致性、确定性查询与精确统计。
🎯 最优访问路径：Text-to-SQL / 语义层 / 结构化函数调用
② 非结构化数据 (Unstructured Data) 长文档与语义问答
数据形态：企业规章制度、操作手册、售后政策、长篇 PDF 研报、客服 FAQ 问答。
核心挑战：版面解析保留层级表格，避免切块断章取义。
特征优势：自然语言泛化匹配、长文本语义理解。
🎯 最优访问路径：企业 RAG 管道（稠密向量 + BM25 混合检索）
③ 关系图谱数据 (Relational Graph Data) 多跳关联与推理
数据形态：复杂供应链网络、股权穿透关系、组织架构、跨文档因果推理链条。
核心痛点：普通 RAG“只见切片不见全局”，多跳推理容易在上下文断裂。
特征优势：全局拓扑洞察、实体关系路径追踪。
🎯 访问路径：图数据库检索（Cypher/SPARQL）或 GraphRAG（多跳拓扑路线之一）
④ 实时动态数据 (Real-time Dynamic Data) 秒级实效与状态
数据形态：实时库存、即时外汇价格、实时物流轨迹、第三方天气/航班状态。
避坑红线：实时数据绝不可写入向量库！时效性极高，重算 Embedding 成本高昂。
特征优势：秒级更新、即时精准。
🎯 最优访问路径：外部业务 API / MCP 工具调用 (Tool Calling)
Demo 读写分层架构：静态商品评测描述进 pgvector（供 RAG 语义理解）；动态库存与实时价格放 MySQL（供第七课 Tool 实时查询）。
静态知识归 RAG · 实时状态归 Tool
