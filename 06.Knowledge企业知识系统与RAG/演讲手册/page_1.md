## Slide Objective
开场定调：从"记住用户"进入"让 Agent 懂商品"。

## Suggested Presentation
上节课让导购 Agent 记住了用户，但它还是个"文盲"——用户问"有什么推荐的笔记本"，它答不上来。因为它根本不知道公司卖什么。

今天的主题是 Knowledge——企业知识系统。课程名称不叫"RAG"，叫"Knowledge"。RAG 只是实现方式，Knowledge 是能力本质。

这节课结束后，导购 Agent 能查商品信息了。但它还不能查库存、不能下单——它只能"说"，不能"做"。"做"是下节课 Tool 的事。

## Key Emphasis
不要一上来就讲 RAG 技术栈。先建立认知：企业 AI 应用必须有知识系统，Prompt 装不下企业知识，Fine-tuning 不划算。

## Optional Extension
**学员问：知识系统是不是就是把公司文档都塞进向量库？**
答：先拆两问——"什么算知识"和"知识给谁用"。
Demo 做法：26 个商品的 `products.json` 走完整链路（加载 → 分块 → Embedding → 检索 → 注入），看清机制只需要这一条最小闭环。
生产做法：先做知识盘点（文档、数据库表、API、工单都算知识），按域划分、定更新责任人和权限边界，再谈向量化——向量库只是存储件。取舍：跳过盘点直接入库，三个月后知识库就是没人维护的垃圾场。

## Classroom Interaction
开场先让学员问 Agent 一句"推荐一台写代码的笔记本"，看它答不上来或瞎编；课后再问同一句，对比知识系统上线前后的差别——开场这一下比任何定义都直观。

## Take Away
上知识系统前先回答三件事：知识从哪来、更新谁负责、答错了怎么发现——答不全就先别买向量库。

## Why This Slide Matters
跳过这页，学员会把 Knowledge 理解成"接个向量库"，立项时只买组件不建治理，上线后知识没人更新、答错没人发现。
