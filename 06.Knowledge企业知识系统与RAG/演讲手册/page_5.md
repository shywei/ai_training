## Slide Objective
建立 RAG 的整体认知——先查资料，再回答问题。讲清楚 RAG 的本质、优势、和 Memory 的区别，以及为什么 RAG 是企业 AI 应用的首选方案。

## Suggested Presentation
RAG = Retrieval-Augmented Generation，检索增强生成。名字很唬人，其实就是"先查资料，再回答问题"。

看中间的流程图：用户提问 → 检索（从知识库找相关商品）→ 组装 Prompt（用户问题 + 检索结果）→ LLM 生成（基于检索结果回答）。

本质是什么？不是改模型，是改输入。把企业知识塞进 Prompt 里，让 LLM "看到"后再回答。知识库在外部，不在模型里。这个设计的好处是：知识和模型解耦——换模型不影响知识，更新知识不需要换模型。

看右边的三个优势框。

知识更新 = 更新文档，不需要重新训练。商品上新了，把新商品的描述加到知识库，分钟级生效。Fine-tuning 要重新训练，天级生效。

数据不出企业，安全可控。知识库在企业内部，不需要把数据交给模型厂商。这对金融、医疗、政务等行业尤其重要。

成本低，只付 API 调用费。不需要 GPU 集群训练，不需要维护模型版本。知识库用 pgvector，数据库本身就有。

和 Memory 的区别很重要。Memory 记"人"——这个用户的偏好、历史、画像。Knowledge 记"事"——商品信息、企业文档、FAQ。两者互补，不可替代。用户问"根据我的偏好推荐笔记本"，需要 Memory（偏好）+ Knowledge（产品信息）配合。

看底部的问题链：RAG 的思路清楚了，接下来的问题是——知识怎么进来？怎么存？怎么查？怎么用？这四个问题就是本课后面四章的内容。

## Key Emphasis
RAG 不是一个产品，是一套工程方案。后面每个章节都在拆解这个工程链路。学员应该理解"RAG 的本质是改输入，不是改模型"——这个认知很重要，决定了后续所有技术选型的方向。
