## Slide Objective
总结全课，展示进度图和能力地图，让学员带走结构化的认知，并给出可执行的课后练习。

## Suggested Presentation
今天的一句话：Knowledge 不是文档，而是经过治理后能够被 AI 使用的企业知识。

这句话的关键是"治理"。文档只是原材料，经过解析、分块、向量化、索引、检索，才变成 AI 能用的知识。这个过程就是 Data Pipeline。

看左边的进度图。导购 Agent 的五大能力，今天完成了第三个——Knowledge。Prompt、Memory、Knowledge 三个绿色的勾，代表导购 Agent 现在能理解用户意图、能记住用户偏好、能查商品信息。三个能力叠加，导购 Agent 从"陌生人"变成了"懂商品的老朋友"。

看右边的能力地图。我们走了一条完整的链路：从 Knowledge 和 Memory 的区别开始（为什么需要 RAG），理解 Fine-tuning 的问题（为什么不划算），建立 RAG 的整体认知（先查资料再回答）。然后进入工程细节：企业知识全景（知识从哪来）、Data Pipeline + Chunking（知识怎么处理）、Embedding（知识怎么向量化）、pgvector（知识存在哪）、语义检索（知识怎么查）、关键词过滤（什么时候该查）。最后把 RAG 结果注入 context，做了数据分层和记忆体系升级。

底部是阶段成果。导购 Agent 能查商品信息了。但它不能查库存、不能下单——它只能"说"，不能"做"。下节课 Tool Calling 解决"做"的问题。

课后练习建议，每个对应一个核心知识点：

第一，启动 Demo，执行 `POST /api/knowledge/index` 索引商品数据，看后端日志里的 Embedding 过程。每条商品都会被逐条处理，这是理解 Data Pipeline 的最直接方式。

第二，问 Agent "推荐一台写代码的笔记本"，看 `logs/llm-chat.log` 里的 `[Memory Injection]`。应该能看到四个部分：用户画像、相关记忆、对话历史、参考知识。验证 RAG 检索有没有生效。

第三，问 Agent "你好"，再看日志。参考知识应该没有出现——因为关键词过滤把不相关的问题跳过了。这是理解"不是所有问题都需要检索"。

第四，聊几轮后说"记住我喜欢轻薄本"，退出再登录，问"推荐笔记本"。看日志里有没有"相关记忆"——验证自动沉淀和语义检索有没有工作。

第五，读一遍 `RetrievalService.java` 的 `retrieve()` 方法和 `MemoryManager.java` 的 `buildContext()` 方法。这是本课最核心的两个方法，理解了它们就理解了整个 RAG 流程。

## Key Emphasis
进度图让学员知道"走到哪了"，能力地图让学员知道"这课学了什么结构"。课后练习要具体、可执行——每个练习对应一个核心知识点。学员学完这课后应该达到：理解 RAG 完整链路、能做向量数据库选型、能看懂 Demo 代码、知道 Demo 和生产的差距、知道从哪里开始补工程细节。
