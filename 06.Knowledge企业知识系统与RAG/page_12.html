CHAPTER 03

关键词过滤 — 什么时候该检索

问题：不是所有消息都需要检索
用户说"你好" → 不需要检索商品知识
用户说"推荐笔记本" → 需要检索
用户说"今天天气怎么样" → 不需要检索

每次都检索 = 浪费 token + 注入无关信息干扰 LLM
Demo 方案：关键词匹配
包含"推荐/买/笔记本/手机/耳机"等关键词 → 检索
不包含 → 跳过检索

优点：简单、零延迟、不消耗 token
缺点：关键词列表需要人工维护，语义理解有限
进阶方案：LLM 路由（第七课预告）
用快模型先判断用户意图：需要检索？还是普通对话？
优点：能理解语义（"帮我优化代码"不含关键词但需要检索）
缺点：每次路由多一次 LLM 调用
💻 Demo 代码：isProductRelated()
// 关键词列表
private static final String[] PRODUCT_KEYWORDS = {
  "推荐", "买", "什么", "哪个",
  "笔记本", "手机", "耳机", "平板",
  "价格", "多少钱", "预算",
  "联想", "苹果", "华为", "小米",
  "游戏", "办公", "开发", "轻薄"
};

// 匹配任一关键词就检索
private boolean isProductRelated(String q) {
  if (q == null) return false;
  String lower = q.toLowerCase();
  for (String kw : PRODUCT_KEYWORDS) {
    if (lower.contains(kw.toLowerCase()))
      return true;
  }
  return false;
}
检索策略总结
Demo：关键词匹配（简单、够用）
生产：LLM 路由（语义理解、动态判断）
进阶：意图分类模型（快、准、不消耗 LLM）
