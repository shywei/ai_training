# 第 02 页：课程目录

## Slide Objective
向学员展示第 09 课 24 页的清晰推进脉络，按“破题定界 ➔ 同构效率提升（V5→V6→V7） ➔ 企业级增量环节补齐 ➔ 框架边界与防套牢 ➔ 选型与总结”逐层展开。

## Suggested Presentation
各位同学，请看今天这节课的 8 个章节脉络：

- **01 破题定界**：先把两条截然不同的演进主线立住，介绍 8080 / 8083 / 8084 三套同屏对照工程各自的使命。
- **02 & 03 同构效率提升**：严格只看“与 V5 做同样功能”的框架替换——先看 Spring AI 2.0（V6）如何接管 Prompt 装配、虚拟线程与可观测底座、`@Tool` 与 `ToolCallingAdvisor`、内置 MCP Client 与 `Advisor` 切面；再剖析 V6 的天花板（仍需手搓 300 行状态循环），从而引出 AgentScope `ReActAgent`（V7）接管主循环，完成 `V5 → V6 → V7` 的效率对照收口。
- **04 ~ 06 企业级增量环节**：进入手搓极难做好的深水区，依次攻克 Execution Checkpointer 断点复水与分支、认知生命周期 Middleware（重点看 `onActing` 挂起 HITL）、多通道 `streamEvents` 实时事件流，以及 Tool 强契约与 Schema Repair 自愈循环。
- **07 & 08 框架边界、防套牢与选型总结**：看清反射死穴、业务风控主权和三层记忆边界，落地六边形 Ports & Adapters 零侵入平替，最后收敛到选型决策树与全课总结。

## Key Emphasis
1. 目录保持简洁干净，逻辑上严格按“同构提效 ➔ 企业级增量 ➔ 边界与防套牢”三段递进。
2. 强调每一个概念都会从“什么问题”讲到“框架哪一块、怎么调用”。

## Optional Extension
### Q1: 为什么把“同构替换”和“企业级增量”拆成两个独立部分讲？
**讲师解析**：如果混在一起讲，学员很容易误以为“用上框架后连业务风控和架构设计也自动升级了”。拆开后就能看清：换掉 `PromptManager` 和 `@Tool` 只是写法升级；而 `Checkpointer`、工具执行前挂起、`streamEvents` 多通道流才是企业生产刚需的能力补齐。

## Classroom Interaction
引导学员快速扫视目录，确认哪一部分是自己当前项目最迫切想解决的痛点（代码胶水太重 / 状态易丢 / 无法中途审批 / 怕被框架绑死）。

## Take Away
沿着“先看懂同构提效，再补齐企业级能力，最后守住框架边界”的路线推进全课。

## Why This Slide Matters
让学员在脑海中先建好清晰的路线图，后续每一页都知道自己处于主线的哪个位置。
