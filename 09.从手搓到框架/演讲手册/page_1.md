# 第 01 页：从手搓到框架：框架的边界（封面与导读）

## Slide Objective
确立第 09 课的核心教学主轴：引导学员把“**同构功能换框架写更省事（5.1 开发效率提升）**”与“**手搓做不好、企业级必须靠框架补齐的能力（5.2 运行时机制补齐）**”严格区分开，同时守住**领域边界与防套牢架构**。

## Suggested Presentation
各位同学、架构师同行，欢迎来到第 09 课《从手搓到框架：框架的边界》。

在前五课（04~08 课）中，我们从零手搓了一套完整可运行的企业导购 Agent 原型（V5，`enterprise-ai-agent`），覆盖了 Prompt 组装、三层记忆、RAG 知识检索、MCP 工具调用以及状态机容错。通过亲手造轮子，大家已经看清了智能体底层的每一颗齿轮。

但回到真实企业研发中，很多团队一引入 **Spring AI 2.0** 或 **AgentScope 2.0** 就容易掉进两个误区：要么把框架当成“万能黑盒”，把风控和业务规则也一股脑交给大模型和框架注解；要么分不清**哪些是换了个更简洁的 API（架构没变）**，**哪些是手搓根本扛不住的企业级深水区能力**。

今天这节课，我们就用一套非常严谨的脉络把这件事讲透：
1. **第一部分（同构提效 V5 ➔ V6 ➔ V7）**：做的是和 V5 完全一样的导购功能，架构设计没有变，变的只是用 Spring AI 2.0 和 AgentScope 2.0 替换手搓胶水；
2. **第二部分（企业级增量环节）**：聚焦 4 个在 V5 里极难手搓做好、但企业级 Agent 必须具备的环节——**Checkpointer 断点复水与分支、认知生命周期 Middleware、多通道类型化事件流、Tool 强契约与自愈循环**；
3. **第三部分（框架的边界与防套牢）**：讲清哪些死穴和业务主权框架管不了，以及如何用**六边形架构（Ports & Adapters）**实现框架可插拔平替。

## Key Emphasis
1. **双主轴思维**：自始至终分清“开发效率提升”与“企业级新能力补齐”。
2. **五步讲透每个概念**：遇到什么问题 ➔ 引入什么概念 ➔ 底层原理 ➔ 如何解决问题 ➔ 对应框架哪一块与怎么调用。
3. **诚实划定边界**：明确标注“Demo 已覆盖”与“仅 PPT 讲解”的知识点。

## Optional Extension
### Q1: 学了 V5 手搓再学框架，手搓的代码是不是白写了？
**讲师解析**：恰恰相反。只有手搓过 `PromptManager`、`McpToolCallback` 和 651 行的 `AgentRuntime`，你才能一眼看出 `ChatClient`、`ToolCallingAdvisor` 和 `ReActAgent` 替你省掉了哪几层胶水；也只有手搓过内存态 `ConcurrentHashMap`，你才能瞬间听懂为什么生产环境需要 `Checkpointer` 和跨进程复水。

## Classroom Interaction
“大家平时在项目里引入新框架时，最容易遇到什么困惑？是不知道它底层帮你做了什么，还是升级版本时发现业务代码被绑死了？”

## Take Away
手搓理解原理，框架解放双手；先分清效率提升与企业级能力增量，再谈框架选型与防套牢。

## Why This Slide Matters
为整堂课定下清晰的问题意识和逻辑框架，避免后面陷入零散 API 的堆砌。
