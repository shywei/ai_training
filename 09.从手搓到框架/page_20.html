框架不会替你做的两件核心大事：风控规则主权 & 企业三层记忆

1. 业务规则主权：绝不交给 Prompt 猜 Demo 已覆盖
如果把“满 ¥5000 须审批”写在 System Prompt 里让模型自己判断，一旦遭遇提示词注入或幻觉就会直接资损！资金阈值、限购配额、选品加权算法必须由纯 Java 领域服务确定性执行：
// ShoppingDomainService.java（V6 与 V7 完全共用） public static final BigDecimal HIGH_RISK_AMOUNT_THRESHOLD = new BigDecimal("5000.00"); public boolean isHighRiskAction(String toolName, ToolOrderRequest req) { if ("createOrder".equalsIgnoreCase(toolName)) { if (req == null) return true; // 参数缺失默认按高风险拦截 if (req.getTotalAmount().compareTo(HIGH_RISK_AMOUNT_THRESHOLD) >= 0) return true; if (req.getQuantity() > 3) return true; } return toolName.contains("refund") || toolName.contains("delete"); }
✅ 结论：框架管运行调度，开发者永远掌握业务判断的最终一票否决权。
2. 边界辨析：StateStore ≠ 企业三层记忆 Harness 为仅 PPT 讲解
AgentScope HarnessAgent 宿主四大支柱：Workspace（工作目录）、Memory（短期窗口）、Sandbox（隔离代码执行）、StateStore（运行状态持久化）——它解决的是智能体运行时的宿主容器问题。
L1 短期会话与运行断点 (Redis)：消息栈与挂起快照 ✅ 框架接管
L2 结构化用户画像 (MySQL)：尺码/品牌偏好/消费力 ❌ 须自建
L3 长期知识与权限穿透 (pgvector)：跨会话记忆与 ACL ❌ 须定制
⚠️ 破除误区：挂了 StateStore 绝不等于替代了第 05 课的画像抽取与第 06 课的企业知识库！
