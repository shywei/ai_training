PART 2 · 企业级增量（二）：认知全生命周期拦截 Middleware

为什么 Spring AI Advisor 拦不住“工具执行前审批挂起”？

问题痛点：高危操作（如订单 ≥ ¥5000）必须在“模型决定调 createOrder、但工具尚未扣款执行”的那一瞬间暂停并存快照；V5 靠关键词硬匹配且内存阻塞，而 Spring AI Advisor 根本看不见智能体内部的轮次与工具动作！
Spring AI Advisor 的拦截视角 单次 HTTP 通信边界
ChatClientRequest ➔ [Advisors] ➔ ChatModel
ChatClientResponse ◄─ [Advisors] ◄─ ChatModel
三大盲区：
1. 只看得到单次模型请求，不知道当前处于 ReAct 第几轮；
2. ToolCallingAdvisor 默认闭环一口气跑完工具；
3. 想在调工具前挂起并释放 HTTP 线程，只能抛异常硬中断循环并手写恢复逻辑。
适用边界：只适合 PII 脱敏、注入检查、Token 计量等单次请求级切面。
概念与原理：AgentScope MiddlewareBase 5 个认知生命周期钩子
1. onAgent：任务入站与收官钩子（全局审计、耗时统计）
2. onSystemPrompt：动态注入/增强系统安全提示词
3. onModelCall：底层模型网络请求钩子（对应 Advisor 能力）
4. onReasoning：模型思考规划前/后拦截，监控思维链
5. onActing（核心！）：工具执行前精准拦截（风控挂起 + 结合 Flux .onErrorResume() 做异常自愈）
✅ 解决方式：把钩子嵌入认知循环内部，不用改业务工具即可在调工具前无损暂停！
