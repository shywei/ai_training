PART 1 · 同构能力提效（V5 ➔ V6 · 工具声明与单步闭环） ✅ Demo 已覆盖（SpringAi2ToolAdapter）

消灭正则硬提取：@Tool 声明式契约 + ToolCallingAdvisor 自动闭环

1. @Tool + @ToolParam：反射自动生成原生 Function Schema
V5 问题：Prompt 约定文本格式 + 手写 80 行 McpToolCallback 拼 Schema。
V6 原理：扫描 Java 方法签名与注解，自动生成 JSON Schema 走大模型原生 tools 字段。
2. ToolCallingAdvisor：内置接管工具调用递归闭环
V5 问题：AgentRuntime 手写 95 行脆弱正则 TOOL_CALL:(...)，多一个换行即崩溃。
V6 原理：ChatClient 默认挂载 ToolCallingAdvisor，自动反序列化参数、反射执行并回填模型。
V5 手搓正则（95行，格式微变即失效）
// AgentRuntime.java：大模型多打空格或全角括号直接失配！ Pattern p = Pattern.compile("TOOL_CALL:(\\w+)\\((.*?)\\)"); Matcher m = p.matcher(thinking);
V6 声明式定义：SpringAi2ToolAdapter.java + defaultTools
@Tool(name = "queryProductInfo", description = "查询商品的详细规格信息。传入商品ID（如 NB001）") public Map<String, Object> queryProductInfo( @ToolParam(description = "商品ID，格式如 NB001") String productId) { return mockProductCatalog.get(productId.trim().toUpperCase()); } // 挂载方式：ChatClient.builder(chatModel).defaultTools(toolAdapter).build()
✅ 开发提效：工具注册代码减少 75%，正则解析胶水直接清零。
ToolCallingAdvisor 幕后是如何自动闭环的？
Step 1：ChatClient 默认启用内置 ToolCallingAdvisor，随请求附上 tools JSON Schema
Step 2：模型返回 chatResponse.hasToolCalls() == true 时自动拦截响应
Step 3：调用 ToolCallingManager 反序列化入参 ➔ 反射执行 @Tool ➔ 包装 ToolResponseMessage 回填模型继续推理
// 架构师须知：若需手动接管循环，可显式关闭内置自动执行（仅PPT讲解） ChatOptions opts = ToolCallingChatOptions.builder() .internalToolExecutionEnabled(false).build(); ChatResponse resp = chatClient.prompt(prompt).options(opts).call().chatResponse();
⚠️ 注意边界：ToolCallingAdvisor 在单次请求内一口气跑完所有工具，不支持中途挂起审批！
