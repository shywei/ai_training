Checkpointer 核心原理：快照模型、热冷双轨与混合捕获策略

1. 纯数据快照模型：AgentCheckpoint.java
public class AgentCheckpoint implements Serializable { private String executionId; // 单次任务全局链路 ID private String checkpointId; // 当前快照版本号 private String parentCheckpointId; // 父快照指针（构建 DAG 版本树） private WorkflowState state; // PLANNING / EXECUTING / CONFIRMING private int stepCursor; // 当前执行游标 private Map<String, Object> scratchpad; // 工具中间结果（物理隔离不污染Prompt） private Map<String, Object> stateDelta; // 增量差分键 private Map<String, Object> pendingConfirmation; // HITL 挂起审批明细 }
2. 捕获策略权衡（Full Snapshot vs State Delta）
• Full Snapshot：读 O(1) 极快，但长链路每步写全量导致存储膨胀。
• State Delta：写 O(Δ) 极轻，但恢复时需沿 parentCheckpointId 回放合并。
• 混合策略：关键跃迁点（如 CONFIRMING）落全量快照，中间步记增量。
⚠️ 序列化铁律：快照内严禁放入 HttpClient、DB 连接或线程对象，只存纯数据 DTO。
