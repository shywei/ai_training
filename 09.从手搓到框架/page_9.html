⚠️ 痛点复现：如果每个业务团队都在 Spring AI 上手写这套循环，就会长出五花八门的“自制简陋版状态机”。
为什么 Spring AI 2.0 不提供这些？
架构类比：Spring AI = Servlet API
Servlet API 标准化了 HTTP Request/Response 与 Filter 链，但它不是工作流引擎。同理，Spring AI 标准化了 ChatClient、@Tool 与 Advisor，刻意保持轻量无状态。
Spring AI 2.0 留给上层的四块空白：
  • 多轮 ReAct 状态机与动态迭代收敛
  • 任务执行现场（CallStack/游标）持久化快照
  • 工具执行前细粒度钩子与无损审批挂起
  • 多通道（思考/工具/正文/审批）结构化事件流
