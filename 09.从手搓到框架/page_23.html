PART 3 · 生态全景坐标与架构师选型决策

2026 企业 AI 技术栈三层坐标与精准选型决策指南

L3 · 低代码平台层（Dify / Coze / 百炼） 类比：可视化 BPM
适合运营快速搭 FAQ 问答或 POC 验证；难以深度嵌入微服务核心事务与内网复杂鉴权。
L2 · 智能体运行时层（AgentScope 2.0 / Embabel / LangGraph） 类比：Spring MVC
接管 ReActAgent 多步循环、五阶段 Middleware 钩子、多通道事件流与 StateStore 状态快照。
L1 · 模型通信底座层（Spring AI 2.0 / LangChain4j） 类比：JDBC / Servlet
统一厂商协议，提供 ChatClient、@Tool、内置 MCP 与单次 Advisor 链，轻量标准、无多步状态机。
为什么不选 Spring AI Alibaba 2.0？ 目前仍处于 Milestone 预发布阶段，生产稳定性与通用 Harness 能力不如已发布稳定 GA 的 AgentScope Java 2.0.0。
🎯 业务需求选型决断树：你的项目该用谁？
✅ 选 L1（Spring AI 2.0）就足够：
  • 单轮/少轮问答、摘要、结构化提取
  • 标准企业 RAG（检索 ➔ 拼 Prompt ➔ 输出）
  • 传统 Java 代码主控流程，仅在某一步调 1~2 个只读工具
🚀 必须引入 L2（AgentScope 2.0）：
  • 动态多步 ReAct 规划（按工具结果决定下一步）
  • 高危工具执行前拦截风控与 HITL 无损挂起审批
  • 跨进程断点复水（Rehydration）与思考/工具/正文多通道流式 UI
选型第一原则：优先选用 GA 稳定版，并用六边形架构将选型隔离在 adapter/ 内，留好退路。
