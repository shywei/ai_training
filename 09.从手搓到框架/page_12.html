PART 2 · 企业级 Agent 应当有的增量环节（V5 极难手搓）

企业级环节一：为什么 ChatMemory 救不了 Pod 重启与跨天审批？

问题场景：智能导购查完商品、锁好优惠券，在支付 ¥8999 前挂起等财务主管次日审批——期间 K8s 发版销毁了 Pod。V5 单机 ConcurrentHashMap 直接清空；把聊天记录存 Redis（ChatMemory）依然不知道代码跑到了哪一步！
① Chat History（对话历史）
• 存什么：自然语言问答消息列表。
• 干什么：拼装下次发给大模型的上下文。
• 局限：里面没有程序步数游标、没有工具返回的中间 Map。
② Agent State（会话业务变量）
• 存什么：用户偏好品牌、预算上限、默认地址等全局事实。
• 干什么：跨轮次低频读写共享。
• 局限：不记录单次任务执行堆栈。
③ Execution Checkpointer（执行栈快照）
• 存什么：stepCursor 游标、callStack、scratchpad、待审批单。
• 干什么：冻结运行现场，支撑重启续跑与分支回滚！
持久化与恢复能力 V5 手搓 / V6 Spring AI 2.0 V7 AgentScope 2.0 本课工程落地定位
Chat History 对话记忆 Redis List / ChatMemory 接口 ✔ 原生（StateBackedMemory） 仅作模型上下文窗口渲染
Execution Checkpointer ✘ 无原生支持（V6 仍须手写 150 行适配器） ✔ 原生（AgentStateStore + AgentState） AgentScopeCheckpointStore 桥接 CheckpointStorePort
跨进程断点复水 & 分支 ✘ 完全缺失（重跑易重复扣款） ✔ 基于快照 ID 恢复与分叉 POST /rehydrate & POST /fork（Demo 已覆盖）
