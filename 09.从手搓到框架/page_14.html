怎么解决恢复与回滚难题？断点复水（Rehydration）与分支（Forking）

1. 跨进程断点复水（Rehydration） POST /rehydrate
• 原理：新 Pod 收到唤醒请求后，通过 executionId + checkpointId 加载快照，还原 stepCursor 与已查询到的 scratchpad 结果，跳过已完成步骤从中断游标原位续跑。
// WorkflowV7Controller ➔ AgentScopeWorkflowAdapter public WorkflowResponse rehydrateFromCheckpoint(String execId, String cpId) { AgentCheckpoint cp = checkpointStore.loadCheckpoint(execId, cpId); if (cp.getState() == WorkflowState.COMPLETED) return completed(...); // 从 stepCursor 与 callStack 原位恢复推演，绝不重复扣款 String resumeMsg = "继续执行在步骤 " + cp.getStepCursor() + " 挂起的任务, 历史栈: " + cp.getCallStack(); return executeTask(execId, cp.getSessionId(), cp.getUserId(), resumeMsg); }
✅ 解决痛点：K8s 发版重启、或次日审批通过后，跨实例无缝唤醒而不重跑前置步骤。
2. 时光倒流分支（Time-Travel Forking） POST /fork
chk-0 (需求解析) ➔ chk-1 (查出拯救者 Y9000P)
  ├── chk-2 (准备下单 ¥8999 ➔ 用户驳回) [原分支保留审计]
  └── cp-fork (parent=chk-1 ➔ 改搜 MacBook) [新分支]
// AgentScopeCheckpointStore.forkFromCheckpoint(...) AgentCheckpoint base = loadCheckpoint(srcExecId, cpId); AgentCheckpoint forked = new AgentCheckpoint( newExecId, "cp-fork-...", cpId, WorkflowState.EXECUTING, base.getStepCursor()); forked.setScratchpad(new HashMap<>(base.getScratchpad())); saveSnapshot(forked);
⚠️ 重要边界（仅 PPT）：若旧分支已产生外部副作用（如锁库存/订机票），Forking 必须联动 Saga 逆向补偿（第 11 课详讲）。
