横切安全与遥测：从散落调用到 CallAdvisor / StreamAdvisor 责任链

五步看透 Advisor：问题：V5 GuardrailsService 散落业务代码极易漏调 ➔ 概念：双向洋葱责任链（2.0.2 GA 正式定名 CallAdvisor / StreamAdvisor，废弃旧 *AroundAdvisor）➔ 原理：按 getOrder() 升序入站前置处理、降序出站后置审查 ➔ 调用：挂载到 defaultAdvisors() 全局生效。
1. GuardrailsCallAdvisor（同步双向拦截） CallAdvisor
public class GuardrailsCallAdvisor implements CallAdvisor { @Override public ChatClientResponse adviseCall(ChatClientRequest req, CallAdvisorChain chain) { String text = req.prompt().getUserMessage().getText(); // 1. 【前置拦截】Prompt 注入阻断 + 手机号/身份证 PII 脱敏 if (checkInjection(text)) throw new SecurityException("违规输入拦截"); req = req.mutate().prompt(req.prompt().augmentUserMessage( old -> new UserMessage(sanitizePii(text)))).build(); // 2. 【推进责任链】进入下一 Advisor 或 ChatModel ChatClientResponse resp = chain.nextCall(req); // 3. 【后置审查】过滤响应密钥与敏感词并注入耗时上下文 String safe = sanitizeOutput(extractResponseText(resp)); return resp.mutate().chatResponse(maskedChatResp(resp, safe)).build(); } }
✅ 调用方式：设置 getOrder() = HIGHEST_PRECEDENCE + 100，确保发给模型前第一道脱敏。
2. TelemetryStreamAdvisor（流式 TTFT 监控） StreamAdvisor
public class TelemetryStreamAdvisor implements StreamAdvisor { @Override public Flux<ChatClientResponse> adviseStream( ChatClientRequest req, StreamAdvisorChain chain) { long start = System.currentTimeMillis(); AtomicBoolean isFirst = new AtomicBoolean(true); return chain.nextStream(req).map(chunk -> { if (isFirst.compareAndSet(true, false)) { log.info("首 Token 延迟 (TTFT): {}ms", System.currentTimeMillis() - start); } return chunk.mutate().context("ttft_ms", ...).build(); }); } }
⚠️ 响应式红线：严禁在 adviseStream 的 map() 中执行阻塞 JDBC/Redis 调用，防止阻塞 EventLoop！
