PART 1 · 同构能力提效（V5 ➔ V6 · 外部 MCP 协议连接） 装配已预留 · Demo 默认 Mock/HTTP 兜底独立运行

MCP 工具接入：从手写客户端与桥接器到官方内置 MCP Client

1. V5 存在什么问题？
McpProductClient(201行) + McpKnowledgeClient(212行) + McpToolCallback(80行) 全部手写 SSE 握手、重连与 Schema 桥接。
2. 引入什么概念？
MCP Client Starter（spring-ai-starter-mcp-client）与 SyncMcpToolCallbackProvider 标准适配器。
3. 原理与怎么解决？
Starter 按 YAML 自动创建 McpSyncClient、执行 initialize 握手并发现远端工具，统一暴露为 ToolCallbackProvider。
4. 框架位置 & 架构评估
仍是连接 8081/8082 MCP Server（架构未变），仅把 493 行手写客户端与桥接胶水压缩为配置 + 3 行注入。
V5 手搓原版 · McpToolCallback.java (80行) 手动连接 + 手动桥接
// 1. McpProductClient.java (201行)：手动建立 SSE 传输与初始化 McpSyncClient client = McpClient.sync(transport).build(); client.initialize(); // 2. McpToolCallback.java (80行)：手动实现 FunctionCallback 桥接 public class McpToolCallback implements FunctionCallback { public String call(String functionInput) { Map<String, Object> args = mapper.readValue(functionInput, Map.class); CallToolResult res = mcpClient.callTool(new CallToolRequest(name, args)); return extractTextContent(res); } }
⚠️ 痛点：每接一个外部 MCP Server 都要复制连接管理、断线懒重连与回调包装代码。
V6 Spring AI 2.0 · 配置即接入 + 自动装配 桥接代码归零
# 1. application.yml：声明远端 MCP Server 连接，Starter 自动建连 spring.ai.mcp.client: enabled: false # 启动 8081/8082 时改为 true 即可直连 sse.connections: product-server.url: http://localhost:8081 knowledge-server.url: http://localhost:8082 // 2. SpringAi2ChatConfig.java：注入 SyncMcpToolCallbackProvider 挂载 SyncMcpToolCallbackProvider mcp = mcpProvider.getIfAvailable(); if (mcp != null) builder.defaultToolCallbacks(mcp);
✅ Demo 工程说明：V6 已预留官方 MCP 自动装配代码；为支持离线零依赖启动，默认 enabled: false 并由 SpringAi2ToolAdapter 兜底（V7 则用独立 McpEnterpriseToolAdapter 实现 EnterpriseToolPort）。
