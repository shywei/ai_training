Prompt 组装与模型调用：从 PromptManager 到 ChatClient.builder()

1. V5 存在什么问题？
每次调用都要手动 String.format 拼模板、建 List<Message>、深层链式取 getOutput()，样板代码多且易漏配切面。
2. 引入什么概念？
ChatClient Fluent API：借鉴 RestClient 的流式声明式接口，取代零散的 ChatModel.call(Prompt) 过程式拼装。
3. 原理与怎么解决？
配置期/运行期分离：启动期用 Builder 固化默认 System、Advisors、Tools；调用期按需覆写 User 参数，自动组装 Prompt。
4. 框架位置 & 架构评估
对应 SpringAi2ChatConfig。架构本质未变（仍是发 System+User 给模型），纯开发效率提升（65 行 ➔ 25 行核心配置）。
V5 手搓原版 · PromptManager + 业务调用 过程式手动组装
// 1. PromptManager.java (65行)：手写占位符拼接 String sys = String.format("# 角色\n你是%s。%s...", agentName, agentRole, agentConstraints); // 2. 每次请求手动新建消息列表与 Prompt 对象 List<Message> msgs = new ArrayList<>(); msgs.add(new SystemMessage(sys)); msgs.add(new UserMessage(promptManager.buildUserPrompt(msg, ctx))); // 3. 显式调用 ChatModel 并层层解包结果 + 手动调安全过滤 ChatResponse resp = chatModel.call(new Prompt(msgs, options)); String reply = resp.getResult().getOutput().getText(); reply = guardrailsService.sanitize(reply); // 极易漏调！
⚠️ 对照结论：底层依然是构造 SystemMessage + UserMessage 发给模型，只是全靠人工搬砖。
V6 Spring AI 2.0 · SpringAi2ChatConfig.java 配置集中 · 调用一行
// 1. 配置期：ChatClient.builder(chatModel) 集中装配 Bean @Bean public ChatClient shoppingChatClient(ChatModel chatModel, ...) { return ChatClient.builder(chatModel) .defaultSystem(systemPrompt) .defaultAdvisors(List.of(guardrailsAdvisor, repairAdvisor, telemetryAdvisor)) .defaultTools(toolAdapter) .build(); } // 2. 运行期（SpringAi2WorkflowAdapter）：业务侧一行完成调用 String reply = chatClient.prompt().user(promptContext).call().content(); // 若需结构化强类型返回：.call().entity(ShoppingIntent.class)
