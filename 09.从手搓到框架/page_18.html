模型传参老出错怎么办？Bean Validation 契约 + 自愈纠错循环

问题与两道防线：大模型常把商品号写成 "lenovo-01"、手机号少一位；V5 一报错就降级。框架下：防线一用 Jakarta 注解把规则推导进 JSON Schema；防线二靠扩展点拦截校验异常拼接 Repair Prompt 驱动限次重填。
防线一：ToolOrderRequest 强契约（事前约束） 单测已覆盖
// 1. 领域契约声明（SpringAI2 与 AgentScope 100% 共用） @Pattern(regexp = "^(NB|PH|ACC)[0-9]{3}$", message = "格式如 NB001") private String productId; @Min(value = 1) @Max(value = 99) private Integer quantity; @Pattern(regexp = "^1[3-9]\\d{9}$", message = "合法11位大陆手机号") private String contactPhone; // 2. 工具入口执行校验（ShoppingAgentTools / SpringAi2ToolAdapter） Set<ConstraintViolation<ToolOrderRequest>> v = validator.validate(req); if (!v.isEmpty()) throw new ConstraintViolationException(...);
✅ 双重作用：既供框架反射生成 JSON Schema，又在运行时把住参数入口。
防线二：Schema Repair Loop（事后扩展点自愈） 需开发者扩展
// V6 实现 (SchemaRepairCallAdvisor.java)：拦截异常并追加修正提示重试 while (attempt <= MAX_REPAIR_ATTEMPTS) { try { return chain.nextCall(currentRequest); } catch (ConstraintViolationException cve) { if (++attempt > MAX_REPAIR_ATTEMPTS) throw cve; Prompt fixed = currentRequest.prompt().augmentUserMessage( old -> new UserMessage(old.getText() + "\n[自愈提示] " + err)); currentRequest = currentRequest.mutate().prompt(fixed).build(); } } // V7 实现 (SchemaRepairMiddleware.java)：onActing + .onErrorResume() return next.apply(in).onErrorResume(err -> emitSchemaRepairEvent(err));
⚠️ 边界澄清：框架原生只管“校验不通过抛异常”；捕获错误拼 Repair Prompt 并限制 2~3 次上限，必须由开发者通过 Advisor / Middleware 扩展。
