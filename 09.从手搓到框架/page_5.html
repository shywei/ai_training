PART 1 · 同构能力提效（V6 运行时底座 · 两项均有配置与代码落地） 虚拟线程 Demo 已覆盖 · OTel 对接仅 PPT 讲解

为什么 Spring AI 2.0 升级了 JDK 21 与 Spring Boot 4.0 底座？

升级动因：Spring AI 2.0.2 GA 绑定 Java 17+/21 与 Spring Boot 4.0 / Framework 7.0，不是为了追新，而是为了直接利用虚拟线程高并发长等待与内建 GenAI 可观测。
1. JDK 21 虚拟线程（Virtual Threads） Demo 已覆盖
• 问题：LLM 响应动辄 2~10 秒，V5 传统 Tomcat 200 线程并发一高直接阻塞耗尽。
• 原理：JVM 轻量级 M:N 调度（JEP 444），网络 I/O 阻塞时自动挂起卸载载体 OS 线程，内存开销仅 KB 级。
• 怎么配 & 怎么用：在 application.yml 开开关 + 流式异步直接 Thread.ofVirtual()：
# enterprise-ai-agent-springai2/src/main/resources/application.yml spring: threads: virtual: enabled: true # 自动让 Tomcat/MVC 长阻塞请求跑在虚拟线程 // SpringAi2WorkflowAdapter.java (第112行)：异步流式任务 Thread.ofVirtual().start(() -> { WorkflowResponse resp = driveWorkflowLoop(root, msg, sink); sink.tryEmitNext(WorkflowStreamEvent.completed(execId, resp.getMessage())); });
✅ 收益：无需为了高并发强行把所有同步业务改造成复杂的 WebFlux 反应式回调。
2. Spring Boot 4.0 / Micrometer 可观测 配置已覆盖 · 采集仅PPT
• 问题：V5 手写 TraceService 仅存内存 Map，跨调用的 Token 统计与模型延迟极易漏埋点。
• 原理：ChatClient 自动接入 Micrometer ObservationRegistry，按 OpenTelemetry GenAI 语义自动记录耗时、Token 与异常 Span。
• 怎么配 & 怎么用：在 application.yml 开启观测开关（生产对接 OTLP/Jaeger）：
# enterprise-ai-agent-springai2/src/main/resources/application.yml spring: ai: chat: observations: log-prompt: false # 生产禁止明文打 Prompt 防 PII 泄露 log-completion: false # 自动采集 gen_ai.usage.input_tokens 等指标 // 生产扩展（仅 PPT）：引入 spring-boot-starter-opentelemetry 后 // management.otlp.tracing.endpoint=http://jaeger:4318/v1/traces // 自动导出 ChatModel + ToolCalling + Advisor 全链路 Span
✅ 收益：模型调用指标（Token/TTFT/错误率）随框架自动采集，不再散落在业务代码里手写埋点。
