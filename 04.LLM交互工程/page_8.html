CHAPTER 05

结构化输出 — Java 开发的生命线

企业痛点：Java 无法解析带有废话的 JSON
方案一：提示词约束
Prompt 中要求"只输出 JSON"
✅ 所有模型支持
✅ 实现最简单
⚠️ 不保证 100% 合规
方案二：API 原生
response_format 强制格式
✅ 合规率接近 100%
✅ 不用改 Prompt
⚠️ 只有部分模型支持
🛡️ 代码层兜底（必须有）
不管用哪种方案，Java 端都必须：① JSON 提取（从废话中提取）② Schema 验证 ③ Bean Mapping（Jackson）
💻 Demo 代码：StructuredOutputHandler.java
public JsonNode validate(String llmOutput) {
  // 1. 从 LLM 输出中提取 JSON
  String json = extractJson(llmOutput);
  // extractJson 处理：
  // - 纯 JSON: 直接返回
  // - ```json...```: 提取代码块
  // - 混合文本: 找 { 到 }

  // 2. JSON Schema 验证
  try {
    return objectMapper.readTree(json);
  } catch (Exception e) {
    return null;  // 验证失败
  }
}

// 3. Self-Correction：验证失败时
public String buildCorrectionPrompt(
    String original, String error) {
  return "你上次输出不是合法JSON，"
    + "报错：" + error
    + "上次输出：" + original
    + "请重新输出，只输出JSON。";
}
关键：提示词约束是通用方案，代码验证是必须的兜底。两者缺一不可。
