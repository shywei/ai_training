CHAPTER 05

结构化输出 — 为什么 LLM 必须返回 JSON？

核心问题：LLM 的输出是给人看的，还是给代码用的？
聊天场景 → 人能读就行
API 场景 → Java 代码需要结构化数据
❌ 自然语言 → Java 无法可靠解析
"推荐联想小新Pro，大概6000到8000，适合写代码"
→ Java 怎么提取商品名？价格？用正则？格式一变就崩。
✅ JSON → Jackson 直接映射为 Java 对象
{"products":[{"name":"联想小新Pro","price":"6000-8000"}]}
→ objectMapper.readValue(json, RecommendResult.class)
结构化输出的真正价值
不是"展示给用户看"，而是让 Java 代码能程序化处理 LLM 的输出：存数据库、传给订单系统、渲染成商品卡片。
两种让 LLM 返回 JSON 的方案
方案一：提示词约束
Prompt 里要求"只输出 JSON"
✅ 所有模型支持
⚠️ 不保证 100% 合规
方案二：API 原生
response_format 强制 Schema
✅ 合规率接近 100%
⚠️ 部分模型支持
代码层兜底（必须有）
// LLM 可能返回: "好的，推荐如下：{...} 希望有帮助"

// 1. 提取 JSON（从废话中提取）
String json = extractJson(llmOutput);
// → {"products":[{"name":"联想小新Pro",...}]}

// 2. Bean Mapping: JSON → Java 对象
RecommendResult result = objectMapper
    .readValue(json, RecommendResult.class);

// 3. Java 代码用对象做具体的事
result.getProducts().get(0).getName();
// → "联想小新Pro"（可靠、类型安全）

// 实际用途：
// · 存数据库: repository.save(result)
// · 传订单系统: orderService.create(result)
// · 渲染卡片: productCardView(result)
Demo 可验证：后端日志会打印 LLM 原始输出 → 提取出的 JSON → 映射后的 Java 对象字段。三个步骤一目了然。
