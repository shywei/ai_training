CHAPTER 04 · 治理核心

多维模型路由矩阵 — 成本、延迟、能力、窗口与可用性

为什么不能只靠单一规则（如字数或成本）路由？
字数长不等于逻辑复杂，关键词匹配极易漏判；企业生产需综合考量性能、预算与 SLA 韧性，构建五维决策矩阵。
💰 成本维度
Token 单价梯度与预算：大模型与小模型价差 10~50x；优先命中 Prompt Caching，对廉价高频任务（分类/实体抽取）坚决走快模型。
⚡ 延迟吞吐
首 Token 延迟 (TTFT) 与 TPS：C 端客服要求 TTFT < 800ms（选快模型）；后台异步批处理与报表生成优先保质量（可容忍 30s+ 推理）。
🧠 能力专精
领域专精匹配：代码/重构走 Coding 专精模型；复杂逻辑/多步反思走 Reasoning（DeepSeek-R1/o3）；日常闲聊走通用轻量模型。
📏 上下文窗口
有效窗口与注意力损耗：长文档分析（>64K）路由至原生超长窗口模型（如 Kimi / Gemini）；常规短问答截留小上下文模型以防注意力退化。
🛡️ 可用性韧性
健康探活与故障熔断：网关实时监控上游 429 / 5xx / 延时毛刺；触发熔断时自动降级：推理模型 → 通用主模型 → 备选供应商兜底。
决策公式：$\text{RouteScore} = w_1 \cdot \text{Capability} - w_2 \cdot \text{Cost} - w_3 \cdot \text{Latency} + w_4 \cdot \text{HealthState}$
💻 Demo 实现：ModelRouter.java (架构解耦教学起点) 
@Component
public class ModelRouter {
  @Value("${agent.model.fast}") private String fastModel;
  @Value("${agent.model.reasoning}") private String reasoningModel;

  public String selectModel(String msg) {
    // 规则快路径：长度阈值 + 关键词匹配
    if (needsReasoning(msg)) {
      return reasoningModel;  // 复杂任务 → 慢思考推理模型
    }
    return fastModel;         // 简单问答 → 毫秒级快模型
  }

  private boolean needsReasoning(String msg) {
    if (msg.length() > 500) return true;
    String[] kw = {"架构", "重构", "分析", "对比", "为什么"};
    for (String k : kw) if (msg.contains(k)) return true;
    return false;
  }
}
🛠️ Demo vs 生产级演进对比
Demo 教学简化：消息长度 + 静态关键词。核心价值是让学员掌握“路由与业务 Controller 严格解耦”，建立独立 Bean 思想。
生产级落地：① 规则快路径 + 轻量小模型意图分类（Semantic Router）兜底；② 路由规则接入配置中心动态热更新；③ 挂载健康检查与熔断降级链。
核心准则：业务代码永远面向“逻辑能力”编程，路由网关负责将逻辑能力映射为具体的物理模型与最优供应商。
