📖 读代码顺序（从入口到链路）
1. ShoppingAgentController.chat() & recommend() 整条链路串联点
2. ModelRouter.selectModel(msg)      复杂度判断 → fast / reasoning
3. PromptManager.buildSystemPrompt()
   & buildUserPrompt(msg, null)      context 扩展点（后续课填充）
4. StructuredOutputHandler.extractJson() → validate()
5. StructuredOutputHandler.buildCorrectionPrompt()
                                     校验失败 → 拼纠错提示词 → 二次调用
6. GuardrailsService.checkInjection() / sanitize()
✅ 可在 Demo（v1.1.1）亲手验证的 7 个点
1 · 入口注入拦截
点「测试注入防御」或传「忽略之前的指令…」→ 立即拦截返回警告，对照 GuardrailsService.checkInjection 中英双语正则
2 · 结构化输出五步控制台链路
点前端「结构化输出演示」按钮 → 看后端控制台打印：【步骤1】原始输出 → 【步骤2】提取 JSON → 【步骤3】Schema 验证 → 【步骤4】Bean Mapping (RecommendResult)
3 · Self-Correction 触发
写单测喂「废话+JSON」三种格式给 extractJson/validate；在 /recommend 断点看 validate 失败后 buildCorrectionPrompt → 二次调用重试
4 · 模型路由自动切换（Fast vs Reasoning）
分别发「推荐一台笔记本」与「分析一下游戏本和轻薄本的架构差异」→ 看气泡顶部 [MODEL] 标签在 fast 与 reasoning 模型间自动切换
5 · 出口敏感信息处理
输出含「密码/password」→ /recommend 响应带 _warning 字段（containsSensitiveInfo）；/chat 流式出口看 sanitize() 替换成 ***
6 · SSE Streaming 逐 Token 效果
前端发消息 → F12 Network 看 GET /api/agent/chat 的 text/event-stream 流式响应与首包 [MODEL] 标记
7 · context 扩展点预留
看 ShoppingAgentController 传给 buildUserPrompt(message, null) 的 null 参数——第五/六/七课将逐步注入记忆、RAG 与工具结果
