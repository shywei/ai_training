CHAPTER 02

OpenAI 接口协议 — 后续六课的共同基础

📤 请求结构
// POST {服务商地址}/v1/chat/completions
// Header: Authorization: Bearer sk-xxx

{
  "model": "Qwen/Qwen2.5-7B-Instruct",
  "messages": [
    {"role":"system", "content":"你是导购助手"},
    {"role":"user", "content":"推荐一台笔记本"}
  ],
  "temperature": 0.7,
  "stream": true
}
messages 是核心。多轮对话 = 把历史消息全部塞进去。
stream=true 逐 token 返回，stream=false 一次返回完整结果。
📥 响应结构（Streaming）
// SSE 格式，每个 data: 是一个 token

data: {"choices":[{"delta":{"content":"根据"}}]}
data: {"choices":[{"delta":{"content":"您的"}}]}
data: {"choices":[{"delta":{"content":"需求"}}]}
...
data: [DONE]

// 非 Streaming：一次性返回
{"choices":[{"message":{"content":"完整回复"}}]}
{"usage":{"prompt_tokens":42,"completion_tokens":156}}
Streaming 用 delta.content 逐 token 返回
[DONE] 流结束标记
usage 返回 token 用量，用于成本监控
🔑 messages 是后续所有课程的基础
v1.0 第四课（当前）
messages = [system, user]
v2.0 第五课 Memory
messages = [system, 历史对话, user]
v3.0 第六课 Knowledge
messages = [system, RAG检索结果, user]
v4.0 第七课 Tool
请求增加 tools 字段，响应增加 tool_calls
v5.0 第八课 Workflow
多次调用协议，编排成流程
OpenAI 协议不是"知道就行的知识"，而是后面六课的共同基础。这一课讲不透，后面都学不会。
