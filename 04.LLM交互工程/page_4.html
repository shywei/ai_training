CHAPTER 02

OpenAI 接口协议 — 为什么配个 URL 和 Key 就能交互

📤 请求（Request）
// POST /v1/chat/completions
// Header: Authorization: Bearer sk-xxx

{
  "model": "Qwen/Qwen2.5-7B-Instruct",
  "messages": [
    {
      "role": "system",
      "content": "你是导购助手"
    },
    {
      "role": "user",
      "content": "推荐一台笔记本"
    }
  ],
  "temperature": 0.7,
  "stream": true
}
URL = 服务商地址 + /v1/chat/completions
Key = Bearer Token 认证
messages = 对话历史（system + user + assistant）
📥 响应（Response）— Streaming
// SSE 格式：每个 data: 是一个 token

data: {"choices":[{"delta":{"content":"根据"}}]}
data: {"choices":[{"delta":{"content":"您的"}}]}
data: {"choices":[{"delta":{"content":"需求"}}]}
data: {"choices":[{"delta":{"content":"，"}}]}
data: {"choices":[{"delta":{"content":"推荐"}}]}
...
data: [DONE]

// 非 Streaming 时，一次性返回完整内容：
// { "choices":[{"message":{"content":"完整回复"}}] }
Streaming = 逐 token 返回（SSE 协议）
[DONE] = 流结束标记
delta.content = 本次返回的文本片段
这就是为什么配个 URL 和 Key 就能交互 — 所有服务商（OpenAI、DeepSeek、硅基流动）都遵循同一套协议。
Spring AI 封装了 HTTP 请求和 SSE 解析，但底层就是这个 JSON 协议。
