## Slide Objective
讲透**企业级多维模型路由矩阵**的设计思想与工程实现。从单一成本/规则路由扩展为**成本、延迟、能力、上下文长度、可用性与健康检查**五维决策矩阵，讲清 Demo 中 `ModelRouter.java`（长度+关键词）的教学定位与生产级演进路线。

## Suggested Presentation
讲这页时，先纠正一个极易犯的工程错误：“模型路由不就是如果字数多就用大模型，字数少就用小模型吗？”
这种单维度的粗暴规则在真实业务中分分钟翻车：
- 一句简单的“重构这段 2000 行的遗留代码”，输入很长，但可能只是代码搬运，不需要最贵的超大思考模型；
- 而一句极短的“这道数学悖论错在哪里？”，输入只有 20 个字，却需要具备极强深度推理（Reasoning）能力的模型才能解答。

### 五维企业级模型路由矩阵
看左侧，企业级网关在做路由决策时，必须考量五个核心维度：

1. **成本维度（Cost）：**
   - 掌握模型单价梯度：不同尺寸模型输入/输出 Token 单价可相差 10 到 50 倍；
   - 优先榨干前缀缓存（Prompt Caching）：对能够高频命中缓存的模版任务，优先路由至缓存友好型模型；
   - 简单分类、实体抽取、意图识别坚决分流到廉价快模型。
2. **延迟与吞吐性能（Latency & Throughput）：**
   - 首 Token 延迟（TTFT）与吞吐速率（TPS）：在线 C 端客服直接决定用户留存，TTFT 必须压到 800ms 以内（必须选快模型）；而对于后台离线数据分析、长篇报表生成，用户可以容忍 30 秒以上的慢思考，此时放行给 DeepSeek-R1 / o3 这类推理模型。
3. **能力专精维度（Capabilities）：**
   - 建立能力标签库：复杂代码重构匹配 Coding 专精模型，复杂逻辑与多跳反思匹配 Reasoning 模型，涉及图文理解匹配 Multimodal 模型，结构化输出匹配具备严格 JSON Schema 遵循能力的模型。
4. **上下文窗口维度（Context Window）：**
   - 有效窗口与注意力退化：对 100K 以上的长文档，必须路由至具备长上下文原生架构的模型；对短文本问答，截留在短窗口模型中，防止无效的注意力稀释。
5. **可用性与健康检查（Availability & Health）：**
   - 监控与故障熔断：生产环境公有云 API 经常发生 429 限流、网络丢包或超时。网关层需持续对上游模型执行健康探测（Health Ping）；一旦主模型报错率或 P99 延迟超标，路由矩阵立即触发断路器，动态降级至备用模型或跨供应商备援。

### Demo 代码与生产落地的差距辨析
看右侧代码 `ModelRouter.java`：
- **Demo 的核心价值：** 演示**“架构解耦”**——将路由决策从 Controller 业务代码中剥离为独立的 Spring `@Component`。业务 Controller 永远只面向“抽象导购助手”调用，不需要关心背后到底由哪个模型执行。
- **Demo 的教学简化（Educational Simplification）：** 
  Demo 内部只用了 `msg.length() > 500` 和关键词数组（"架构"、"分析"、"重构"）进行快慢模型分流。这是为了让学员在单机不引入额外依赖的前提下，直观验证“发你好走快模型，发分析走推理模型”。
- **生产级升级路径：**
  1. **意图路由（Semantic Router）：** 规则快路径未命中时，调用轻量小模型进行语义意图打分；
  2. **规则动态化：** 关键词与权重配比托管至配置中心（如 Nacos / Apollo），支持秒级热更新，无需重启应用；
  3. **指标驱动选型：** 结合 Prometheus 监控各模型的耗时、Token 成本与报错率，驱动加权评分公式自动调优。

## Key Emphasis
1. 强调“路由组件必须独立”：换模型、换策略绝不能修改 Controller 业务逻辑。
2. 牢记五维决策矩阵：成本、延迟、能力、窗口、可用性缺一不可。
3. 理解 Demo 的简化目的：关键词规则是教学的“脚手架”，生产环境依托网关与语义路由。

## Optional Extension
**学员问：如果在高并发场景下，每次都用一个小模型去做意图路由，会不会增加额外的网络延迟和开销？**
答：会！所以在企业网关中，通常采用“三级路由漏斗”：
- **一级（L1 规则快路径，耗时 &lt;1ms）：** 正则白名单、固定接口标识、用户 VIP 等级，直接命中固定模型；
- **二级（L2 向量路由 / Embedding 语义路由，耗时 ~5ms）：** 将用户问题向量化后与预定义的意图向量库做余弦相似度匹配（如 FastEmbed / Semantic Router），不需要调用 LLM；
- **三级（L3 智能代理路由，耗时 ~200ms）：** 仅在极其模糊或复杂的多步任务中，才调用轻量分类模型（如 Qwen2.5-1.5B）进行精准判断。

## Classroom Interaction
让学员在前端界面上测试两个问题：
1. 输入“你好”，观察前端模型标签显示为 `fast`；
2. 输入“请帮我分析一下轻薄本和游戏本在散热架构上的区别”，观察前端模型标签无缝切换为 `reasoning`。
让学员查看控制台日志，确认路由生效，切身体会解耦带来的平滑体验。

## Take Away
业务逻辑面向能力，网关路由面向模型。五维矩阵兼顾成本与体验，熔断降级兜底系统生命线。
