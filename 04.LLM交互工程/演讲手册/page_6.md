## Slide Objective
让学员理解 Token 和 Context Window 的工程含义，以及模型选型的成本考量。

## Suggested Presentation
Token 是大模型的计费单位。你在硅基流动控制台能看到每次调用的 token 消耗。一个汉字 1-2 个 token，一个函数 50-200 个 token。输出 token 比输入贵 2-5 倍——这是成本控制的关键：Prompt 写得越精简，成本越低。

Context Window 是模型一次能处理的最大 token 数。窗口越大，推理越慢、成本越高。不是越大越好——你给用户推荐一个笔记本，不需要 100 万 token 的窗口。

右边两个模型的对比是重点。Qwen2.5-7B 是快模型，日常对话够用。Qwen3-8B 是推理模型，有思维链，适合复杂分析。Demo 里的 ModelRouter 就是根据消息复杂度自动选择这两个模型。

你可以验证：在前端问"推荐一台笔记本"——简单问题，看后端日志，用的是 Qwen2.5-7B。然后问"分析一下游戏本和轻薄本的架构设计差异"——含"分析"关键词，ModelRouter 会切换到 Qwen3-8B。看后端日志里的模型名变化。

这里有个真实的踩坑经验：一开始我们用的是 `DeepSeek-R1-0528-Qwen3-8B`，后来发现它已经下架了。免费模型经常变动，你做项目时也会遇到。解决方案：用多个免费模型做备选，ModelRouter 的模型名从配置读取，改配置不用改代码。

## Key Emphasis
让学员在 Demo 里验证模型切换。看后端日志，不要只听。

## Transition
知道了 Token 和模型差异，下一个问题：代码里怎么实现"简单问题走快模型，复杂问题走推理模型"？这就是模型路由。
