💻 前端 fetch + ReadableStream 解析与取消控制
// 支持主动取消的流式请求
const abortCtrl = new AbortController();
const resp = await fetch(`/api/agent/chat`, {
  method: 'POST', body: JSON.stringify({ message: text }),
  signal: abortCtrl.signal // 绑定中断信号
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = ''; // 维护半行数据缓冲区

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop(); // 截留最后未闭合的半行，防止解析崩溃

  for (const line of lines) {
    if (line.startsWith('data:')) {
      const chunk = line.substring(5).trim();
      if (chunk === '[DONE]') continue;
      fullText += chunk;
      updateUI(fullText); // 增量渲染 Markdown
    }
  }
}
⚡ SSE 流式传输四大生产工程挑战与解法
① 代理层缓冲机制风险 (Proxy Buffering) 高频线上踩坑
痛点：Nginx / 网关默认开启缓冲，拦截后端 Token 攒满 4KB 或等连接结束才一次性下发，导致前端“打字机流式”彻底失效！
工业解法：Nginx 显式配置 proxy_buffering off;，后端响应头加 X-Accel-Buffering: no 与 Cache-Control: no-cache，并关闭 gzip 块缓冲。
② 粘包拆包与半行数据截断 (Chunk Parse Boundary) Demo 已覆盖
痛点：TCP 传输的分片与 SSE 事件行边界不重合。单个 chunk 常常从中间截断 JSON（如前半包 {"choi，后半包 ces":...}），直接解析必报错。
工业解法：客户端/网关维护行暂存缓冲区 buffer，以换行符切割，未闭合的半行留存等待下一包拼接。
③ 客户端断开检测与上游取消 (Client Disconnect) Token 止损底线
痛点：用户中途关闭页面或点击“停止生成”，若后端不感知，上游 LLM 继续空跑几十秒，白白烧光企业 Token 预算与 GPU 算力！
工业解法：前端调用 abortCtrl.abort()；后端监听连接断开（Servlet ClientAbortException / Flux doOnCancel），立即向上游 LLM 发送 Cancel 请求终止生成。
④ 长连接资源保活与中断重连 (Keep-Alive & Reconnect) 生产稳定性
痛点：推理模型深度思考（Reasoning）长达 20~60 秒不发正文，中间网络代理因空闲超时强制掐断；移动端网络抖动。
工业解法：后端每隔 15 秒主动下发 SSE 注释心跳帧（: keep-alive\n\n）；支持带 Last-Event-ID 断点重连机制，避免用户从头重来。
流式总结：SSE 不只是前端打字机特效，更是贯穿“反向代理缓冲、数据拆包缓冲、客户端断连止损与长连接保活”的系统工程。
