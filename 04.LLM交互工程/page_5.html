CHAPTER 02

OpenAI 协议定义了哪些标准能力？

一个 POST 请求，通过不同的参数组合，就能调用大模型的全部标准能力。
💬 Messages（对话）
role: system — 定义 Agent 角色
role: user — 用户输入
role: assistant — 模型回复

多轮对话就是把历史 messages 全部传上去。模型根据完整对话历史生成回复。
📡 Streaming（流式输出）
stream: true → SSE 逐 token 返回
stream: false → 等全部生成完一次性返回

用户体验差异：首字响应 200ms vs 数秒等待。所有对话类产品必须用 Streaming。
🌡️ Temperature（温度）
0.0 = 确定性最高，每次回答一样
0.7 = 平衡模式
1.0+ = 创造性强，但可能胡说

客服用 0.2，创意写作用 0.9。
🔧 Function Calling（工具调用）
在请求中定义工具列表（函数名+参数描述）。
模型判断需要调用哪个工具、传什么参数。
模型不直接调用，而是返回调用意图，由服务端执行。

这是第七课 Tool 的基础。
📋 Structured Output（结构化输出）
通过 response_format 参数强制输出 JSON Schema。
模型保证输出符合定义的结构。
不是所有模型都支持，OpenAI 原生支持，其他厂商部分支持。

这就是第五章讲的"方案二"。
🔢 Token 计数
响应中返回 usage.prompt_tokens（输入 token 数）
usage.completion_tokens（输出 token 数）

用于成本监控和用量统计。企业必须记录。
核心认知：一个 HTTP POST + 一套 JSON 参数 = 大模型的全部标准能力。所有服务商遵循同一协议，这就是为什么换服务商只需要改 URL 和 Key。
