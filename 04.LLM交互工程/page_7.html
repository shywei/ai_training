CHAPTER 03

Token、Prefix Caching、窗口与模型选型

1 · Token 与计费结构
文本经 BPE 词元化拆为 Token（1 汉字 ≈ 0.6~1.5 token，1 函数 ≈ 50-200 token）。

三种单价档位：
· 缓存命中输入：仅标准输入的 10%~25%
· 标准未命中输入：1x 基准价
· 输出 Token（含思维链）：比输入贵 2-5 倍
2 · Prompt Caching（前缀缓存）
2026 交互工程第一降本利器（OpenAI / DeepSeek / Claude / 千问均支持）。

原理：服务端自动缓存请求头部的相同前缀 KV Cache（通常 ≥1024 tokens 触发）。
收益：多轮对话/Agent 循环降低 50%~90% 输入成本，降低 80% 首字延迟（TTFT）！
3 · Context Window 与注意力退化
模型单次最大处理量（输入+输出）：从早期 4K/128K 演进至 2026 主流 256K~100万+。

工程陷阱：窗口大 ≠ 可以无脑塞！上下文过长会导致 Lost in the Middle（中间信息遗忘）、TTFT 飙升、单次成本剧增。
4 · 推理模型与思考预算
推理模型回答前生成长思维链（Thinking），按输出 Token 计费（消耗 3-10 倍 Token）。

控制手段：通过 reasoning_effort（low / medium / high）或 thinking_budget 控制思考深度；简单问题路由至快模型。
⚡ Fast Model（日常对话 / 意图分类 / 摘要提取）
低延迟（TTFT < 300ms）、高吞吐、低成本 → Demo 配置 agent.model.fast（如 Qwen2.5-7B）
🧠 Reasoning Model（架构分析 / 复杂规划 / 严格 JSON 抽取）
内置慢思考推理、逻辑严密、高成本 → Demo 配置 agent.model.reasoning（如 DeepSeek-R1 / Qwen3-8B）
