CHAPTER 03 · 现代模型训练范式与前沿架构

模型架构演进：Dense（稠密模型）vs MoE（混合专家稀疏路由）

从全量参数激活的稠密模型到按需调度的混合专家网络，MoE 是现代前沿大模型以极低推理算力换取超大容量的架构奇迹。
经典范式 · 稠密模型 Dense Architecture
100% 神经元全量参与前向计算
• 工作机制：每个输入 Token 在流经每一层 Transformer 时，必须无差别地穿越全部 MLP 前馈神经元。
• 代表模型：LLaMA-3 (8B / 70B), Qwen-2.5-Dense。
• 算力困境：模型参数量越庞大，每个 Token 消耗的 FLOPs 呈严格线性放大。
规模瓶颈：当 Dense 模型参数达到 400B~1T 时，推理单 Token 延迟和昂贵算力将变得工业不可承受。
现代主流 · 混合专家 Mixture of Experts (MoE)
稀疏门控路由与动态 Top-K 激活
• 结构重组：保持注意力层不变，将标准 FFN 替换为 $N$ 个并行专家子网络（如 8 个或 64 个）。
• Router 路由器计算：为当前 Token 动态计算专家归属权重 $G(x) = \text{Softmax}(\text{TopK}(x \cdot W_g))$，仅激活得分最高的 $K$ 个专家（如 Top-2 或 64 选 8）。
核心奇迹：获得千亿甚至万亿模型的能力记忆容量，却只消耗中小模型的推理 FLOPs 与极低单字延迟！
工业级 MoE 典型模型参数量 vs 激活量与工程权衡
总容量决定智能上限 · 激活量决定推理成本
Mixtral 8×7B (47B)
总参数：47B | 激活参数：13B
每 Token 选 2 个专家，以 13B 算力实现胜过 LLaMA-2-70B 的性能。
DeepSeek-V3 (671B)
总参数：671B | 激活参数：37B
细粒度 256 专家选 8 + 共享专家，推理成本暴降为千亿 Dense 的 1/5！
部署工程权衡（Trade-offs）
静态显存占满 + 跨卡 All-to-All 通信
虽单步计算快，但全部权重必须常驻显存，对跨 GPU 节点网络互联要求极高。
