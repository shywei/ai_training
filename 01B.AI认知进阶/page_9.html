CHAPTER 02 · 模型推理核心机理

推理性能密码：Prefill 计算密集 vs Decode 访存密集与 KV Cache

大语言模型推理在物理硬件层呈现鲜明的两阶段特性：算力瓶颈与访存带宽墙交替主导，KV Cache 是性能的核心救赎与最大显存负担。
阶段一 · 输入评估 Prefill / Prompt Phase
典型计算密集型（Compute-Bound · GEMM）
• 计算特征：Prompt 中的 $T$ 个 Token 并行送入 GPU 执行矩阵乘（GEMM），计算强度高。
• 硬件利用率：Tensor Core 利用率通常达 60%~80%，算力被充分压榨。
• 业务对应指标：直接决定首字到达延迟（TTFT, Time To First Token）。
主导瓶颈：GPU TFLOPS 纯浮点算力峰值（极短序列受带宽影响）
阶段二 · 逐字吐字 Decode / Generation Phase
典型访存密集型（Memory-Bound · GEMV）
• 计算特征：单步输入 1 个 Token 执行 GEMV，计算强度低，依赖显存带宽反复搬运全权重。
• 硬件利用率：低 Batch 下算力核心空转；超大 Batch 并发下计算强度提升，可转化为计算密集。
• 业务对应指标：直接决定逐字生成速度（TPS, Tokens Per Second）。
主导瓶颈：GPU HBM 显存带宽（Batch Size 极显著影响瓶颈跃迁）
KV Cache 的空间换时间机理与长文本显存膨胀公式
推理引擎必备核心优化
1. 空间换时间直觉：
如果没有 KV Cache，生成第 $N$ 个 Token 时，前 $N-1$ 个历史词的 Key 和 Value 必须全部从头重新算一遍，推理计算复杂度将飙升至 $O(N^2)$！
缓存历史 $K$ 与 $V$ 矩阵后，单步复杂度直降为 $O(1)$。
2. KV 显存精准计算黄金公式：
VRAM_KV = 2 × 2 × L × H_kv × d_h × Context_Len × Batch_Size (bytes)
示例：70B 模型（80层, 8对KV头, 128维），并发 16，单会话 32K 长度，KV Cache 显存独占 67 GB，直接超越模型权重本身！
