CHAPTER 05 · 物理边界、架构反哺与全栈选型

为什么理解底层机理是设计高阶 Agent 与 RAG 架构的硬门槛？

底层机理从来不是死板理论，而是上层软件系统架构设计的“决策指南针”——深知物理限制，方能构筑高韧性工程。
架构反哺 01 · 知识系统 RAG Engineering
Token 边界对齐与注意力衰减攻坚
• 严禁字符硬切分：盲目按 500 字符切片会切断 UTF-8 字节和代码缩进，引发乱码；必须使用原生 Tokenizer 动态切块。
• 破局 Lost in the Middle：在构建 Prompt 时，将核心检索事实放在 Prompt 最首部与最尾部，中间留给对话历史；采用父子块索引（Parent-Child）保持大块上下文完整性。
底层机制反哺：BPE 编码原理 + U 型注意力分布
架构反哺 02 · 智能体 Agent Orchestration
抑制 KV Cache 膨胀与防循环崩溃
• 选型强制对齐 GQA：多步 ReAct 工具调用循环中，KV Cache 呈指数级膨胀，必须选型支持 GQA 架构的模型降低显存压力。
• Context 剪枝与状态机熔断：外部工具吐出大量无用日志会迅速填满窗口，必须在 Harness 层进行结构化修剪（Pruning），并用有限状态机（FSM）设定最大跳数防止无限循环死锁。
底层机制反哺：GQA 注意力演进 + KV 显存膨胀公式
架构反哺 03 · 算力路由 Cost & Model Routing
快慢思考动态分流与成本削减 80%
• 分级路由器（Classifier Router）：根据请求复杂度自动分流：80% 的简单信息提取走轻量快模型（7B/14B），仅 20% 复杂逻辑推导调用满血慢思考模型（o1/R1）。
• 最大化 Prefix Caching 命中率：固定静态 Prompt 前缀顺序，规避动态时间戳破坏，使推理引擎缓存命中率达到 90%+，推理成本立降数倍。
