## Slide Objective
为学员建立现代大语言模型推理全流程的端到端计算拓扑图，打通从用户原始文本 Prompt 到 Token 矩阵、隐藏层流转、Transformer 层特征变换、LM Head 投影到采样 Next Token 的全部数据结构流转，并清晰界定 Prefill 与 Decode 两个截然不同的物理阶段。

## Suggested Presentation
搞清楚了宏观扩展律，现在让我们正式把显微镜对准模型，看看一个请求从发出到返回，底层张量到底经历了怎样的计算拓扑。

请看中间的五步流转管道：
第一步，分词（Tokenization）。用户输入的无论是一行中文、一段 Python 代码还是一个 JSON 字符串，计算机都无法直接处理。分词器通过 BPE 等算法，将其切碎成 Token ID 列表，形成一个形状为 `[Batch_Size, Sequence_Length]` 的整型张量。
第二步，查表与位置编码（Embedding & RoPE）。每一个 Token ID 会在词表嵌入矩阵中查出一个 $d_{model}$ 维的稠密连续向量（如 4096 维），同时注入现代旋转位置编码 RoPE，把 Token 在上下文中的相对位置信息编码进复数旋转空间。
第三步，堆叠的 Transformer 核心层。数据流穿过数十层（例如 32 层或 64 层）完全相同的 Transformer Block。在每一层内部，张量首先经过 RMSNorm 和 GQA 分组查询注意力机制，与历史上下文的 KV Cache 发生交互；随后经过残差连接与第二级 RMSNorm，进入 SwiGLU 或 MoE 前馈神经网络，提取深层抽象语义。
第四步，LM Head 反向投影。最后一层的输出通过一个反向投影矩阵，直接把 $d_{model}$ 维度的连续向量放大映射回词表大小 $V$（比如 128,000 维），生成包含每一个词出现倾向的未归一化打分——Logits。
第五步，自回归采样闭环。应用 Temperature、Top-P 或 Top-K 算法，经过 Softmax 概率归一化，随机或贪婪采样出唯一的一个 Next Token ID。紧接着，这个新的 Token ID 会被回填拼接到输入序列的最末尾，以此为基础重新启动下一次循环，直到遇到结束符 `<|im_end|>`。

最底部的两行对比至关重要：
在大模型推理中，一次完整的交互被硬生生切分为两个完全不同的物理阶段：
1. Prefill 阶段：模型一次性吞入整个 Prompt。因为所有 Prompt Token 可以并行计算矩阵乘法（GEMM），所以显卡的计算单元（Tensor Cores）全功率打满，这个阶段决定了首字延迟（TTFT）；
2. Decode 阶段：生成阶段每次只计算一个新词，必须把数百亿参数和全部 KV Cache 从显存重新读取一次，显卡计算单元大面积空转，完全被显存带宽死死卡住。

## Key Q&A / Clarifications
**Q：为什么大模型不能像 Prefill 一样把整个回答并行一次性生成出来，而必须一个词一个词地串行生成？**
A：因为语言的因果因果性（Causal Dependency）。第 $N$ 个词的概率分布完全依赖于第 $1$ 到第 $N-1$ 个词。在第 $N-1$ 个词尚未被模型实际采样确定之前，第 $N$ 个词的上下文是不存在的。因此自回归生成在数学上是严格串行、步长为 1 的马尔可夫链式前向过程。
