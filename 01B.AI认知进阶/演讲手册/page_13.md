## Slide Objective
深入剖析大模型从 Dense（稠密模型）向 MoE（混合专家稀疏路由模型）的架构演进；解释门控路由器（Router）的 Top-K 动态激活机制；通过典型开源模型对比“总参数量”与“激活参数量”的经济学差异，并客观指出 MoE 私有化部署时的显存与跨卡通信挑战。

## Suggested Presentation
在 2024–2026 年，大家会发现一个极其违反直觉的现象：DeepSeek-V3 拥有高达 6710 亿的超大参数量，但它的调用 API 价格却比很多 70B 稠密模型还要便宜好几倍，吐字速度还飞快！为什么参数量越大，推理反倒能更便宜、更快？答案就在于架构层面的彻底革命——从 Dense 迈向 MoE。

请看左侧卡片：经典的 Dense（稠密架构）。
在传统 Dense 模型中，不管用户输入的是一句“你好”还是一个极其复杂的量子力学方程，前向传播时模型 100% 的神经元权重都必须全量启动参与计算。当模型扩大到 70B 甚至 405B 时，每生成一个 Token 需要消耗的浮点运算量（FLOPs）呈线性飙升，这在经济上是不可持续的。

请看右侧卡片：MoE（混合专家架构）。
MoE 的核心思想是“分工协作”。它把每一层原本巨大无比的 FFN 前馈网络，切分成几十个甚至上百个小型的独立网络，称之为“专家（Experts）”。
在这些专家门前，放着一个门控路由器（Router）。当一个 Token 流经时，Router 会在几微秒内计算出各个专家的匹配得分，然后只挑选得分最高的 $K$ 个专家（比如 8 个专家中的前 2 个，或者 256 个专家中的前 8 个）去计算这个 Token，其余 90% 以上的专家全部处于睡眠状态！

大家看底部的对照表：
Mixtral 8x7B 虽然总参数有 47B，但每个 Token 实际上只激活 13B 参数的算力；
而 DeepSeek-V3 更为极致：总参数高达 671B，但因为采用了细粒度专家切分（256 个路由专家选 8 个 + 1 个常开的共享专家），每个 Token 在运行时只激活区区 37B 参数！这就是它为什么能以 37B 的极快推理成本，换取 671B 顶级智力记忆容量的根本机理。

但是，架构师必须清醒地看到 MoE 带来的工程挑战：
MoE 降低的是“计算 FLOPs”，但并没有降低“权重显存占用”！
虽然每个 Token 只激活 37B，但 671B 的全部专家权重必须同时常驻在集群的 GPU 显存里，随时等待 Router 调度！此外，不同专家分布在不同的显卡上，Token 在专家之间流转需要通过机间网络进行密集的 All-to-All 分布式通信。如果你的机房没有 InfiniBand 高速 RDMA 互联，MoE 模型的吞吐就会被网络通信死死卡死。

## Key Q&A / Clarifications
**Q：企业做本地私有化部署时，应该优先选 Dense 模型还是 MoE 模型？**
A：取决于你的硬件卡槽资源与并发要求。如果你的机房只有 1~2 张高端消费级显卡（如双卡 RTX 4090），受限于显存总量，应该优先选择小尺寸 Dense 模型（如 Qwen-2.5-14B/32B）；只有当你的集群拥有 8 卡 A100/H800 等充沛的显存容量、且需要承载高并发业务时，部署 MoE 才能发挥出其单 Token 计算低成本、高并发吞吐的压倒性优势。
