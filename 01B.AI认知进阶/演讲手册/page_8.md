## Slide Objective
深入拆解自回归推理最后一步“采样解码（Sampling & Decoding）”的数学本质；从 Softmax 微积分角度理解 Temperature 对概率分布陡峭度的调节机制，剖析 Top-K 截断与 Top-P 核采样的组合逻辑，并提供企业级工程调参对照表。

## Suggested Presentation
很多开发者在调用大模型 API 时，经常随便设置几个参数：`temperature=0.7`、`top_p=0.9`，但很少有人从微积分层面搞懂它们在干什么。

模型最后一层输出的是一组没有任何概率含义的浮点数打分，叫 Logits（$z_i$）。要把它们变成概率，必须经过 Softmax 函数。
请看中间左侧卡片的公式：$P(w_i) = \frac{\exp(z_i / T)}{\sum \exp(z_j / T)}$。
这里的除数 $T$ 就是 Temperature（温度系数）：
当我们将 $T$ 调到极小（无限逼近于 0），任何微小的得分差异经过指数放大后，都会让最高分的那个词概率变成 100%，其余所有词全变成 0%！这就是所谓的贪婪搜索（Greedy Search），每次输出绝对确定，适合用于输出严密的 JSON 或编译代码；
反之，当我们将 $T$ 调大（比如 1.2），所有得分被除以一个大于 1 的数，极差缩小，Softmax 分布被硬生生拉平，原本概率只有 0.001% 的生僻词概率被抬高到 1%，模型展现出极大的多样性和想象力，但若温度过高（如 1.5 以上），模型就会彻底胡言乱语。

为了防止温度拉大带来的荒谬错误，工业界引入了 Top-K 与 Top-P 两个守门人：
中间卡片 2 是 Top-K 截断：不管词表有多大，永远只保留概率最大的前 $K$ 个（比如 50 个），把剩下的垃圾尾巴直接一刀切归零。这筑起了一道物理硬防线；
中间卡片 3 是 Top-P（核采样 Nucleus Sampling）：它比 Top-K 更聪明。它将所有候选词按概率从大到小排序并累加，只要累积概率超过 $P$（比如 90%），后续所有词立刻截断。这意味着在确定性极高的语境下（例如“法国的首都是”），“巴黎”一个词的概率就达到了 98%，Top-P 会自动将候选集收缩为 1 个词；而在开放发散语境下，Top-P 会自动把候选池扩展到几十个词，实现了真正自适应的动态窗口！

在底部，我们给出了工程实战推荐：
如果你在做 SQL 生成、函数调用或 JSON 结构化提取，请将 Temperature 压到 0.0~0.2，Top-P 设为 0.8；如果是日常智能客服或知识库问答，保持在 0.5~0.7，Top-P 设为 0.9；而只有在营销文案撰写或剧本创作时，才建议放开到 0.8~1.0。

## Key Q&A / Clarifications
**Q：如果将 Temperature 设为 0，大模型的输出就绝对确定不变了吗？**
A：理论上是确定性的。但在工程物理机房中，多卡并行推理使用了混合精度（FP16/BF16）矩阵运算，GPU 浮点加法并不满足结合律（即 $(A+B)+C \neq A+(B+C)$），微小的浮点舍入差异在极高深度网络中可能发生微小震荡，导致偶发的 Token 漂移。如果业务要求绝对 100% 确定性，除 $T=0$ 外还需在推理引擎中锁定固定随机种子（Seed）并使用确定性 CUDA 内核。
