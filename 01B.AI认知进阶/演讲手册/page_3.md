## Slide Objective
剖析 2024–2026 年大模型底层扩展律（Scaling Laws）的重大演进：从传统的“预训练数据与参数扩展”迈向“预训练 + 推理时思考扩展（Test-Time Compute）”双引擎时代，深入解释 DeepSeek-R1 与 OpenAI o1 等前沿模型的底层算力机理。

## Suggested Presentation
各位技术同仁，当我们讨论大模型的性能跃升时，很多人脑海中还停留在 2020 年 OpenAI 提出的 Chinchilla Scaling Law——也就是“只要不断增加参数量、给更多的预训练语料和 GPU 集群，模型的 Loss 就会按幂律不断下降”。

但是在 2024 年底到 2025 年初，整个 AI 工业界遇到了一个公认的瓶颈：高质量文本数据墙（Data Wall）。互联网上现成的人类高质量文本、教科书和开源代码，几乎已经被千亿大模型扒光了；再单纯把模型参数从 100B 堆到 1T，带来的性能提升已经呈现明显的边际效益递减。

就在这个关键节点，以 OpenAI o1 和中国团队的 DeepSeek-R1 为代表，开辟了模型的“第二引擎”——Test-Time Compute Scaling（推理时思考扩展）。

大家请看右侧的卡片：第二引擎的核心秘密在于，它不再把所有算力都在预训练阶段“一次性固化在静态权重里”，而是把相当一部分计算开销转移到了“推理阶段”。
在过去，你问大模型一个高难度的算法题，它会立刻以快思考（System 1）的方式吐出第一个词，一旦第一个词方向走偏，整段代码就全面崩溃。
而在第二引擎中，模型在强化学习（RL）的引导下，学会了人类科学家的慢思考（System 2）：它在把答案展示给用户之前，会在后台的 `<think>` 标签内部生成数千甚至数万个内部 Token。在这些 Token 内部，模型会自主进行假设分析、试探执行、发现矛盾、自我否定、回溯重算，直到推导出可信结论后，才输出最终答复。

从架构师的视角来看，这带来了算力经济学的巨变：我们不再需要为了极其罕见的复杂任务去买单昂贵的万亿参数巨无霸模型，而是可以用中等尺寸的高效底座，按问题难度动态分配推理 Token 算力——简单任务 0.2 秒解决，极难任务允许它思考 3 分钟，消耗更多推理 FLOPs 来换取极高的确定性。

## Key Q&A / Clarifications
**Q：慢思考模型输出的那些 `<think>` Token 会被计费吗？对系统延迟有什么影响？**
A：是的。所有在内部生成的思考 Token 都会占用 GPU 显存与计算时间，云厂商同样会计入输入/输出 Token 成本。对于架构师而言，这意味着在接口设计时不能盲目对所有接口都开启慢思考，而必须设计前置的路由层：简单分类走低延迟快思考，复杂逻辑决策才路由至慢思考模型。
