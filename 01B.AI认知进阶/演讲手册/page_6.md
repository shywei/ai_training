## Slide Objective
深入剖析大语言模型的向量化表示机制：从高维连续空间流形直觉，到绝对位置编码（APE）的致命缺陷，再到现代主流大模型标配的 RoPE（旋转位置编码）复数几何原理及其支撑 128K~1M 超长上下文的外推（Extrapolation）工程机理。

## Suggested Presentation
上一页我们看到，分词器吐出的是离散的整数编号，比如 1520 代表“代码”，3051 代表“逻辑”。但离散数字是无法计算语义关联的，因此进入模型的第一步，就是通过 Embedding 矩阵，把每个整型 ID 映射到一个极高维度的连续几何空间流形（比如 4096 维或 8192 维）。

请看上方左侧：在高维空间中，语义相近的词汇会被拉近在一起，形成一个稠密的几何流形。例如“Java”和“Python”的向量余弦相似度可能高达 0.82，而“Java”和“香蕉”的相似度可能只有 0.12。模型后续所有的“理解”，本质上都是在对这个高维流形进行几何变换。

然而，单纯的词向量是不带顺序的。如果把“狗咬人”和“人咬狗”送进去，词向量完全相同。这就需要注入位置编码。
请看上方右侧，为什么绝对位置编码（APE）彻底退出了历史舞台？
早期模型（如 GPT-2）使用硬编码的第 1、第 2 个绝对坐标。这种方案有两个致命硬伤：
第一，模型学不到“相对距离”，它无法理解“前一个词和后一个词”与“第 100 个词和第 101 个词”具有相同的语法修饰关系；
第二，完全无法外推！如果预训练时只见过 4096 个位置，当线上请求输入 4097 个词时，位置编码根本没有对应的参数，系统直接崩溃。

这就引出了下方的现代 LLM 标配——RoPE（旋转位置编码，苏剑林 RoFormer 提出）。
RoPE 的数学设计极其天才：它将向量每两维看作复平面上的一个点，位置为 $m$ 的 Token，就将其向量逆时针旋转 $m\theta$ 角度。
最神奇的推导在于：当 Query 向量（位置 $m$）和 Key 向量（位置 $n$）进行点积时，通过三角函数积化和差公式，两个绝对位置直接抵消，点积结果只严格取决于相对位移 $(m - n)$！
这不仅天然保证了相对距离不变性，而且伴随着相对距离变大，点积注意力自然衰减。更进一步，结合 YaRN 或 NTK-aware 频率插值技术，工程师只需做极轻量微调，就能把原本 4K 训练的模型无损扩展到 128K 甚至 100 万超长上下文！

## Key Q&A / Clarifications
**Q：为什么我们在使用开源模型处理 32K 或 128K 超长 Prompt 时，有时候需要在配置文件里修改 `rope_scaling` 参数？**
A：`rope_scaling`（如 `type: "yarn"` 或 `factor: 8.0`）正是告诉推理引擎如何对 RoPE 的基频 $\theta$ 进行动态缩放插值。通过将位置索引的旋转步进频率按比例压缩，使得 32K 位置的向量旋转角度落在模型预训练时见过的 4K 角度范围内，从而避免高频震荡导致注意力崩塌。
