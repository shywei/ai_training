CHAPTER 05 · 裸模型缺陷与全课认知跃迁

裸模型的四大先天软肋与软件工程的长期价值

为什么企业绝对不能直接拿裸大模型（Raw LLM API）丢上生产环境？因为裸模型具备不可忽视的四大先天硬伤，必须由软件工程体系去武装。
1. 易幻觉（Hallucination）
概率采样机制决定了其无法做出 100% 事实保证，时常一本正经编造不存在的接口。
工程救赎：RAG 事实注入 + 静态类型检查 + 自动化测试断言
2. 无记忆（Stateless）
单次 HTTP 请求无状态。会话一旦刷新，模型对历史决策、用户画像与长周期演进一无所知。
工程救赎：会话上下文压缩 + 长期记忆持久化存储
3. 无手脚（Passive Text）
裸模型只会生成文本字符串。它无法直接查生产数据库、调支付接口、更不能自主跑 Shell。
工程救赎：Tool Calling（工具调用）+ API 规范连接器
4. 窗口受限（Finite Window）
单次上下文承载量存在物理上限与注意力稀释，无法一口气吞下百万行历史遗留工程全量代码。
工程救赎：工作流编排（Workflow）+ 分治任务拓扑拆解
经典汽车工程类比：裸大模型只是一台转速极高、马力狂暴的发动机（Engine）。一台只有发动机的机械根本无法上路；要造出一辆能安全载人飞驰的汽车，必须配上变速箱、方向盘、ABS 刹车系统、安全气囊与坚固底盘——而这些，正是软件工程不可替代的阵地！
工程学结论：软件工程不仅没有被大模型颠覆，反而迎来了有史以来最重要的黄金时期！大模型越强大，治理大模型、驯服大模型、为大模型构建确定性护栏与企业系统的软件工程能力就越发昂贵而稀缺！
