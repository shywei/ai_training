## Slide Objective
直面裸大模型（Raw LLM）不可逾越的四大先天软肋（易幻觉、无记忆、无手脚、窗口受限），阐明为什么任何企业都绝不可能直接把裸模型接口丢进生产系统。使用经典的“汽车与发动机”类比，向学员深刻揭示“软件工程不仅没有死，反而迎来了黄金期”的终极逻辑，彻底重燃程序员的工程自豪感。

## Suggested Presentation
我们正式进入全课的最后一章——第五章！
在前面的章节里，我们看到大模型写代码有多厉害，推理有多牛。很多非技术人员和所谓的行业自媒体就大肆鼓吹：“软件工程已经死了！以后不需要架构师了，人人对着大模型打几句自然语言，什么软件都能搞定！”

作为深谙生产系统残酷性的技术人，我们听到这种话，只能报以冷静的一笑。
为什么？
因为任何一个敢在生产环境直接裸接大模型 API 的企业，最多活不过三天！
大模型作为纯粹的算法产物，天生带着四大写在物理基因里的**先天硬伤**：
- **第一大硬伤：易幻觉（Hallucination）**。我们在第 16 页讲过了，概率采样决定了它永远不可能做出 100% 的事实承诺。在金融交易、医疗支付系统里，你能容忍万分之一的随机虚构吗？绝对不行！
- **第二大硬伤：无记忆（Stateless）**。单次 API 调用是完全无状态的 HTTP 请求。每次会话一关，大模型就把你忘得一干二净。它无法自主沉淀企业的长期演进历史和用户画像。
- **第三大硬伤：无手脚（Passive Text Only）**。裸模型只能在屏幕上给你打印字符。你让它给用户退款 50 块钱，它在回答里写“退款成功”，请问微信支付的账真的退了吗？没有！它没有手脚，它自己不会调用 RPC 接口，不会去修改数据库，更不会操作终端沙箱。
- **第四大硬伤：窗口受限（Finite Context Window）**。虽然现在模型支持长上下文，但单次推理的计算资源有限，注意力机制在超长文本中必然面临稀释，它不可能一口气把公司十几年来上千万行的祖传巨石系统全部装进脑子里。

大家看看，面对这四大致命缺陷，谁来救它？
**是软件工程！只有我们软件工程师才能救它！**
- 它容易幻觉，我们用 **RAG 知识检索 + 静态类型分析 + 单元测试 Harness** 建立严格的客观校验红线；
- 它没有记忆，我们用 **Memory 记忆系统架构** 做上下文提取与持久化数据库挂载；
- 它没有手脚，我们用 **Tool Calling（工具调用）** 帮它接上企业内部的 API 管道与执行终端；
- 它窗口受限，我们用 **Workflow 工作流编排** 把复杂的庞大业务拆解成一条条拓扑清晰、单步可控的子任务链！

请大家牢记这个生动的汽车工程类比：
**裸大模型，充其量只是一台马力狂暴、转速飙到上万转的发动机（Engine）；**
**但只有发动机能上高速公路吗？绝对不行！要造出一辆能安全载人飞驰的汽车，必须配上底盘、变速箱、方向盘、ABS 刹车系统与安全气囊——而这整套把发动机武装成一辆合格汽车的浩瀚系统，正是我们软件工程的领地！**

大模型越是狂飙突进，能够驯服它、驾驭它、把狂暴算力转化为企业高可用生产系统的软件工程师，就越是价值连城！

## Key Q&A / Clarifications
**Q：业界常说的“Agent 架构”与这里提到的四大工程救赎有什么关系？**
A：Agent（智能体）的本质，就是“以大模型为计算核心，用软件工程的四大护栏将其完整武装起来的自主系统”。模型负责中枢推理，而工程系统负责提供记忆（Memory）、手脚（Tools）、知识（RAG）与流程调度（Workflow）。离开软件工程体系，就根本不存在能落地的 Agent！
