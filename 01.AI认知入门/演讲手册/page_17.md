## Slide Objective
帮助学员建立对当前繁杂工具生态的全局视角，消除“工具焦虑”。引导学员将注意力从“掌握某个具体产品”转移到“理解 Agent 的底层工作方式”上，为后续讲解 Agent 架构（培训三）做铺垫。

## Suggested Presentation
大家看这张表，2026年市面上有非常多的 Coding Agent 产品。GitHub Copilot、Cursor、Claude Code，还有国内的通义灵码和 Trae 等等。如果把这些工具的说明书都看一遍，可能要花上几个月的时间，而且几个月后，它们可能又大换血了。

你们觉得我们需要把每个产品都精通吗？（停顿，环顾四周）

其实不需要。大家仔细观察就会发现，现在的产品边界正在变得模糊。Cursor 里内置了终端，Claude Code 也推出了 IDE 插件，大家的功能越来越像。这就好比以前我们要学怎么骑各种牌子的自行车，但现在，我们更应该去理解自行车的传动原理。

在这个时代，真正需要学的，不是某一个特定的产品怎么按快捷键，而是这些 Agent 究竟是怎样思考和工作的。掌握了底层原理，不管明天再出什么新工具，你都能在一小时内迅速上手并让它为你所用。

## Key Emphasis
重点强调“工具的底层逻辑是相通的”这一认知。千万不要逐一去念表格里各个工具的优缺点，不要纠结于价格或具体模型的差别。表格只是用来展示“生态繁荣”的背景板，核心是讲透“学工作方式”的理念。

## Optional Extension
如果有学员问到国内开发团队应该选什么，可以简单提一句：如果是预算有限或偏好中文环境，Trae 和通义灵码是极佳的起步选择；如果追求极致的工程体验，可以考虑 Cursor。但最终取决于团队的合规要求和实际业务场景，工具只是手段。

## Classroom Interaction
提问：“大家在平时开发中，用过表格里的哪款工具？如果明天让你换一个全新的工具，你觉得最大的挑战是什么？”
目的：引导学员思考，得出“其实只要掌握了正确的任务拆解和 Prompt 编写方式，换工具的迁移成本极低”这一结论。

## Take Away
真正需要学的不是某一个产品，而是 Agent 的工作方式。

## Why This Slide Matters
如果没有这一页，学员可能会陷入“比较各种工具优劣”的细节中，产生工具焦虑，无法站在更高的架构视角去看待 AI 产品，后续也难以平滑过渡到对“理解 Agent 架构”这一核心目标的学习上。

## Transition
