## Slide Objective
全景梳理现代 AI 辅助编程工具的三大梯队与演进主线：从第一梯队单行代码补全插件（Ghost Text），到第二梯队 AI 原生 IDE（Cursor/Windsurf），再到第三梯队具备完整环境工具调用能力的终端自主 Coding Agent（OpenCode/Claude Code）。帮助学员看清工具进化背后的“自主度提升”脉络。

## Suggested Presentation
上一页我们讲了 Software 3.0 的范式跃迁。现在，我们把目光落回每个工程师天天打开的开发电脑上。
市场上各种 AI 编程工具眼花缭乱，铺天盖地。很多同学分不清 Copilot、Cursor 和最近爆火的各种终端 Agent 到底有什么区别。
其实，只要从“**自主度（Autonomy）**”和“**执行环境接入深度**”来看，整个工业界目前清晰地分化为三大梯队：

- **第一梯队：IDE 补全插件时代（Ghost Text 灰字补全）**。
以早期的 GitHub Copilot 插件为代表。它寄生在 VS Code 或 IntelliJ IDEA 内部。
交互模式非常原始：你敲几行代码，光标停顿一下，它给你弹出一行淡淡的灰色建议。你觉得好，按一下 Tab 键采纳；觉得不好，继续敲。
它最大的痛点是**缺乏全局上下文视野**。它只看你当前打开的文件，完全不知道你另外一个包里的接口长什么样；而且它没有手脚，不能帮你执行 `mvn compile`，本质上就是一个“稍微聪明点的打字按键加速器”。
- **第二梯队：AI 原生 IDE 时代（In-Editor 深度副驾）**。
以 Cursor、Windsurf 为代表。他们不再满足于只当一个插件，而是直接基于 VS Code 深度魔改，重构了底层架构。
它做到了两件大事：第一，**全代码库向量索引（Codebase Indexing）**。当你在聊天框里问它问题时，它能通过 RAG 自动关联你工程里的十几处相关类库；第二，**多文件协同修改（Composer）**。它可以一次性帮你创建 Controller、实现 Service、修改 application.yml，并给你列出清晰的 Git Diff 红色绿色对比图，让你在编辑器内一键合并。
这一梯队，把人类与 AI 结对编程的摩擦力降到了极低。
- **第三梯队：终端自主 Coding Agent（Autonomous Terminal Agent）**。
以 OpenCode、Claude Code、Aider 为代表。这是 2025–2026 年最具颠覆性的前沿形态！
它直接跳出了 GUI 编辑器的局限，**以独立命令行（CLI）的方式直接运行在你的开发机终端里**！
它拥有真正的“手和脚”：
你给它下达一个需求：“帮我把系统里的老版 Redis 客户端迁移到 Redisson，并补齐重试单元测试”。
它不需要你在旁边干等着。它自己调用 `grep` 搜索全项目的所有 Redis 调用；它自己用工具修改代码；修改完，它自己启动 Maven 执行单测；测试报错了，它自己看堆栈、自己修改代码再次执行；直到所有测试全绿，自动提交一个带有规范语义的 Git Commit，然后通知你：“主人，代码写完测完了，请审查”！

大家看这条演进主线：
**从第一代“人敲代码，AI 偶尔递一把螺丝刀”；**
**到第二代“人做主驾，AI 坐在副驾实时帮你看地图”；**
**再到第三代“人定目标并验收，AI 作为独立工程师去车间里把活干完”！**

## Key Q&A / Clarifications
**Q：终端自主 Coding Agent 相比于 Cursor 这种 IDE，最大的优势到底是什么？**
A：最大的优势在于**完整的环境闭环能力与工具链执行权**。Cursor 依然强依赖人去点“Accept”、人去跑终端看报错；而终端自主 Agent 直接把编译命令、测试用例、Linter 校验和 Git 命令封装为自己的执行工具。它能够在一个完整的循环（Loop）里自主试错，真正实现了“任务级（Task-level）”的交付，而不仅仅是“代码级（Code-level）”的建议。
