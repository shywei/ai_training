## Slide Objective
梳理软件工程七十年来的三代范式跃迁：Software 1.0（手写代码时代）、Software 2.0（数据驱动的神经网络时代）到 Software 3.0（意图驱动与 Agent 时代）。向程序员揭示“代码从最终交付物退化为中间态产物”的历史必然性，引导学员建立全新的软件架构世界观。

## Suggested Presentation
我们正式迈入第四章——软件工程的范式革命与角色重塑！
特斯拉前 AI 总监安德烈·卡帕西（Andrej Karpathy）曾提出过一个著名的论断：软件正在经历 1.0、2.0 到 3.0 的范式剧变。
作为深耕在软件一线的工程师，我们必须清晰地看透这三代演进的本质逻辑：

- **第一代：Software 1.0（手写代码时代 · 1950s–2010s）**。
这是我们所有人最熟悉、浸润最深的时代。从 C、C++、Java 到 Python、Go，程序员是唯一的创造者。我们把业务需求在脑子里拆解成算法流程，用一行行确定性的语法敲出来。
在 1.0 时代，**代码是绝对的“第一公民”和最终交付产物**。
但是，正如我们在第一章讲的，面对图像识别、语音理解、复杂的非线性模糊业务，人类写不出那么多 if-else，1.0 遭遇了规则爆炸的严重瓶颈。
- **第二代：Software 2.0（数据驱动时代 · 2012–2022）**。
深度学习爆发后，程序员开始放弃手写具体逻辑。我们只定义网络架构（比如 ResNet 或 Transformer）和损失函数（Loss Function），然后把海量数据倒进 GPU 集群，由机器通过反向传播自动搜索出最优的浮点数权重矩阵 $W$。
在 2.0 时代，**参数权重成为了核心交付物**。
但它的局限在于：每个业务都要单独收集标注数据，训练一个专有的小模型，微服务烟囱依然林立。
- **第三代：Software 3.0（意图驱动与 Agent 时代 · 2023–2026+）**。
伴随通用大模型与 Coding Agent 的成熟，我们正式跨入了 3.0 时代！
在这一代，**人类不再负责写具体的语法实现，而是使用高精度的自然语言与技术契约（Spec）来描述最终目标与安全边界**；底层的 AI Agent 自主读取工程上下文、自主编写代码、自动在终端沙箱中运行编译与测试，直到把绿灯交付给你！

请大家仔细体会这一层惊天动地的蜕变：
**在 Software 1.0 里，代码是你的心血；而在 Software 3.0 里，代码正在变成一种“易耗品”和“中间计算态”！**
AI 可以为了完成一个需求，在 3 秒钟内生成 500 行代码；如果不符合预期，直接全量删掉重新生成 500 行。
人类工程师的关注点，从微观的“这行代码的语法对不对”，彻底升维到了宏观的“系统的业务契约是什么、模块边界清不清晰、验收护栏牢不牢固”！

## Key Q&A / Clarifications
**Q：如果代码变成了按需生成的中间态，那我们以后还需要看代码、审查代码（Code Review）吗？**
A：当然需要，甚至比以前更重要！但审查的重点彻底变了：以前 Code Review 看的是有没有空指针、有没有拼写错误、变量名起得规不规范；而现在的 Review 核心看的是：这段生成出来的代码有没有引入隐藏的死锁与竞态条件？有没有破坏系统的权限隔离？有没有违背当初定义的业务规格（Spec）？这是高阶架构师才能具备的核心能力。
