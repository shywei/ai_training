CHAPTER 03 · 程序员视角的四大灵魂解惑

机制解惑：为什么大模型会“一本正经胡说八道”？—— 幻觉根源与治理

传统程序员最痛恨的“Bug”：编造不存在的 API、虚构字段。幻觉绝不仅是概率采样，而是数据、上下文与生成机制共同作用的结果。
传统工程心智：确定性布尔逻辑（0 与 1）
纯函数契约
程序是确定性的状态机：相同的输入实参经过函数执行，必然产生恒等不变的预期输出。
assert function(x) == expected; // 确定性断言
// 任何模糊、偏差或不确定性在代码中均被定义为 Defect
大模型生成机制：高维连续条件概率采样
概率流形
大模型没有物理“真理”概念，输出的每个 Token 均为条件概率分布采样：P(wₜ | w_{<t})。
Token = Sample(Softmax(W · h / Temperature))
// 所谓“幻觉”，往往是模型平滑插值与泛化能力的孪生副作用
全面纠偏：大模型产生幻觉的五大根源剖析
① 概率采样漂移
自回归生成中，前序采样的微小偏差在后续步数中雪崩式放大。
② 训练数据盲区
知识截止、私有代码未覆盖或长尾知识样本极度稀疏导致臆测。
③ 长上下文位置偏差与截断
关键信息处在中间位置（Lost-in-the-Middle）或被挤出窗口，信息利用不足导致臆测。
④ 检索噪音干扰
RAG 召回了不相关或相互矛盾的过期文档，直接误导模型判断。
⑤ 多指令冲突
System Prompt 与用户需求逻辑自相矛盾，导致自洽崩溃。
工程解法：不在黑盒里求真理，在白盒外建护栏！ 接纳概率核心的不确定性，通过动态 RAG 知识锚定 + 强类型 Schema 校验 + 静态代码检查（Linter）与沙箱单测执行反馈，用确定性的软件工程体系为大模型托底，打造即便产生幻觉也能自动拦截自愈的高可用架构！
