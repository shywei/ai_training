# AgentScope 2.0 重构工程启动与联调指南 (v7.0-setup)

本指南针对 `enterprise-ai-agent-agentscope` 工程提供保姆级环境准备、启动说明与端到端接口验证测试用例。

---

## 1. 端口矩阵与基础设施复用

为了支持三套工程同屏对照，本工程设计为**完全复用** `enterprise-ai-agent`（手搓原版）现有的 Docker 基础容器与 MCP 服务：

| 服务名称 | 监听端口 | 作用与归属 | 说明 |
|:---|:---:|:---|:---|
| **手搓原版 Agent** | `8080` | `enterprise-ai-agent` (v5.0-workflow) | 教学对照基准线（手搓状态机原版，永久冻结） |
| **基础设施版 Agent** | `8083` | `enterprise-ai-agent-springai2` (v6.0-springai2) | 现代基础设施演进对照 |
| **框架重构版 Agent** | **`8084`** | **`enterprise-ai-agent-agentscope` (v7.0-agentscope)** | **本工程主服务端口** |
| **MCP Product Server** | `8081` | 外部企业商品与库存 ERP 服务 | 暴露 `query_product`, `check_inventory`, `create_order` |
| **MCP Knowledge Server**| `8082` | 外部企业知识与向量 RAG 检索服务 | 暴露 `search_knowledge`, `search_memory` |
| **Redis** | `6379` | 会话记忆与状态持久化 | 复用 Docker 容器中的 Redis 实例 |
| **MySQL** | `3306` | 用户画像与订单数据存储 | 库名: `agent_db` |
| **PostgreSQL (pgvector)**| `5432` | 向量知识库数据存储 | 库名: `agent_db` |

> **提示（零 Docker 优雅降级支持）**：  
> 本工程的 `McpEnterpriseToolAdapter` 内置了健壮的本地数据源回退机制（Mock Fallback）。  
> 如果在没有 Docker 或未启动 8081/8082 MCP Server 的纯离线环境下，应用仍能 100% 正常启动并通过所有业务流程测试！

## 2. 环境准备与环境变量配置

### 2.1 基础运行要求
- **操作系统**：Windows / macOS / Linux
- **JDK 基线**：JDK 17 LTS 或 JDK 21+（代码完全遵循 Java 17 语法）
- **构建工具**：Apache Maven 3.8.0+

### 2.2 环境变量配置
建议在终端或 IDE 运行配置中设置 SiliconFlow 兼容 API Key：

```bash
# Windows PowerShell
$env:SILICONFLOW_API_KEY="sk-your-siliconflow-api-key"
$env:LLM_BASE_URL="https://api.siliconflow.cn"
$env:LLM_MODEL_NAME="Qwen/Qwen2.5-7B-Instruct"

# Linux / macOS Bash
export SILICONFLOW_API_KEY="sk-your-siliconflow-api-key"
export LLM_BASE_URL="https://api.siliconflow.cn"
export LLM_MODEL_NAME="Qwen/Qwen2.5-7B-Instruct"
```

## 4. 核心接口联调验证（cURL 测试用例集）

### 4.1 场景一：多品对比与导购问答（同步任务）
```bash
curl -X POST "http://localhost:8084/api/v7/workflow/execute" \
  -d "message=我想买一台适合打游戏和视频剪辑的高性能电脑，拯救者和MacBookPro有什么区别？" \
  -d "sessionId=session-demo-01"
```
**响应特性**：
- 自动触发 ReActAgent 内部的 `query_product` 与 `search_knowledge` 工具；
- 返回格式包含 `executionId`, `checkpointId`, `status: "COMPLETED"`, 以及自动记录的执行耗时与迭代轮次。

---

### 4.2 场景二：28 类类型化 AgentEvent 多通道流式透传 (SSE)
```bash
curl -N -X GET "http://localhost:8084/api/v7/workflow/stream-events?message=帮我查一下拯救者Y9000P的库存和配置&sessionId=session-sse-01"
```
**SSE 流式输出样例（多通道解耦）**：
```json
data:{"channel":"control","type":"AGENT_START","rawType":"AGENT_START"}
data:{"channel":"thought","type":"THOUGHT_START","rawType":"THINKING_BLOCK_START"}
data:{"channel":"thought","type":"THOUGHT_DELTA","rawType":"THINKING_BLOCK_DELTA","delta":"用户想了解拯救者Y9000P的配置和库存，我需要调用商品查询工具..."}
data:{"channel":"thought","type":"THOUGHT_END","rawType":"THINKING_BLOCK_END"}
data:{"channel":"tool","type":"TOOL_CALL_START","rawType":"TOOL_CALL_START","toolName":"query_product","toolCallId":"call_101"}
data:{"channel":"tool","type":"TOOL_RESULT","rawType":"TOOL_RESULT_END"}
data:{"channel":"answer","type":"TEXT_DELTA","rawType":"TEXT_BLOCK_DELTA","delta":"拯救者Y9000P目前在售..."}
data:{"channel":"control","type":"AGENT_COMPLETED","rawType":"AGENT_END"}
```
*前端可按 `channel` 属性分别将思考流（thought）渲染在折叠面板，工具调用（tool）渲染在步骤卡片，最终回答（answer）平滑逐字打字机输出！*

---

### 4.4 场景四：人在回路 (HITL) 审批确认与下单恢复
```bash
curl -X POST "http://localhost:8084/api/v7/workflow/confirm" \
  -d "checkpointId=cp-hitl-749e7cf8-..." \
  -d "approved=true" \
  -d "reason=主管领导已确认预算，同意购买"
```
**响应特性**：
- 状态机解除挂起，恢复挂起的 `create_order` 工具调用；
- 生成正式订单并返回 `ORD-xxxx` 单号，保存终态快照。

---

### 4.5 场景五：从 Checkpoint 断点复水 (Rehydration)
```bash
curl -X POST "http://localhost:8084/api/v7/workflow/rehydrate" \
  -d "checkpointId=cp-hitl-749e7cf8-..."
```
**响应特性**：
- 无需从头重新开始推演，直接基于 Checkpoint 中的 `callStack` 与 `scratchpad` 恢复智能体运行时。

---

### 4.6 场景六：时光倒流分支演进 (Time-Travel Forking)
```bash
curl -X POST "http://localhost:8084/api/v7/workflow/fork" \
  -d "baseCheckpointId=cp-hitl-749e7cf8-..." \
  -d "note=用户改变主意，决定改买轻薄本MateBook"
```
**响应特性**：
- 不破坏原执行链条，以 `baseCheckpointId` 为父节点分叉出一个全新的 `newExecutionId`，支持多分支试探。

---

### 4.7 场景七：查询任务的 Checkpoint 版本血缘链条
```bash
curl -X GET "http://localhost:8084/api/v7/workflow/checkpoints?executionId=exec-order-001"
```
**响应特性**：返回该任务从规划、执行、挂起到完成的完整快照版本血缘列表。
